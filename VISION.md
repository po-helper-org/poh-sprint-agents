# poh-sprint-agents — Vision

> **Автономный скрам-мастер-агент.**
> Главная миссия — чистота и порядок в управлении спринтами.

**Функции [манифеста](https://github.com/po-helper-org/.github/blob/main/profile/README.md):**
3 — контракт с командой (система задаёт что и критерии приёмки, техлиды дают сроки) ·
4 — риски и раннее предупреждение (лид-тайм сигнала до эскалации).

## Миссия

Снять со скрам-мастера и PO рутину ведения спринта и сделать управление
спринтом **предсказуемо чистым**: точный план с персональной декомпозицией,
честный план/факт по дейликам, доказуемый факт спринта, привязка каждого
действия к квартальной цели — с надёжностью, за которую платят. Каждый рабочий
шаг фиксируется в презентации по шаблону, кратко и по сути, без AI-slop.

## Отличие от poh-helper

`poh-helper` — операционка **PO**: что хотим, OKR, БФТ, стратегия
(«образ результата»). `poh-sprint-agents` — автономный **скрам-мастер** поверх
этого: обеспечивает **исполнение** спринта — декомпозиция, ёмкость, консенсус
команды, каденс дейликов, факт, ретро. Не «что хотим», а «как команда чисто это
доведёт до результата».

Автономность: собственный установщик, собственный доменный профиль, собственные
навыки. Зрелые контуры `daily-review` / `sprint-fact` портируются как
standalone-копия (не runtime-зависимость), планирование переписывается под
скрам-мастер-модель.

## Функции (контур спринта)

| # | Функция | Ценность |
|---|---|---|
| 1 | **Планирование** | Точная декомпозиция сотруднику + привязка к квартальной цели |
| 2 | **Daily-каденс** | План/факт по дейликам; расхождения «PO ожидал ↔ сотрудник сделал» |
| 3 | **Спринт-ревью** | Сводный план/факт + операционная эффективность команды |
| 4 | **Корректировка квартала** | Движение спринт-к-спринту к целям квартала |
| 5 | **Презентация** | Каждый шаг — в Google Docs по шаблону, без AI-slop |

Демо-скрипт (13 шагов) — приёмочный сценарий: ПЛАН → DAILY → ФАКТ → РЕТРО,
каждая фаза замыкается подтверждением PO и переносом в презентацию.

## North Star

Живой автономный контур: **план → персональные ожидания → каденс → факт → ретро
→ персональная память**. Меряется движением к OKR и чистотой процесса, а не
активностью.

## Принципы

- **Каждый факт ← источник.** Нет источника → `[УТОЧНИТЬ у {кого}]`. Ноль
  невыясненных фактов в согласованном артефакте.
- **Консенсус до материализации.** Команда согласует декомпозицию, только потом
  запись в трекер / презентацию.
- **Обратимость первой.** Vault под git перед необратимым трекером.
- **Персона скрам-мастера** — facilitator и страж процесса, а не диктатор:
  диалог по одному вопросу за раз, видение формируется совместно.
- **Без AI-slop.** Деловая телеграфная проза, без стоп-слов и декоративных эмодзи.

## Дорожная карта срезов

1. **Slice 1 (текущий): навык планирования** — vault ПЛАН-артефакт +
   операционный контракт + гейт консенсуса. БФТ: `docs/bft-sprint-planner-slice1.md`.
2. Материализация в JIRA (BUILD-проход).
3. Презентационный движок (Google Docs) + план-слайд.
4. Daily-каденс (порт `daily-review`) + презентация.
5. Факт спринта (порт `sprint-fact`) + протокол закрытия.
6. Ретроспектива → персональная память.
