# poh-sprint-plugin — плагин для DeepSeek Harness

Контур скрам-мастера в чате харнесса: спланировать спринт и закрыть его
отчётной колодой для бизнеса.

## Как это работает

Плагин ставится в режиме **skill-root**: `.claude/skills` подключаются к
харнессу как нативный каталог навыков, и агент вызывает их прямо из чата.
Собирать нечего — ни npm-пакета, ни браузерного бандла. Установка сводится к
одному блоку в профиле харнесса.

Отдельного раздела в левом меню плагин **не поднимает**: артефакт отчёта —
самостоятельный HTML-файл, который открывают с диска, и UI-панель ему не нужна.
Если раздел понадобится, это другой режим — Cordis-плагин с `apply` и
React-бандлом; рабочий образец лежит в `po-helper-org/poh-bft-writer`,
инструкция — в его `docs/guides/dsh-plugin-setup.md`.

## Демо-сценарий

**1. «Установи плагин в мой dsh»**

Агенту достаточно этого файла: команды ниже он выполняет сам.

**2. Скачать репозиторий**

```sh
git clone https://github.com/po-helper-org/poh-sprint-agents.git
```

**3. Активировать плагин**

```sh
bash poh-sprint-agents/dsh/install.sh \
  --harness   /путь/к/harness \
  --workspace /путь/к/воркспейсу
```

Установщик пишет блок в `harness/.dsh-data/profiles/web/cordis.patch.yml`
(включает `skill-filesystem` и `tool-skill`, указывает `customSkillDirs` на
skill-root репозитория) и кладёт `domain-profile.md` в воркспейс, если его там
нет. Свои записи профиля он перезаписывает, чужие не трогает; повторный прогон
безопасен.

Проверить, что получилось: `--check`. Посмотреть, что будет сделано, ничего не
меняя: `--dry-run`.

**4. Открыть dsh в браузере**

```sh
cd /путь/к/harness
DSH_HOME="$PWD/.dsh-data" pnpm dsh web --no-open --port 3082
```

Харнесс печатает ссылку с токеном сам. Перезапуск обязателен: плагин на живую
он не подхватывает.

**5. В чате: «собери отчёт по спринту 2026Q3-S8»**

Агент поднимает `sprint-result` и ведёт ресинк факта по одному вопросу, затем
собирает `ФАКТ-{sprint}.md` и колоду. Фразы-триггеры перечислены в
`plugin.json` и проверяются контрактным тестом на совпадение с описаниями
навыков — без этого агент не поймёт, что запускать.

## Что ставится

| Навык | Команды | Что делает |
|---|---|---|
| `sprint-planner` | `/sm-sync` … `/sm-consensus` | спринт → ПЛАН + операционный контракт + гейт консенсуса |
| `sprint-result` | `/sprint-result`, `/sr-revise`, `/sr-final`, `/sr-html` | закрытие спринта → `ФАКТ-{sprint}.md` + HTML-колода |

Контур замкнут: незакрытые строки отчёта уходят кандидатами в carryover, и
`/sm-sync` следующего спринта читает их из того же файла.

## Настройка

Читается из `{workspace}/.claude/domain-profile.md`, не из профиля харнесса:

| Параметр | Зачем |
|---|---|
| `paths.*` | где лежат спринты, ПЛАН, ФАКТ, roadmap |
| `team.roster_source` | ростер исполнителей |
| `capacity.*` | velocity, focus factor, fallback |
| `publication.link_whitelist` | хосты, ссылки на которые допустимы в отчёте (гейт 5). Пусто — внешний адрес остаётся текстом |

## Проверка

```sh
bash dsh/test-contract.sh
```

24 проверки: манифест, наличие и описания навыков и команд, совпадение
триггеров с описаниями, компиляция скриптов, установка в чистый харнесс,
идемпотентность, сохранность чужих записей профиля, валидность YAML после
правки и **сквозной прогон** — оба валидатора и сборка колоды в установленном
воркспейсе.

## Если не поднялось

**В чате нет инструмента `skill`** — в профиле `web` и `skill-filesystem`, и
`tool-skill` выключены по умолчанию. Установщик ставит обоим `disabled: false`;
если правили профиль руками, проверьте оба.

**Навыки не находятся** — `customSkillDirs` указывает не туда. Сверьтесь:
`cd harness && pnpm dsh --profile web --dump-config`.

**Агент не понял фразу** — триггер не совпал с описанием навыка. Список
рабочих фраз в `plugin.json`, проверка — в контрактном тесте.

**Отчёт собрался, но пустой** — `paths.*` в домен-профиле указывают не на тот
воркспейс. Домен-профиль лежит в воркспейсе, а не в каталоге харнесса.
