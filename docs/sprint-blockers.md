# Блокеры команды — как устроено и почему

Навык `/sprint-blockers` отвечает PO на три вопроса за квартал: **кого команда ждала**, **где в процессе стояли задачи**, **какие случаи были самыми долгими и что ещё открыто**. Образец формы — отчёт разработчика «Простои из-за внешних зависимостей» (таблицы «Кого ждали», «Главные случаи», «Источники и ограничения»); навык делает то же для команды целиком и только по JIRA.

## Конвейер

| Шаг | Кто | Что |
|---|---|---|
| `fetch` | скрипт | задачи команды за период: история статусов, комментарии, связи → снимок |
| `facts` | скрипт | ожидания по рабочим дням, стадии процесса, доказательства рядом с каждым ожиданием, слабые сигналы |
| разбор | агент | каждое ожидание → случай (сторона, чего ждали, основание) или «не блокер» с причиной; вывод |
| `apply` | скрипт | проверка разбора против фактов, все числа пересчитаны по датам → страница |

Границу держит проверка, а не доверие: неразобранное ожидание, ожидание в двух случаях, ключ задачи не из фактов, устаревший `factsHash` — ошибка; число в выводе, которого нет ни в фактах, ни в таблицах, — предупреждение.

## Правила счёта

- **Ожидание** — интервал в статусе стадии: приостановка (`On Hold` / «В ожидании» / Blocked) любой длины или очередь (ревью, тест, установка) не короче `queue_min_days` (5) рабочих дней. Короче — обычный ход процесса: он виден в таблице стадий, но случаем не становится.
- **День ожидания** — рабочий день D, для которого начало ≤ D < конец; открытое ожидание идёт по дату отчёта включительно. Так совпадает с эталоном: 17.08–17.09 — 23 дня, «с 23.09» на 14.10 — 16.
- **Задаче-день** — день, который одна задача простояла; основная мера потерь команды. «Дней из N» (хотя бы одна задача ждала сторону) на уровне команды быстро насыщается — на живых данных приостановка была в 66 из 66 дней квартала, — поэтому идёт второй цифрой.
- Дни считаются только внутри периода отчёта; даты интервала на странице — как в JIRA.
- **Часы не считаются**: учёта времени в JIRA нет. Пока задача стоит, команда делает другую работу — дни означают задержку сроков, а не простой людей. Это написано на странице в ограничениях.
- В истории JIRA статус бывает записан по-английски (`On Hold`, `Ready to Check`), а в карточке — по-русски: списки статусов стадий содержат оба имени.

## Транспорт: скрипт — MCP-клиент

В окружениях, где JIRA разрешена только через официальный MCP-сервер, раньше данные в отчёт возил агент (replay-фикстуры из ответов MCP). Здесь скрипт сам запускает MCP-сервер Atlassian (`mcp-atlassian`) по stdio и зовёт `jira_search` постранично — правило «только MCP» соблюдено, а модель в доставке данных не участвует. Без MCP — REST с токеном, TLS всегда включён (как у базового сборщика). Проверено на живой команде: 1423 задачи за квартал — 2 минуты, 134 ожидания.

## Выбор основы (OpenSource)

| Кандидат | Покрытие («где ждали» / «кого ждали» / квартал+месяц) | Лицензия | Живость | Стек | Развёртывание и доработка |
|---|---|---|---|---|---|
| [jira-agile-metrics](https://github.com/DeloitteDigitalUK/jira-agile-metrics), калькулятор `impediments` | где — да (флаг/статус, по месяцам, задачи и дни); кого — нет | MIT | коммиты 2025 | Python + pandas + matplotlib | pip-зависимости, графики PNG, флаг JIRA (в наших командах не используется) |
| [Apache DevLake](https://github.com/apache/devlake) | время в статусах, DORA; кого — нет | Apache-2.0 | активен | Go + MySQL + Grafana | отдельный сервис с БД — тяжело для навыка, ставящегося копированием |
| [jira-metrics-extract](https://github.com/rnwolf/jira-metrics-extract) | даты входа в стадии (CSV); кого — нет | MIT | заброшен с 2019 | Python | устарел |
| Коммерческие (Issue Delivery Report, Timepiece) | время в статусах, блокировки | — | — | Jira-приложения | не open source |

**Выбор:** модель случая взята у `impediments` из jira-agile-metrics — ожидание как интервал в стадии, бэклог и «Готово» не считаются, итог по периодам в задачах и днях. Код не подключён: плагин без зависимостей (Python 3.9+, ставится копированием), а pandas ради интервалов не нужен. Отличия: несколько стадий, рабочие дни, статусы вместо флага. Ответ на вопрос «кого ждали» не даёт ни один кандидат — это классификация по комментариям и связям, её делает агент под проверкой скрипта.
