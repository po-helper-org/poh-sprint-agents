# Бизнес-колода: строка = эпик, блокеры отдельно от недобора

## Ситуация

Владелец посмотрел бизнес-колоду на реальном спринте: слишком подробная — строка на каждую историю, 26 слайдов на две команды; блокеры не отличить от недобора по объёму; слайды не помещаются; сгорание кривое; у команды без подзадач график ломается; «Планы» перегружены ключами.

## Причина

Колода проектировалась на демо-данных: истории равномерно распределены по эпикам, подзадачи есть у всех, слайды одинаковой высоты. Реальные спринты несимметричны: один эпик с 30 историями, у другой команды подзадач нет, ключи задач длинные.

## Причина (вторая, найденная в итерации 2)

Комментарии исчезали после перезагрузки: корзина и счётчик не перерисовывались («Комментарии (0)»), корзина показывала одну команду, ключ зависел от спринта, битая запись затирала остальные.

## Решение

**Итерация 1:**
- **Строка = эпик (KR)** со сводкой историй: метки «заблокировано N» / «не закрыто N», блокер, следующий шаг; результат — среднее по историям с полосой статусов. Истории без эпика — строка «Вне эпиков». На реальном снимке 26 слайдов → 14.
- **Слайд команды**: «Заблокированы» (ждём других) отдельно от «Не успели по объёму» (не закрыли сами).
- **Прокрутка**: слайд выше 720px прокручивается внутри; ↓/пробел сначала докручивают, потом листают.
- **Сгорание в двух вариантах** (с подзадачами и без): идеальная линия только по рабочим дням; сборщик 1.10.0 отдаёт `burndown.days[].storyScope/storyClosed`.
- **Планы в четыре колонки** (взять / доделать / возможно войдёт / эскалировать), автосписок «Взять» — до трёх следующих задач эпика, а не весь открытый объём.

**Итерация 2 (заметки владельца):**
- **Комментарии не пропадают**: все команды в корзине, ключ без спринта (старые корзины вливаются), битая запись откладывается, копия в IndexedDB, `navigator.storage.persist()`; новый e2e `comments_persist.mjs`.
- Сборщик 1.10.0: `report_types` (раньше 32 из 54 задач одной команды не попадали в отчёт — не тот тип), lead/type задач, подзадачи участника, `output.offboard`.
- Ключи: меню «в браузере» / «в виджет»; сайдбар эпика с фильтром по статусам; операционный без сортировок и «Застряли»; SP план/факт.

## Как проверить

- Python 263 теста; e2e `business_deck`, `comments_persist`, `report_mobile` — все проверки прошли.
- Реальный снимок: 26 слайдов → 14, блокеры видны отдельной панелью.

## Уроки

- Демо-данные скрывают асимметрию реальных спринтов; первую проверку макету отчёта надо делать на живом снимке.
- «Заблокированы» и «не успели» — разные проблемы руководителю; смешивать их в одной цифре нельзя.
- Локальное хранилище заметок нуждается в собственном e2e на перезагрузку и битые записи — именно там нашлись потери.
