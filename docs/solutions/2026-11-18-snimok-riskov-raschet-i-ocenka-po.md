# Недельный снимок рисков хранит расчёт рядом с оценкой PO

## Ситуация

`quarter.py render` каждую неделю пишет снимок `quarter-risks.history/<понедельник>.json` — по нему считается
смещение к прошлой неделе. В строке снимка был только итоговый `status`, в который уже подставлена оценка PO
(`override` из блока агента). Расчётный статус модели и сама оценка PO терялись: по истории нельзя было
ни проверить точность расчёта рисков (модель против того, чем инициатива кончилась), ни посчитать, сколько раз
и в какую сторону PO поправил расчёт. Текущий `quarter-risks.json` историю не хранит — он перезаписывается.

## Решение

- `quarter_model.snapshot_row`: в строку снимка рядом со `status` добавлены `computedStatus` (расчёт до оценки PO,
  берётся строго из строки модели, без подстановки `status`) и `override: {status}` — только у инициатив, где оценка
  есть. Остальные поля прежние.
- Причину оценки (`reason`) в снимок не пишем: метрикам Q-4 и Q-5 нужны только факт оценки и её сторона, а свободный
  текст PO (имена, подробности о смежниках) копился бы в истории без срока. Причина остаётся в перезаписываемом
  `quarter-risks.json`.
- Контракт для читателя истории (метрики в poh-widget-okr) — в `docs/quarter-risks.md`, раздел «Смещение»: старый снимок
  отличают по отсутствию `computedStatus`, а не по дате или имени файла (снимок текущей недели перезаписывается каждой
  сборкой, граница версий — момент выкладки); у старого снимка расчёт и оценка неизвестны, `status` вместо них не
  подставлять. `override.status == computedStatus` — оценка без сдвига. Отдельной функции чтения в этом репо нет:
  poh-widget-okr модули отсюда не импортирует.
- Смещение (`delta`) читает только `status`, `p85`, `blockers` — старые снимки работают как прежде.

## Проверка

`tests/test_quarter_risks.py`: снимок с оценкой PO (итог `yellow`, расчёт `green`, `override: {status}` без текста
причины; у строки без оценки поля `override` нет; строка переживает JSON); `computedStatus` есть у строк всех трёх веток
расчёта (`green`, `done`, `none`); оценка PO без причины, совпавшая с расчётом; старый снимок без новых полей даёт
смещение. Весь прогон: `python3 -m unittest discover -s tests`.

## Уроки

- Если поле итога складывается из расчёта и ручной поправки, в историю пишутся обе части: итог без них
  не разбирается обратно, а метрики по истории появляются позже, чем история.
