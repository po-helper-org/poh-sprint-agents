# Текст из трекера закрывал script-блок страницы отчёта

## Ситуация

Название эпика вроде `</script><script>alert(1)</script>` выполняло произвольный код на странице отчёта. `build.render` вставлял JSON данных команд в `<script>` как есть, а тексты — названия эпиков и историй, заметки, имена — приходят из трекера, где их пишет кто угодно.

## Причина

JSON сериализовался без учёта контекста: внутри `<script>` последовательность `</script>` закрывает блок раньше конца строки, и остаток строки становится разметкой/кодом. Обычное HTML-экранирование тут не помогает — блок не HTML, а JS-литерал.

## Решение

В `runner/build.py` добавлен `script_json()`: `<`, `>`, `&`, U+2028, U+2029 внутри строк JSON заменяются на `\uXXXX`-последовательности. Вне строк в JSON этих символов нет, синтаксис не страдает; для `JSON.parse` и JS-литерала результат — те же строки, данные на странице не меняются.

## Как проверить

- `tests/test_build_escape.py`: до исправления тест красный (`</script>` попадал в блок как есть), после — в блоке нет ни `</script`, ни `<!--`, разделителей строк нет, `json.loads` возвращает исходные данные.
- Весь набор на момент PR — 99 тестов зелёные на Python 3.12.

## Уроки

- Данные трекера — ввод пользователя: любой текст, попавший на страницу, надо экранировать под контекст (script-блок — свой набор символов, не HTML).
- Дешёвая проверка на будущее: в тесте на escape искать не только `</script`, но и `<!--` и разделители строк U+2028/U+2029.
