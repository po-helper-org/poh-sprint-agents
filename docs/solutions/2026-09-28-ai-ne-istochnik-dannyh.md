# ИИ не источник данных отчёта — контракт, runner и проверяемые сборщики

## Ситуация

Отчёт «ФАКТ по спринту» собирал скрипт `scripts/collect.py`: правила статусов захардкожены, SSL-проверка отключена (`CERT_NONE`), любой новый статус или поле — правка кода. ИИ-агент мог свободно править данные на пути из трекера в отчёт: числа на странице нечем было проверить. Параметры команды (типы историй, бакеты статусов, поле эпика) приходилось менять форком скрипта.

## Причина

Скрипт писался под одну доску и один набор процессов. Правила команд, устройство инстанса трекера и сам сбор не были разделены: всё в одном файле, изменения которого никто не проверял.

## Решение

Границу «ИИ пишет код, но не данные» сделали явной:

- `contract/` — источник истины о форме данных: `team.schema.json`, `PROTOCOL.md` (stdin/stdout/stderr, коды выхода 0/1/2/3, время только из now), `status_rules.json` (правила бакетов данными) и их единственная реализация `buckets.py`.
- `runner/` — единственный способ собрать отчёт: `run.py` (run | validate | lock | new), `validate.py` (схема + 12 инвариантов), `schema.py` (минимальный валидатор JSON Schema на stdlib), `build.py` (атомарная запись HTML).
- Сборщик — отдельный процесс по протоколу: получает stdin-запрос, отвечает stdout-JSON, логи в stderr. Хеш сборщика фиксируется в `sprint-report.lock.json`; байт изменился после проверки — отказ до запуска. Упала хоть одна команда — HTML не пишется, прошлый файл цел.
- Правила команды — настройки в `sprint-report.config.toml` (`story_types`, `status_buckets`, `epic_link_field`, …), свой сборщик нужен только когда меняется алгоритм.

Эталон вывода снят со старого `collect.py` до удаления (`tests/fixtures/legacy_collect_team.json`); паритет держится тестом `LegacyParityTest`.

## Как проверить

- `python3 -m unittest discover tests` — 81 тест без сети, на синтетическом трекере.
- Изменить байт сборщика → exit 2, «сборщик изменён после проверки», HTML не сгенерирован.
- Убрать обязательное поле из ответа → exit 1, прошлое имя поля в сообщении, прошлый HTML побайтово цел.

## Уроки

- Модель, свободно правящая данные «по дороге», — скрытый источник ошибок отчёта; контракт (схема + протокол + инварианты) делает проверяемым и код, и данные.
- Паритетный эталон старого вывода, снятый до удаления старого пути, стоит дёшево и окупается при каждом рефакторинге.
- Трекер недоступен (код 3) — отдельный код выхода и текст «проверьте VPN и токен», а не общий отказ.
