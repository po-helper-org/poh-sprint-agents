# «Прогресс инициативы» — весь эпик в строке и дата из Target end

## Ситуация

В бизнес-колоде у каждого направления был только результат спринта. Владельцу нужно второе: дойдёт ли инициатива целиком — полоса статусов всего эпика, целевая дата и прогноз. Заодно при слиянии #18 вошёл редизайн сайдбара задачи (#20): капс и рамки ушли, лента — строка на событие.

## Причина

Снимок содержит весь эпик (`epic.scope`), но таблица строки показывала только задачи спринта. Целевая дата не показывалась вовсе: сборщик брал `duedate`, а у эпиков трёх команд оно пустое — дату ведут в поле Target end (Advanced Roadmaps).

## Решение

- Новая колонка «Прогресс инициативы»: `61% (+5%)` и полоса статусов всего эпика (не начато → в работе → блок → QA → готово); подсказка: сделано 34 из 56 · срок · прогноз. Опоздание/просрочка — красный процент. Клик открывает сайдбар сразу на вкладке «Весь эпик».
- **Сборщик 1.11.0**: `epicDue` берётся из Target end (поле ищется по имени), если его нет — из `duedate`; параметры `params.epic_due_field` / `epic_due_names` по образцу `sp_field`.
- Прогноз — та же «Расчётная дата», что в сайдбаре (`epicBurn.forecast`); «(+n%)» — закрытое с начала спринта к объёму эпика.
- Вид строки как в отчётной колоде: Arial 14px, «Дальше:»/«Блокер:» обычным текстом.
- #20 (редизайн сайдбара) слит в составе: шапка без капса, задачи строками без рамок, событие подзадачи одной строкой, легенда графика ушла в подсказки.

## Как проверить

- `test_epic_due_from_target_end`: без правки сборщика падает (`'2026-11-20' != None`), с ней проходит.
- `unittest discover` — 266/266 OK на Python 3.10 и 3.12; заодно исправлены две давние ошибки `LegacyParityTest` (фейк трекера разбирал `.000+0300` через `fromisoformat` — работает только с 3.11; добавлен хелпер `jira_dt`).
- Живые данные: было 0 из 8 эпиков с датой, стало 7 из 8; в колоде срок/прогноз совпадают с сайдбаром.

## Уроки

- Поле, которое «все ведут», может быть не тем, которое читает API: перед построением метрики проверь, где реально лежат данные (здесь — Target end вместо duedate, 0/8 заполнено).
- Формальная дата в трекере пустая → ищи соседнее поле по имени, параметризуй имя поля, а не хардкодь.
- Фикстуры старого паритета нашли ошибку совместимости версий Python — держите их зелёными на обеих версиях.
