# Агенты команд пишут тексты рисков квартала сами — `put` под замком

## Ситуация

По понедельникам до синка с руководством тексты страницы «Риски квартала» должны быть готовы без ручного «Промта агенту»: агенты команд сверяют кандидатов в эскалацию с трекером и пишут эскалации и риски ROAM своей команды. До этого тексты были шаблонными из данных («уточнить, кого ждём»).

## Причина

Прямая запись каждого агента в общий файл `quarter-risks.json` затёрла бы чужие команды; оценки PO и тексты агентов смешивались без различия источника.

## Решение

- **`quarter.py put --team slug --file черновик --author профиль`** — агент пишет только свою команду: под замком (`quarter-risks.json.lock`), с проверкой до записи (схема, эпики команды, длины); черновик не принят — файл не меняется, чужие команды остаются.
- **Оценку PO (`override`) агент не ставит и не снимает**: `put` переносит прежнюю, новую принимает только с `--with-override` (PO сказал сам, в чате).
- `quarter.py facts --team` — факты одной команды, короче контекст агенту.
- У команды в блоке `author` и `updatedAt`; на странице — «текст агента …, 19.10» вместо пустого места.
- Навык-обёртка для профилей: facts → сверка с трекером только чтением → черновик → `put` → сборка страницы без fetch → 2–4 строки в чат. Одобренную PO эскалацию при неизменных фактах переносит слово в слово (иначе слетит ✅).
- Установщик: копия навыка в профили и cron по понедельникам 09:00/09:15/09:30 (после сбора 08:45, по очереди), доставка локальная — результат на странице, сообщений в чаты нет.

## Как проверить

- `AgentPutTest`: слияние команд, оценка PO переносится, отказ без записи, facts по команде, пометка на странице; всего 384+ зелёных.
- Установщик прогнан на поддельном окружении: install / повтор / --check / --replace / --remove.

## Уроки

- Несколько писателей в один файл — писать по разделу под замком, проверять до записи, весь файл не переписывать.
- Оценка человека и текст агента — разные источники: агент переносит чужую оценку, но не создаёт; новая — только с явного подтверждения.
- Cron-результат, который живёт на странице, не должен дублироваться сообщениями в чаты.
