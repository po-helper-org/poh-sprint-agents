# Порог входа агента: сухой прогон и атомарная сборка страницы

## Ситуация

Кодовая база навыков доросла до объёма, когда ИИ-агент, которому поручают доработку, не может безопасно пройти полный цикл «понять → изменить → проверить»: тестов на новую функциональность ещё нет, а список задач уже есть.

## Причина

(Раздел восстановлен по структуре PR; отдельная предыстория в описании PR не сформулирована — сама доработка и есть ответ на порог входа.)

## Решение

Части PR #12, которые снижают порог входа агента:

- **Сухой прогон на полном образце**: `examples/example_team_full.json` (1978 строк) — каждый экран можно проверить против полного снимка без живого трекера; `run.py check` гоняет по нему схему, 14 инвариантов и покрытие 27 экранов.
- **Атомарная сборка страницы**: шаблон собирается из `resources/shared/` (head, core.css, core.js, notes, panels) — общий движок для отчёта PO и колоды; правка одного экрана не требует понимать весь файл.
- **Тесты-сверки**: схема ↔ справочник полей ↔ образец ↔ демо-данные ↔ сборщик проверяются друг против друга тестами — агент, меняющий одно, сразу видит, что отстало.
- **Проверка в браузере без агента**: e2e-скрипты (`business_deck`, `report_comments`, `report_mobile`) дают готовый чек-лист проверок после правок.

## Как проверить

- `python3 -m unittest discover tests` — 255 тестов; e2e-скрипты из `tests/e2e/`.
- Изменить поле в схеме без правки `fields.md` → тест сверки красный.

## Уроки

- Полный образец данных + инварианты + e2e — это «площадка» для агента: доработка проверяема до появления ручного ревью.
- Общие ресурсы страницы (`shared/`) с переопределением на уровне шаблона убирают дублирование между отчётом и колодой.
