# «Риски и проблемы» в три столбца: строки из данных, комментарий — агента

## Ситуация

Слайд «Риски и проблемы» колоды спринта был неинформативен: метка («Внешнее», «Срок»), склеенный заголовок «инициатива: история» и шаблонный текст «Стоят 2 задачи… Нужна помощь — эскалирует PO». Из заблокированных историй инициативы показывалась только первая; почему стоим и что делать — не видно.

## Причина

Тексты агента (`risks` бизнес-блока) привязаны к снимку (`dataHash`): после утреннего сбора колода собирается на свежих данных и текст агента отбрасывается — на проде почти всегда был шаблон из данных.

## Решение

- **Три столбца: Инициатива · История · Комментарий.** Первые два — детерминированно из снимка: каждая заблокированная история — строка («В ожидании» с даты · дней), эпик с прошедшим сроком или прогнозом позже срока — строка «Инициатива целиком». Группы по инициативам, дольше стоящие — выше; до 10 строк, остальное — «ещё N».
- **Комментарий — отдельный файл `sprint-risk-notes.json`** рядом с блоком: `business.py risk-todo` (строки без свежего комментария) → `risk-put --team --author --file` (до 3 предложений, до 240 знаков, только ключи строк команды, под замком). Комментарий привязан к задаче и её состоянию (`sig`: статус@дата смены, срок эпика), а не к снимку — переживает пересборку и гаснет, когда задача сменила статус.
- Нет комментария — короткий текст из данных серым («Стоит без движения 8 дн., кого ждём — не записано. Нужно снять блокер — эскалирует …»).
- Пишут Hermes-агенты команд по будням (`hermes/install-sprint-risk-notes.sh`, навык `sprint-risk-notes`), Jira — только чтение.
