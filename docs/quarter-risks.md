# Риски квартала для CPO — `/business/risks`

Подотчёт к колоде «ФАКТ | спринт» для еженедельного синка с CPO (понедельник). Колода рассказывает, что команда сделала; эта страница — что может не дойти к концу квартала и где нужно решение руководителя. Термины — [GLOSSARY.md](../GLOSSARY.md), решения — ADR [0001](adr/0001-shans-k-koncu-kvartala-monte-carlo.md), [0002](adr/0002-epiki-kvartala-otdelnym-sborom.md), [0003](adr/0003-stranica-riskov-bez-vstroennogo-js.md), исследование форматов — [research/cpo-risk-report-formats.md](research/cpo-risk-report-formats.md).

## HowToDemo

1. Понедельник, перед синком: PO открывает `/business/risks` (кнопка «⚠ Риски квартала» в виджете колоды).
2. Наверху — строка квартала (сколько инициатив в каждом статусе, сколько прогнозов сдвинулось за неделю) и блок «Нужно решение»: до 3 эскалаций — что прошу · у кого · до какой даты · что будет, если нет.
3. Ниже — все инициативы квартала трёх команд, по строке: статус, KR, Target end → прогноз 85%, шанс к концу квартала, прогресс, блокатор или риск, путь в зелёный, смещение к прошлому понедельнику.
4. Нажатие на строку — подробности: открытые задачи и блокаторы со ссылками в Jira, риски с метками ROAM, как посчитан шанс.
5. «Кандидаты в эскалацию» — свёрнутый блок; ✅ переносит кандидата в «Нужно решение».
6. «Скопировать для CPO» — текст эскалаций и строки квартала для чата или письма.

## Решения (пул вопросов 2026-10-19)

Владелец не ответил на пул — взяты рекомендуемые варианты (правило «брать рекомендуемый вариант, решение с причиной — в отчёт»):

| Вопрос | Решение | Почему |
|---|---|---|
| Кто решает «нужна эскалация» | данные находят кандидата, текст — агент PO-команды или из данных, на верх — только после ✅ PO | данные не знают, кого ждём и что просить; без ✅ на экран CPO попадёт шум |
| Как CPO получает отчёт | PO показывает с экрана + «Скопировать для CPO» | новых доступов не нужно; страница за входом владельца |
| Форма | до 3 решений сверху + таблица всех инициатив | эскалации видно за 10 секунд, квартал целиком — за 2 минуты |
| К какой дате шанс | конец квартала, Target end — веха | ADR 0001 |
| Прогноз | Monte Carlo по недельному темпу | ADR 0001 |
| Цвет | считается, PO может поставить свою оценку с причиной | как самооценка против независимой у NISTA |

## Правила

**Инициативы** — эпики из `sprint-goals.json → teams.<slug>.epics` (цель — значение, KR — `kr`). Необязательные списки там же: `unconfirmed` (вхождение в квартал не решено) и `dropped` (снята) — отдельными блоками внизу.

**Темп** — задачи эпика (без подзадач), закрытые за каждую из последних 12 полных недель (пн–вс), нулевые недели считаются. Меньше 7 недель с начала работы по эпику — доля темпа команды (закрытия по всем её инициативам квартала ÷ число открытых инициатив) с пометкой «по темпу команды». Остаток — незакрытые задачи эпика. Рост объёма — каждый прогон умножает остаток на случайное число из [1, 1 + рост], рост = задачи, заведённые с начала квартала ÷ задачи на начало квартала (не больше 1).

**Шанс** — доля из 10 000 прогонов, в которых остаток закрыт до конца квартала. **Прогноз 85%** — воскресенье недели, к которой закрыто в 85% прогонов. **Сколько успеем** — число задач, закрытых к концу квартала в 85% прогонов.

**Блокатор** — задача эпика в бакете `blocked` (On Hold, «В ожидании»), с последней смены статуса прошло ≥ 3 рабочих дня (как «✋ Блокаторы» в `/sprints`).

**Статус** (первое совпавшее; P — шанс, B — возраст самого старого блокатора в рабочих днях):

| Статус | Условие |
|---|---|
| ✅ Готово | все задачи эпика закрыты (или эпик закрыт) |
| 🔴 Не успевает | P < 50% или B ≥ 10 |
| 🟡 Под риском | P < 85% или B ≥ 3 |
| ⚪ Нет прогноза | нет задач в эпике или нет темпа (ни своего, ни команды) |
| 🟢 В срок | P ≥ 85% и B < 3 |

Оценка PO из блока агента (`override: {status, reason}`) заменяет расчётный статус; расчёт — в подсказке.

**Кандидат в эскалацию** — 🔴 или 🟡, и (есть блокатор, или P < 50%), или агент написал для инициативы эскалацию. Текст — из блока агента; нет — из данных:
- блокатор: «снять блокатор KEY: стоит в «статус» N раб. дн.», до — последний понедельник, при котором после снятия шанс ещё ≥ 50% (нет такого — ближайший понедельник), если нет — прогноз 85%;
- P < 50%: «решение по объёму или сроку: к концу квартала с 85% успеем N из M задач», до — ближайший понедельник.

✅ PO хранится с хешем текста: агент переписал текст — нужен новый ✅. Наверху — не больше 3, по дате «до».

**Путь в зелёный** — блокатор: «снять блокатор до <даты>»; P < 85%: «снять M−N из M задач или сдвинуть на <прогноз 85%>».

**Смещение** — сравнение с недельным снимком предыдущей недели (`quarter-risks.history/<понедельник>.json`, текущая неделя перезаписывается при каждой сборке): сдвиг прогноза 85% в днях, смена статуса, новые и снятые блокаторы.

| `quarter-risks.history/` | `quarter.py render` | недельные снимки для смещения |

## Задачи

1. **Прогноз** (`sprint-business/forecast.py`): недельный темп, Monte Carlo, шанс к дате, прогноз 85%, «сколько успеем», окно задержки. Тесты на детерминированных выборках.
2. **Модель** (`sprint-business/quarter_model.py`): инициативы из целей и данных, блокаторы, статус, кандидаты и тексты эскалаций, путь в зелёный, смещение. Блокирован 1.
3. **Сбор** (`quarter.py fetch`): REST Jira только на чтение, replay в тестах. Независим.
4. **Страница и текст** (`quarter.py render`, `check` блока агента): HTML без встроенного JS, `.txt`, история. Блокирован 2.
5. **Виджет** (poh-widget-sprint-business): `/business/risks`, API `risks`, `risks.txt`, `risks/refresh`, `risks/approve`, кнопка в колоде, таймер сборки. Блокирован 3, 4.
6. **Навык**: раздел «Риски квартала» в SKILL.md sprint-business — что пишет агент и как проверить. Блокирован 4.
