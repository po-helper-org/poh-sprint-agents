# /sprint-status — статус спринта в чат

Короткий текстовый отчёт по текущему спринту: одна и та же форма каждый раз, цифры те же, что на HTML-странице `/actual-sprint`. Текст собирает скрипт, а не модель, поэтому ответ на «как там спринт» больше не зависит от настроения агента.

## Как выглядит

```
Платформа · Спринт 74 — день 6 из 11, до 22.09 (осталось 5 раб. дней)
Готово 5 из 48 (10%) · отстаём от идеального темпа на 21
За сутки: закрытий нет
Статусы: открыто 9 · блок 3 · в работе 20 · тест 3 · ревью 8 · готово 5

Внимание: блокеров 3, без движения >3 дн. — 13
· блок: INIT-138 Нагрузочный прогон — Участник Ж., «В ожидании», 7 дней
· блок: INIT-149 Схема БД — Участник И., «В ожидании», 7 дней
· блок: INIT-128 Схема БД — Участник Г., «В ожидании», 2 дня
· стоит 22 дня: INIT-132 Сервис приёма событий — Участник Ж., «В работе»
· стоит 15 дней: INIT-152 Структура хранения заказов — Участник Г., «В работе»
· ещё 11 — на странице отчёта
Зона риска: 10 в работе дольше медианы; дольше всех — INIT-132 (28 дн.), INIT-150 (25 дн.), INIT-153 (22 дн.)

Эпики (готово/всего):
· Приём заказов из внешнего канала — 0/9
· Единый каталог позиций — 1/7
· Наблюдаемость сервисов — 1/5
```

Демо без JIRA:

```bash
python3 .claude/skills/actual-sprint/scripts/demo_data.py --out demo.json
python3 .claude/skills/sprint-status/status.py --data demo.json --team platform
```

## Что означает каждая строка

| Строка | Как считается |
|---|---|
| **день N из M** | рабочие дни спринта (без суббот и воскресений) по датам спринта в JIRA. «Срок истёк» — дата окончания прошла, а спринт в JIRA ещё активен |
| **Готово X из Y** | задачи спринта с подзадачами, закрытые на сегодня, из объёма на сегодня |
| **отстаём / опережаем** | сегодняшний остаток минус остаток на идеальной прямой (та же серая линия, что на burndown страницы) |
| **За сутки** | разница burndown сегодня и вчера: сколько закрыли, как изменился объём |
| **Статусы** | шесть бакетов по всем задачам спринта; раскладка статусов — `actual-sprint/resources/status_mapping.md` |
| **Внимание** | по историям и подзадачам эпиков: сначала все блокеры, затем задачи в работе, тесте или ревью без смены статуса дольше 3 дней (как красный возраст на странице). Не больше 5 строк, остальное числом |
| **Зона риска** | задачи **этого** спринта, которые идут дольше медианы Cycle Time своей группы. На странице график показывает три спринта, здесь хвосты прошлых спринтов отброшены |
| **Эпики** | готово/всего по всей иерархии эпика; если в эпике есть блокеры — их число |
| **Данные JIRA на …** | когда собран снимок. Старше 12 часов — пометка ⚠ (`--max-age`) |

## Откуда данные

`/actual-sprint` (runner) при каждой успешной сборке пишет рядом со страницей снимок `reports/sprint-report.data.json` — тот же массив команд, что уходит в HTML. `/sprint-status` читает его:

- `status.py` — мгновенно, без обращения к JIRA;
- `status.py --refresh` — сначала пересобирает отчёт runner'ом (страница тоже обновится), потом пишет текст.

Сбор не удался (нет VPN, токен просрочен, сборщик не проверен) — скрипт не молчит и не падает: первой строкой идёт `⚠ Свежий сбор не удался: <причина>`, ниже последний снимок. Путь к снимку меняется ключом `data` в `sprint-report.config.toml`.

## По расписанию в Hermes Agent

### Вариант 1 (рекомендуется): cron без модели

Hermes умеет запускать скрипт по расписанию и отправлять его stdout в чат **дословно**, без LLM (`--no-agent`). Для отчёта фиксированной формы это самый надёжный путь: никаких пересказов, лишних токенов и «творчества».

```bash
cp .claude/skills/sprint-status/hermes/sprint-status.sh "$HERMES_HOME/scripts/"
chmod +x "$HERMES_HOME/scripts/sprint-status.sh"

hermes cron create "45 9 * * 1-5" --no-agent --script sprint-status.sh \
  --name sprint-status --deliver telegram
```

- `SPRINT_REPORT_PROJECT` — каталог проекта с `sprint-report.config.toml` и установленными навыками. По умолчанию `~/sprint-report`.
- `JIRA_URL` и `JIRA_PERSONAL_TOKEN` должны быть в окружении Hermes. Если их нет, придёт последний снимок с пометкой ⚠ и причиной.
- Одна команда вместо всех: допишите `--team <slug>` в последнюю строку скрипта.
- Ненулевой код выхода (нет проекта, конфига или снимка) Hermes доставляет как ошибку — в stdout при этом одна понятная строка.

### Вариант 2: cron с агентом

Если к отчёту нужны пояснения агента или доставка в сессию PO-агента:

```bash
hermes cron create "45 9 * * 1-5" \
  "Выполни навык sprint-status: запусти status.py --refresh и отправь его stdout без изменений." \
  --skill sprint-status --workdir /path/to/project --deliver telegram
```

Промпт cron-задачи должен быть самодостаточным: у задачи нет памяти прошлых разговоров. Навык запрещает агенту переписывать текст, но дословность здесь держится на модели, поэтому для ежедневной рассылки лучше вариант 1.

### Вызов в чате

«Статус спринта», «как идёт спринт», `/sprint-status` → агент запускает скрипт и отдаёт его вывод как есть. Навык ставится вместе с остальными: `bash install.sh <проект>`. В Hermes каталог навыка можно также положить в `~/.hermes/skills/sprint-status/`, но тогда рабочим каталогом агента должен быть проект: пути в навыке относительные.

## Связь с /morning

`/morning` (poh-morning-status) — бриф PO по всем каналам. `/sprint-status` — только спринт. Утренний бриф может брать этот текст целиком как блок «Спринт» вместо пересказа `sprint-report.md`.
