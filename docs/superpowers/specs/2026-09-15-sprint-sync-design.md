# Design — Навык sprint-sync (poh-sprint-agents)

**Дата:** 2026-09-15 · **Статус:** реализовано · **Навык:** `.claude/skills/sprint-sync/`

## 1. Проблема

Спринт идёт, состояние живёт в JIRA, но у скрам-мастера и PO нет одной поверхности «чем занята команда сейчас». Доска показывает карточки, а не картину: кто чем занят, что закрыто, что осталось, где встало. ПЛАН из `sprint-planner` фиксирует ожидание; факта рядом нет.

## 2. Решение

Команда `/sprint-sync` читает трекер и отдаёт два представления одной выгрузки:

1. `sprint-sync-{sprint}.html` — страница состояния (прогресс, счётчики, «Требует внимания», карточки исполнителей с подзадачами, итоговая таблица);
2. краткий отчёт текстом — `Команда · История · Что сделано · Что осталось` — в чат и файлом рядом с HTML.

Разделение ответственности: цифры считает скрипт, трактовку даёт агент. Модель не пересказывает трекер по памяти — это ядро принципа нулевого допуска к галлюцинациям на живых данных.

## 3. Состав

```
.claude/commands/sprint-sync.md          # стадия: доступ → прогон → отчёт → STOP
.claude/skills/sprint-sync/
  SKILL.md                               # роль, доступ, артефакты, границы
  resources/jira_mapping.md              # поля JIRA → колонки отчёта, коды возврата
  resources/report_format.md             # формат текста и структура страницы
  examples/ideal_sync_report.md          # эталон вывода (реальный прогон фикстуры)
  scripts/sprint_sync.py                 # выгрузка и рендер, только стандартная библиотека
tests/fixtures/jira-sample/…json         # сохранённый ответ JIRA для офлайн-прогона
tests/test_sprint_sync.py                # 18 тестов без сети
```

## 4. Решения и обоснование

| Решение | Почему |
|---|---|
| Данные тянет скрипт, не модель | статус/исполнитель/SP не должны проходить через пересказ |
| Классификация по `statusCategory` | имена статусов кастомизируются в каждом инстансе JIRA; категория стабильна. Запасной путь — `done_statuses` из профиля |
| Только GET | синк обратим по определению; материализация в трекер — отдельный срез (VISION, дорожная карта) |
| Конфигурация — секция `## jira` профиля, доступ — окружение | токен не попадает в vault и в git |
| Стандартная библиотека, без зависимостей | навык ставится копированием в любой проект, `install.sh` не тянет окружение |
| `--save-raw` / `--from-json` | спорная цифра воспроизводится офлайн; на этой же паре держатся тесты |
| Незаполненный слот профиля (`[УТОЧНИТЬ …]`) = отсутствие значения | лучше явная ошибка конфигурации, чем запрос к плейсхолдеру |

## 5. Границы

Чтение и рендер. Правки задач в JIRA, презентация, дейли-каденс, ретро — другие срезы дорожной карты. Навык не меняет ПЛАН: расхождение «план ↔ факт» он показывает, решение принимает команда.

## 6. Проверка

`python3 -m pytest tests/ -q` — 25 тестов, сеть не требуется: офлайн-фикстура `tests/fixtures/jira-sample/sprint-2026Q3-S7.json` описывает тот же домен, что `demo-domain` (2026Q3-S7, срез на 6-й день). Покрыто: сборка модели (подзадачи, заглушки `fields.subtasks`, категории статусов, cold-поля), детекторы внимания, обе формы отчёта, экранирование HTML, коды возврата CLI без сети.
