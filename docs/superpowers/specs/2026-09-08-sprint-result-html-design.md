Разбор эталона и таблица «было → стало» — в

Что пережило пересмотр: цикл правок (комментарий на строке → промт → круг по
хэшу содержимого), автономность файла, вайтлист ссылок, лестница готовности.

## 2. Форма

Лента слайдов 1280×720 (16:9) на сером фоне, Arial. Слайд не переливается по
высоте: **что не влезло в 720 пикселей, не существует**. Отсюда разрез стрима
на «(продолжение)» и порог в 6 строк — не оформление, а способ уместить
содержание.

Механика правок живёт в полях: рейка слева, панель справа, попап на строке.
В `@media print` её нет, на показе колода выглядит ровно как эталон.

## 3. Раскладка

Порядок слайдов и состав блоков — БФТ §3.1 и эталон §3. Здесь только то, что
решает вёрстка.

| Слайд | Что решает вёрстка |
|---|---|
| Титул | надзаголовок собирается из имён команд, шапка `.md` уходит в мелкий блок метаданных |
| HERO команды | чёрная черта 64×3, имя 46px, под ним перечень стримов одной строкой |
| Стрим | легенда из трёх пилюль в правом верхнем углу — на каждом слайде: она объясняет заливку строк |
| Изменения | карточка: «было» и «стало» рядом для сравнения, результат под ними с отбивкой |
| Метрики | две карточки в ряд; файла картинки нет → место под него с ожидаемым путём, не битая ссылка |
| Итоги | три счётчика считает экспортёр по строкам всех стримов, руками их не проставляют |

## 4. Четыре правила, вынесенные в код

Это не советы агенту, а поведение экспортёра: агент их не может нарушить.

1. **Сортировка по убыванию результата** + подпись о ней на слайде. Без подписи
   читатель принимает порядок за приоритет.
2. **Заливка строки целиком.** Слайд читается светофором сверху вниз, а не
   сверкой колонки чисел.
3. **Разрез стрима** длиннее порога на «(продолжение)». Содержательный разрез
   при этом остаётся решением PO (Д2) — гейт 6 предупреждает отдельно.
4. **Счётчики итогов** — производное от таблиц. Разойтись с ними не могут.

## 5. Ступень лестницы (решение Д4)

Эталонная ячейка результата несёт только число. Лестница готовности (решение
О2) при этом остаётся механизмом вывода процента.

Развязка: в `.md` ячейка пишется как `80% · ревью пройдено, откат при выкатке`
— ступень есть, гейт 3 её проверяет. На слайде рендерится только `80%`,
ступень уходит в `title=` ячейки. Формат-мишень не нарушен, вывод не потерян.

Так же решён вердикт по Sprint Goal: состояние идёт в подзаголовок слайда,
доказательство — в подсказку. В эталоне вердикта нет вовсе, это дельта навыка;
места под три хода на слайде нет.

## 6. Регистр текста (ФТ-SR-9)

Caveman ultra + anti-slop, порт из `poh-bft-writer`
(`resources/writing_register.md`). Обоснование не стилевое: ячейка в колонке
58% ширины при шрифте 12.5px вмещает ограниченный текст, и длинная
формулировка рвёт слайд. Линтер меряет ячейку в словах (`CV002`) ровно за этим.

## 7. Валидаторы (ФТ-SR-10)

```
ФАКТ-{sprint}.md
   ├─ check_report_structure.py     гейты 2, 3, 4, 6 + структура    🔴 всегда
   └─ sprint-report-style-lint.py   гейт 9: регистр                 🟡 → 🔴 на финале
              ↓ только при нулевом коде
       sprint-report-html.py → ФАКТ-{sprint}.html
```

Колода не собирается по непроверенному документу: сборка дорога тем, что её
показывают. На `/sr-final` оба валидатора блокирующие.

## 8. Границы

Не делаем: экспорт в `.pptx`, вложение файлов в колоду (скриншоты и записи —
ссылками), тёмную тему, автосбор метрик, рендер диаграмм.

## 9. Решения PO

| # | Вопрос | Решение |
|---|---|---|
| **Д1** | Счётчики считают строки или SP | **Строки.** Взвешивание по SP даёт «закрыли 80% спринта» при двух незакрытых Must |
| **Д2** | Порог строк на стрим | **Предупреждать.** Экспортёр режет слайд механически, содержательный разрез — решение PO |
| **Д3** | Исполнитель в отчёте для бизнеса | **Ролью** (`[BE] BE-1`): вклад виден, персональной оценки нет |
| **Д4** | Где ступень лестницы, если в эталоне её в ячейке нет | **В подсказке ячейки** (§5) |
