# `/actual-sprint` — отчёт по факту спринта

Навык читает JIRA и собирает одну самодостаточную HTML-страницу: что происходит в текущем спринте, как команда шла последние три спринта и кто что делал за неделю. Только чтение — в JIRA ничего не пишет.

Страница одна на все команды: переключатель вкладок в шапке, у каждой команды своя доска, свой спринт и свои заметки.

---

## Быстрый старт

```bash
bash install.sh              # развернуть навыки в проект
export JIRA_PERSONAL_TOKEN=…  # личный токен JIRA
```

Дальше в Claude Code:

```
/actual-sprint GDS
```

Навык задаст уточняющие вопросы, покажет что именно соберёт, сходит в JIRA и положит рядом `sprint-report.html`. Открывать лучше через локальный сервер, а не двойным кликом:

```bash
python3 -m http.server 8777
# http://127.0.0.1:8777/sprint-report.html
```

Почему не `file://` — заметки хранятся в `localStorage`, а он привязан к origin. У `file://` origin непредсказуем, и заметки могут не сохраниться между открытиями.

---

## Как проходит запуск

| Стадия | Что происходит | STOP |
|---|---|---|
| 0 | Уточняет команду, проект, спринт и какие типы задач считать историями | да |
| 1 | Показывает состав данных и объём выгрузки — что именно пойдёт в отчёт | да |
| 2 | Находит доску и активный спринт | — |
| 3 | Собирает истории, эпики, подзадачи, метрики, ленту | — |
| 4 | Отрисовывает HTML и отдаёт путь | да |

Стадия 1 существует, чтобы не потратить пару минут выгрузки впустую. Доски часто названы не по команде, а по техлиду или продукту, и «та ли доска» дешевле выяснить до сбора.

### Как найти доску, если она названа не по команде

В крупных проектах десятки досок. Надёжный способ — найти по человеку из команды:

```
project = TLND AND (assignee = <логин> OR reporter = <логин>) AND updated >= -30d
```

В поле спринта (`customfield_10100`) каждой найденной задачи лежит `rapidViewId` — это и есть id доски.

## Что на странице

### Таблица эпиков

Единица отчёта — **эпик**, не история: PO трекает прогресс на этом уровне. Истории без эпика не выбрасываются, а собираются в псевдо-эпик «Без эпика».

В строке — счётчики статусов по всей иерархии (истории плюс подзадачи) в виде `2/2/3/0/5/1`. Порядок фиксирован, цвет на бакет:

| Цвет | Бакет |
|---|---|
| серый | Открыто |
| красный | Заблокировано |
| синий | В работе |
| жёлтый | Тестирование |
| оранжевый | Ревью |
| зелёный | Готово |

Подписей нет намеренно — расшифровка приходит подсказкой при наведении, только по ненулевым: «2 — в бэклоге, 5 — в ревью · всего 13».

Клик по строке открывает панель: слева заметка о прогрессе, справа истории эпика. У каждой истории — статус, возраст статуса и инициалы исполнителя (полное имя по наведению). Стрелка разворачивает подзадачи.

**Возраст статуса** — сколько дней статус не менялся: «1д», «22д». Дольше трёх дней без движения — красным. Считается от даты из changelog, а не от `updated`: последнее двигается от любой правки, включая комментарий, и завышало бы свежесть. У закрытых задач возраст всегда зелёный — они стоят без движения по определению.

### Сводный отчёт за 3 спринта

Клик по Lead Time в шапке. Три графика:

**Burndown текущего спринта.** Серая прямая — идеальный темп, красная ломаная — фактический остаток, обрывается на сегодня. Объём пересчитывается по дням из changelog поля `Sprint`, поэтому внесённые и вынесенные посреди спринта задачи видны ступеньками. Если брать сегодняшний объём как стартовый, burndown врёт.

**Производительность.** Пара столбцов на спринт: плановый разложен по текущим статусам, рядом сделано. Видно, где именно осело незакрытое. Считаются задачи, а не story points — поле заполнено у 67–88% задач в зависимости от спринта, столбец в SP потерял бы до трети работы.

**Диаграммы управления** — отдельно по историям и подзадачам, у подзадач свой масштаб Cycle Time. По горизонтали дата закрытия, по вертикали Cycle Time. Красные точки — выбросы (`среднее + σ`), жёлтые — **зона риска**: задачи, которые ещё не закрыты, но уже идут дольше медианы. Это единственные точки, которые говорят о будущем: выбросы уже случились, а эти ещё можно вытащить. Под графиком оба списка кликабельны.

### Лента активности

Кнопка «Logs». Что команда делала за неделю: смены статусов, комментарии с цитатой и созданные задачи. Фильтры по типу события и по автору комбинируются.

Переходы вида `Backlog → Backlog` не прячутся: в JIRA это реальное событие workflow, и скрывать его — врать, что человек ничего не делал.

## Заметки: как они переживают перезапуск

Заметки пишутся в `localStorage` браузера и сохраняются сами, без кнопки. Но `localStorage` привязан к origin — открыли отчёт с другого порта или в другом браузере, и заметок нет.

Поэтому цикл замыкается вручную:

1. **«Заметки ⬇»** на странице — выгружает `sprint-report-notes.json` со всеми заметками всех команд.
2. Положить файл рядом со страницей.
3. При следующем запуске навык прочитает его и вошьёт заметки в новую страницу.

Живая заметка всегда важнее вшитой: вшитая подставляется только если в этом браузере ключа ещё нет. Иначе правка затиралась бы старой версией при каждом открытии.

Кнопка **«⬆»** рядом — загрузить заметки из файла вручную, если переносите на другую машину.

> Навык никогда не перезаписывает `sprint-report-notes.json` — файл принадлежит вам. Выгружайте его перед тем, как менять браузер или порт.

## Демо без доступа к трекеру

Показать навык или снять скриншоты можно без единого запроса в JIRA:

```bash
python3 .claude/skills/actual-sprint/scripts/demo_data.py --html demo-report.html
```

Собирает страницу на синтетических данных: три команды, вымышленные эпики, задачи `INIT-*`, люди «Участник А…». Сид фиксирован — одинаковый запуск даёт одинаковую картинку, скриншоты не «плывут» между пересборками. Корпоративных данных в файле нет по построению, а не по результату вычистки.

## Пересборка без похода в JIRA

Данные собирает отдельный скрипт, его можно звать напрямую:

```bash
python3 .claude/skills/actual-sprint/scripts/collect.py \
  --board 16383 --team "GDS / Live" --slug gds-live --out gds.json

python3 .claude/skills/actual-sprint/scripts/collect.py \
  --board 6834 --team "LIVE" --slug live --out live.json
```

В шаблоне `resources/report_template.html` ровно один плейсхолдер — `{{TEAMS_JSON}}`. Подставьте туда массив собранных JSON, и страница готова. Порядок в массиве = порядок вкладок.

`slug` обязан быть уникальным: он же ключ, по которому разводятся заметки команд.

Если данные уже собраны, а поменять надо только вёрстку — пересоберите страницу из того же JSON, в JIRA идти не нужно.

## Что считается и как

| Метрика | Определение |
|---|---|
| Lead Time | от создания задачи до перехода в финальный статус |
| Cycle Time | от первого взятия в работу до финального статуса |
| Возраст статуса | от последней смены статуса до сегодня |
| Зона риска | незакрытая задача, идущая дольше медианы Cycle Time своей группы |
| Выброс | закрытая задача с Cycle Time выше `среднее + σ` |

Разница медиан Lead и Cycle — время ожидания в очереди до взятия в работу.

Статусы раскладываются по шести бакетам эвристикой, выверенной регрессией по всем ~330 статусам инстанса. Готовность определяется категорией JIRA и точным совпадением имени, **не подстрокой**: подстрочный поиск уводил «Ожидает решения КЦ» и «Аналитика завершена» в «Готово». Подробности — `resources/status_mapping.md`.

## Если что-то не так

**Собрался не тот спринт.** Список спринтов доски пагинируется. У доски с длинной историей первая страница отдаёт спринты многолетней давности — скрипт обходит все страницы, но если правите его, не потеряйте пагинацию.

**Пустые метрики.** В changelog имена статусов приходят на языке workflow (`Closed`, `In progress`), а `/rest/api/2/status` отдаёт русские. Сопоставлять нужно по числовым id, иначе совпадений ноль.

**Задачи висят, запросы таймаутят.** Проверьте VPN: без него корпоративный хост резолвится в публичный адрес и всё виснет. Быстрая проверка — `curl -sk -m 10 $JIRA_URL/rest/api/2/myself`.

**Заметки пропали.** Открыли с другого порта или браузера. Загрузите `sprint-report-notes.json` кнопкой «⬆».

## Границы

Навык только читает JIRA и генерирует локальный файл. Не пишет в JIRA и Confluence, не публикует страницу наружу, не ходит по расписанию. Токен берётся из окружения и никуда, кроме JIRA, не отправляется.
