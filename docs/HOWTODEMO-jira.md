# HowToDemo — коннектор к корпоративной JIRA

Сценарий приёмки встроенного коннектора: от установки раздела до ответа модели
данными из JIRA. Одиннадцать шагов — ровно те, что заявлены в задаче.

Что проверяем: JIRA приходит в чат **без MCP-моста** — раздел ходит в трекер сам,
доступы задаются в настройках, а модель получает инструменты и понимает, когда
их звать.

---

## 1. Sprint-agent установлен

Навык планирования — в рабочий каталог (там же лежат `backlog/`, `bft/`, волт):

```sh
bash install.sh ~/projects/мой-воркспейс
```

Раздел харнесса — собрать и подключить к профилю
(подробно — [plugins/dsh-plugin-sprint/README.md](../plugins/dsh-plugin-sprint/README.md)):

```sh
cd plugins/dsh-plugin-sprint
npm install && npm run build
```

В `package.json` профиля харнесса (`$DSH_HOME/profiles/web/`) — `link:`-зависимость
на этот каталог и имя пакета в `dsh.profile.bundles`.

> Несобранный плагин роняет харнесс целиком: `npm run build` обязателен,
> `lib/` в репозиторий не коммитится.

## 2. Запускаю DeepSeek Harness

```sh
./scripts/start-web.sh          # в каталоге poh-harness
```

Открыть ссылку с токеном из вывода. Харнесс поднялся без ошибок про плагин —
первый признак, что раздел смонтирован.

## 3. Настройки → Плагины → «Управление спринтами»

**Настройки → Плагины → Конфигурация плагинов**. В списке карточек — «Управление
спринтами». Раскрывается на месте: «Сохранить» и «Отменить» внизу карточки,
«Не сохранено» — в заголовке, пока есть правки.

Карточки нет → узел не отдаёт пространство настроек `sprint-management`:
смотреть журнал харнесса, плагин не поднялся.

## 4. Выбираю иконку JIRA

В карточке — полоса **«Коннекторы»** с иконкой JIRA и подписью состояния
(`не настроен` / `подключение задано`). Клик по иконке раскрывает поля этого
коннектора. Следующий источник данных спринта встанет в полосу рядом — поля под
полосой принадлежат выбранному.

## 5. Ввожу доступы

| Поле | Пример |
|---|---|
| Ссылка на JIRA | `https://jira.example.com` |
| Токен доступа | персональный токен JIRA (вводится скрыто) |
| Промт подключения | «Команда ведёт проект SPRINT. Историей считаем тип „История“. Статус „Готово“ означает принято PO.» |

Необязательное, но ради шага 9 полезное: **Проект** — ключ проекта команды
(`SPRINT`). Без него (и без своего JQL) инструмент историй скажет, чего ему не
хватает, вместо того чтобы гадать.

## 6. «Протестировать» → статус подключения

Кнопка проверяет **введённое**, а не записанное: сохранять до проверки не нужно.

Ожидаемый ответ — зелёная строка:

```
Подключение к https://jira.example.com установлено: Иванов И.; запрос историй вернул 12
```

Красная строка называет причину, а не «не получилось»:

| Строка | Что чинить |
|---|---|
| `JIRA не приняла токен (401)` | токен истёк или скопирован не целиком |
| `JIRA отказала в доступе (403) (JIRA требует входа через браузер: …)` | контур просит пройти капчу в браузере и повторить |
| `JIRA ответила не JSON … страница входа SSO` | адрес ведёт на SSO-портал, а не в REST API |
| `JIRA не ответила в отведённое время` | нет VPN либо мал `timeoutMs` в конфигурации плагина |
| `подключение есть, но запрос историй не прошёл — …` | доступ рабочий, чинить ключ проекта или JQL |

Затем — **«Сохранить»**.

## 7. Закрываю настройки

Панель настроек закрывается. Сохранённые значения живут в документе настроек
харнесса; перезапуск для них не нужен — инструменты читают настройки на каждый
вызов.

## 8. Перехожу в режим чата

Новый чат в харнессе.

## 9. Спрашиваю про истории команды

```
Покажи актуальные истории команды из JIRA
```

## 10. Модель зовёт коннектор

В ленте чата виден вызов `jira_current_stories` — не `run_code`, не MCP-инструмент.
Выбор не случаен: схема инструмента уехала в промт вместе с секцией «Корпоративная
JIRA», где сказано, что вопрос про истории команды — это вызов инструмента, и туда
же попал ваш промт подключения из шага 5.

Уточняющие вопросы работают тем же коннектором: «а что у Иванова» →
`jira_current_stories` с фильтром по исполнителю; «покажи SPRINT-128» →
`jira_issue`; «а что было в прошлом спринте» → `jira_search` со своим JQL.

## 11. Получаю ответ с данными из JIRA

Ответ построен на таблице инструмента: ключ, тип, статус, исполнитель, SP,
спринт, заголовок. Пустое поле — прочерк, не выдумка. Ключи задач кликабельны:
`https://jira.example.com/browse/SPRINT-128`.

## Что считается приёмкой

| Шаг | Признак |
|---|---|
| 3 | Карточка «Управление спринтами» есть в списке плагинов |
| 4 | Иконка JIRA раскрывает поля коннектора |
| 6 | Проверка отвечает учётной записью или названной причиной отказа |
| 10 | В ленте чата виден вызов `jira_current_stories` |
| 11 | В ответе — ключи и статусы из JIRA, ссылки ведут в трекер |

## Границы демо

Коннектор только читает. Ни одной записи в JIRA сценарий не делает и сделать не
может: заведение задач и смена статусов — отдельный срез дорожной карты
([VISION](../VISION.md)).
