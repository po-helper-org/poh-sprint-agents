# Отладка `/actual-sprint` на реальном инстансе

Фикстуры проверяют логику, а живой JIRA — окружение: VPN, сертификаты, права, чужие имена статусов. Этот файл про второе.

## Порядок первого запуска

```bash
export JIRA_URL=https://jira.вашкомпания.ru
export JIRA_PERSONAL_TOKEN=…            # PAT, только в окружении

R=.claude/skills/actual-sprint/runner/run.py
python3 $R doctor                        # 1. стенд: файлы, конфиг, переменные, lock. Без сети
python3 $R validate <slug> --sample 5    # 2. первый поход в JIRA по одной команде
python3 $R lock <slug>                   # 3. после сверки выборки с трекером
python3 $R run                           # 4. отчёт
```

Не начинайте с `run`: он идёт по всем командам сразу, и разбирать придётся несколько отказов одновременно. `validate` работает по одной команде и печатает то, что нужно для сверки.

## Что видно → что это → что делать

| Сообщение | Причина | Действие |
|---|---|---|
| `runner требует Python 3.9+` | слишком старый интерпретатор | запустить другим: `python3.11 run.py …` (на 3.9–3.10 конфиг читает мини-парсер, на 3.11+ — `tomllib`) |
| `[slug] ✗ сайдкар протух: N ч` (в `merge`) | команду давно не собирали | `run --only slug`, либо `merge … --stale-ok` — страница с пометкой возраста |
| `конфиг: … board должен быть числом` | опечатка в `sprint-report.config.toml` | сообщение называет команду и поле |
| `переменная окружения … не задана` | нет `JIRA_URL` или токена | `export`, затем `doctor` ещё раз |
| `сертификат JIRA не проверился … укажите jira.ca_bundle` | корпоративный CA, которого нет в системном хранилище | положить бандл в проект и прописать `jira.ca_bundle`. **Проверку не отключаем**: по этому соединению идёт личный токен |
| `не читается CA-бандл <путь>` | путь есть в конфиге, но файла нет или нет прав | поправить путь |
| `JIRA недоступна (…) — проверьте VPN и адрес` | нет VPN, опечатка в хосте, прокси | `curl -sS -o /dev/null -w '%{http_code}' "$JIRA_URL/rest/api/2/myself" -H "Authorization: Bearer $JIRA_PERSONAL_TOKEN"` — ожидается 200 |
| `JIRA не авторизует запрос (HTTP 401)` | токен просрочен, отозван или скопирован не целиком | выпустить новый PAT |
| `в … есть символы вне latin-1` | в переменную попал не токен (например, текст из письма) | скопировать токен заново |
| `доски #N не существует или она не видна этому токену` | не тот id доски или нет прав | id доски виден в URL: `…/RapidBoard.jspa?rapidView=<id>` |
| `у доски N нет спринтов` | доска канбанная или спринты не заведены | навык рассчитан на scrum-доску с активным спринтом |
| `ни одна задача спринта не попала в story_types` | у команды свои названия типов задач | посмотреть реальные типы в спринте и вписать их в `params.story_types` |
| `поле связи с эпиком не найдено` | поле называется не «Ссылка на эпик» / «Epic Link» | найти id поля и задать `params.epic_link_field = "customfield_XXXXX"` |
| `N эпиков не отдались по ключу` | нет прав на проект эпика или эпик удалён | обычно не мешает: строка эпика останется без названия |
| `статус «X» не покрыт правилами бакетов → progress` | в workflow есть статус, которого правила не знают | вписать его в `params.status_buckets`, если это не «в работе» |
| `сборщик не проверен` / `базовый сборщик обновился` | strict-режим | `/collector-validate <slug>` и заново `lock` |
| `схема ✗` / `инвариант N` | сборщик отдал не то, что обещал | чинить **код сборщика**; сообщение называет команду и путь поля |

Коды выхода: `0` успех, `1` прочая ошибка, `2` конфиг или lock, `3` JIRA недоступна или не авторизует.

## Снять сырые ответы трекера

Чтобы отлаживать логику сборщика без повторных походов в JIRA:

```toml
[teams.params]
record = "./fixtures/team-a"       # один прогон с записью
# replay = "./fixtures/team-a"     # дальше — из записанного, без сети
```

`_index.json` в каталоге показывает, какой файл каким запросом получен.

**В дампах лежат реальные данные задач** — названия, ФИО исполнителей, комментарии. Токена и заголовков авторизации там нет по построению, но сам дамп корпоративный: не выкладывайте его в публичные места и не прикладывайте к внешним issue. Для воспроизведения бага обычно хватает одного-двух файлов.

## Что прислать, если нужен разбор

- Полный вывод `doctor` и упавшей команды — токена в них нет по построению (проверено тестом).
- Номер строки инварианта или путь поля из сообщения.
- **Не присылать:** токен, целиком record-дамп, готовый `sprint-report.html` — в нём все задачи команды.

Достаточная выжимка, если сомневаетесь:

```bash
python3 $R validate <slug> --sample 5 2>&1 | tail -40
```

## Известные особенности реальных инстансов

- **Спринты пагинируются.** У доски с долгой историей первая страница отдаёт спринты многолетней давности — сборщик обходит все страницы, не потеряйте это при правках.
- **Язык workflow.** В changelog имена статусов приходят на языке процесса (`Closed`, `In progress`), а `/rest/api/2/status` отдаёт локализованные. Сопоставление идёт по числовым id. Категории «выполнено» и «в работе» берутся из `contract/status_rules.json` и переопределяются `params.done_categories` / `params.progress_categories`.
- **Названия эпиков** добираются пачками по 50 ключей (`params.epic_batch`): длина JQL не резиновая.
- **Нагрузка.** Полный сбор команды за три спринта — порядка 10–15 запросов, без запроса на каждую задачу. Число в `_meta.requests` и в сводке.
- **Только чтение.** У клиента сборщика есть единственный метод — GET. Записи в трекер нет ни в одном режиме.
