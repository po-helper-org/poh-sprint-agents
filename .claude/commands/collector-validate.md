# /collector-validate {slug}

Роль: проверяющий сборщика. Здесь ты **имеешь право** ходить в JIRA — но только чтобы сверить выборку, а не чтобы собрать отчёт.

1. **Прогон.**
   ```bash
   python3 .claude/skills/actual-sprint/runner/run.py validate {slug} --sample 5
   ```
2. **Покрытие.** Тот же вывод печатает «покрытие экранов»: какие экраны отчёта PO, презентации и PDF останутся без данных и каких полей не хватает (`.claude/skills/sprint-data/reference/render.md`). Пустой экран, который команде нужен, — повод доделать сборщик, а не подставить данные.
3. **Починка.** Схема или инварианты упали → правь **код сборщика** (не данные, не схему) и повторяй прогон, пока не станет `14/14 ✓`. Ошибка называет команду и путь поля — начинай с него. Ошибка сборщика с кодом 3 — это VPN или токен, тут править нечего.
4. **Сверка с JIRA.** Возьми напечатанные задачи выборки и запроси их в трекере доступным инструментом. Сравни поле за полем: статус, категория, эпик или родитель, исполнитель. Покажи человеку расхождения и спорные решения — например, статус, который сборщик считает блокировкой, а команда считает работой.
5. **Предупреждения.** Разбери каждое: новый статус вне правил бакетов лечится строкой в `params.status_buckets`, истории без эпика — решением PO, считать ли их вообще.
6. **Гейт PO.** Спроси прямо: «совпало, фиксируем?» Только после «да»:
   ```bash
   python3 .claude/skills/actual-sprint/runner/run.py lock {slug}
   ```
   Хеш пишется в `sprint-report.lock.json`. Этот файл — машинный: руками его не правят. Если сборщик изменится хоть на байт, runner откажется его запускать, пока проверка не пройдёт заново.

**STOP** после записи хеша: показать, что зафиксировано, и что дальше `/actual-sprint`.
