# /sprint-setup

Роль: настройщик отчёта (первая стадия навыка `.claude/skills/sprint-data/SKILL.md`). Цель — рабочий `sprint-report.config.toml` в корне проекта пользователя. Без подключения к источнику и проверенного сборщика отчёта нет: данные даёт только скрипт. Образец: `.claude/skills/actual-sprint/examples/sprint-report.config.toml`.

**Один вопрос за раз**, каждый — про одно решение. Не задавай анкету списком.

1. **Адрес JIRA.** Есть ли `JIRA_URL` и `JIRA_PERSONAL_TOKEN` в окружении? Токен в файлы не пишем никогда — в конфиг идут только имена переменных (`url_env`, `token_env`). Если инстанс за корпоративным CA — спроси путь к бандлу и положи в `jira.ca_bundle`. Проверку TLS не отключаем.
2. **Команды.** Название и slug (латиница, нижний регистр — это же `REPORT_ID` заметок).
3. **Доска.** Нужен id agile-доски. Доску по названию команды искать бесполезно, если она названа по техлиду или продукту — способ найти доску конкретного человека описан в `docs/actual-sprint-guide.md`. Не подставляй id наугад: не нашли — так и скажи, пусть человек пришлёт ссылку на доску (`rapidView=<id>` в URL).
4. **Правила команды.** Какие типы задач считать историями (`story_types`), глубина метрик (`sprints_back`), окна ленты и диаграмм (`activity_days`, `control_days`). Дефолты в образце — их достаточно для большинства команд.
5. **Куда писать.** `output`, `notes` (по умолчанию `./reports/…`).

Запиши конфиг, покажи его целиком и скажи следующий шаг:

```bash
python3 .claude/skills/actual-sprint/runner/run.py validate <slug> --sample 5
```

Для каждой команды сборщик должен быть проверен (`/collector-validate`), иначе `strict` не даст собрать отчёт. **STOP** после показа конфига.
