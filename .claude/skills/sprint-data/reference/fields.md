# Справочник полей JSON команды

Один объект — одна команда. Сборщик отдаёт его в stdout (протокол — `actual-sprint/contract/PROTOCOL.md`); runner проверяет его схемой `actual-sprint/contract/team.schema.json` и 14 инвариантами и складывает объекты всех команд в массив `TEAMS` — снимок `reports/sprint-report.data.json`. Этот массив без изменений читают отчёт PO, презентация, PDF-статус и факты для ИИ.

**Схема — источник истины по форме**, этот файл — по смыслу: зачем поле, как его получить из трекера, на каком экране оно видно и что будет без него. Образец со всеми полями — `actual-sprint/examples/example_team_full.json`. Как поля превращаются в экраны — `render.md`. Как их собрать из JIRA — `../guides/jira.md`.

## Соглашения

| Что | Формат | Пример |
|---|---|---|
| момент времени | ISO 8601 с поясом; пояс со двоеточием (`+03:00`) — предпочтительно, JIRA-вид `+0300` страницы тоже понимают | `2026-09-15T17:00:00+03:00` |
| дата | `YYYY-MM-DD` | `2026-09-15` |
| момент до минуты (события, история, комментарии) | `YYYY-MM-DDTHH:MM`, время трекера без пояса | `2026-09-12T14:05` |
| длительность | дни, дробное число | `3.5` |
| люди | `displayName` как в трекере; без исполнителя — `null` (в `output` — строка `Не назначен`) | `Иванов Иван` |
| статус | `status.name` как в трекере, не переводится | `Ожидает ревью` |
| категория статуса | `statusCategory.name` как в трекере; набор — `contract/status_rules.json` (`categories`) или `params.categories` | `В работе` |
| бакет | одно из `open`, `blocked`, `progress`, `testing`, `review`, `done` | `review` |

Порядок массивов значим: спринты (`metrics.sprints`, `velocity.sprints`, `output.sprints`) — от старого к новому, последний — активный; точки диаграмм — по возрастанию `doneAt`; хронология истории — по возрастанию `at`; лента — по убыванию `at`. Имена людей — одна строка на человека во всех секциях: `output.sprints[].members[].name` и ключи `output.lead` совпадают с `assignee` историй и подзадач, иначе строки участников не связываются.

Обязательность: **обяз.** — схема не пропустит без поля; **нет → …** — поле необязательное, и сказано, что пропадёт со страниц. Пустая выборка статистики — `null`, а не нули: «0 дней» и «нет данных» — разные утверждения. Числа и даты сборщик не округляет «для красоты» сверх указанного.

## Почему форма такая
- **Единица отчёта — эпик**, а не история: PO ведёт прогресс по эпикам. Истории без эпика не выбрасываются — они в одном псевдо-эпике `rowId: "no-epic"`, `epicKey: null`: потерянная работа хуже некрасивой строки.
- **Агрегатов нет.** Процентов готовности эпика, «3 из 5» и бакетов задач в данных нет: страница считает их сама из статусов, поэтому таблица, графики и счётчики не могут разойтись.
- **Статус — как в трекере**, бакет — отдельно, в `statusMap`: у команд разные workflow, и правило «что такое ревью» принадлежит команде (`params.status_buckets`), а не шаблону. Категория статуса не заменяет бакет: «Ожидает тестирование» — очередь, а не тесты.
- **Даты, а не дни.** В данных лежит момент смены статуса (`statusChanged`), а не «N дней»: дни считает страница. `fields.updated` для этого не годится — он двигается от любой правки.
- **Окна — период спринта.** Лента, история и комментарии задач участника — в границах спринта; диаграммы управления — спринты отчёта; хронология истории — вся её жизнь.
- **Две выборки диаграмм управления**: у подзадач свой масштаб Cycle Time, в общей куче он теряется.
- **Паспорт сбора обязателен** (`_meta`): без него не видно, чем и когда собраны цифры, а значит им нельзя доверять.

| `team` | строка | обяз. | название команды из конфига | переключатель команд, титул и слайды презентации |
| `boardId` | целое | обяз. | id agile-доски | — (сверка с конфигом, инвариант 1) |

| `sprintName` | строка | обяз. | имя активного спринта — якоря отчёта; равно имени последнего спринта в `velocity.sprints` и `output.sprints` | шапка, заголовок презентации, PDF, ключи заметок |
| `statusMap` | объект статус → бакет | нет → бакет по правилам в браузере | раскладка всех встреченных статусов (`contract/buckets.py` + `params.status_buckets`) | цвет каждого статуса, группы на всех экранах |

| `_meta.warnings` | массив строк | обяз. | что человек должен увидеть: статус вне правил, задачи без эпика, обрезанная выборка | сводка runner, PDF |
| `_meta.sha` | строка | дописывает runner | хеш проверенного сборщика | — |

## Эпики — `epics[]`
Единица отчёта PO — эпик. Порядок массива = порядок строк таблицы.

| Поле | Тип | | Смысл и источник | Где видно |
|---|---|---|---|---|
| `epics[].rowId` | строка | обяз. | уникальный id строки: ключ эпика, у псевдо-эпика — `no-epic` | строки таблицы, заметки |
| `epics[].epicKey` | строка \| `null` | обяз. | ключ эпика из поля связи истории; `null` — псевдо-эпик «Без эпика» (ровно один на команду) | таблица, KR в презентации |
| `epics[].epicTitle` | строка \| `null` | обяз. | `summary` эпика (пакетный поиск по ключам); у эпика с ключом не `null` — нет прав на эпик, значит ключ (сборщик 1.9.0+); `null` — только у псевдо-эпика | таблица, шапка KR, «Эпик «…»» в «Планах» |
| `epics[].epicPriority` | строка \| `null` | нет → глиф «·» | `priority.name` эпика | глиф приоритета в таблице |
| `epics[].epicDue` | дата \| `null` | нет → нет плановой даты | `duedate` эпика | красная линия «план» и итог в днях на сгорании эпика |
| `epics[].stories` | массив | обяз. | истории активного спринта этого эпика | таблица, панель эпика, строки слайдов целей |
| `epics[].scope` | массив | нет → нет «Весь эпик» | весь объём эпика, не только спринт | «Весь эпик», сгорание эпика, клик по KR, «Взять в работу» в «Планах» |

## Истории спринта — `epics[].stories[]`
История — задача типа из `params.report_types` (по умолчанию — `story_types`). `report_types = "*"` — в эпики отчёта идут все задачи спринта, кроме подзадач и эпиков: истории, задачи, ошибки (иначе работы типа «Задача»/«Ошибка» в отчёте не видны, хотя есть в метриках).

| Поле | Тип | | Смысл и источник | Где видно |
|---|---|---|---|---|
| `epics[].stories[].key` | строка | обяз. | ключ | везде, ссылки |
| `epics[].stories[].title` | строка | обяз. | `summary` | панель эпика, строки слайдов |
| `epics[].stories[].status` | строка | обяз. | `status.name` | бейдж, счётчики, результат строки |
| `epics[].stories[].category` | строка | обяз. | `statusCategory.name` по id статуса | бакет, если статуса нет в `statusMap` |
| `epics[].stories[].statusChanged` | момент времени \| `null` | нет → «—» вместо возраста | последняя смена статуса из changelog; не было — `created`. Первые 10 знаков — дата | возраст статуса (красный дольше 3 дней), «в работе с …» и «стоит с …» на слайдах, «застряли» на операционном, блокеры в «Итогах», PDF «без движения» |
| `epics[].stories[].assignee` | строка \| `null` | нет → «—», всё у «Не назначен» | `assignee.displayName` | инициалы в панели, распределение по участникам на операционном слайде |
| `epics[].stories[].priority` | строка \| `null` | нет → глиф «·» | `priority.name` | глиф приоритета |
| `epics[].stories[].subtasks` | массив | обяз. (может быть пустым) | подзадачи истории | счётчики эпика, результат строки (доля закрытых), «сделано / след. шаг» |
| `epics[].stories[].events` | массив | нет → события из ленты спринта | хронология за всё время, сборщик 1.7.0+ | календарь и лента в сайдбаре истории (презентация) |

### Подзадачи — `epics[].stories[].subtasks[]`

| Поле | Тип | | Смысл и источник | Где видно |
|---|---|---|---|---|
| `epics[].stories[].subtasks[].key` | строка | обяз. | ключ | панель эпика |
| `epics[].stories[].subtasks[].summary` | строка | обяз. | название (у подзадачи поле `summary`, не `title`) | панель, «сделано: …», «след. шаг» |
| `epics[].stories[].subtasks[].status` | строка | обяз. | `status.name` | бейдж, счётчики |
| `epics[].stories[].subtasks[].category` | строка | обяз. | категория статуса | бакет |
| `epics[].stories[].subtasks[].statusChanged` | момент времени \| `null` | нет → «—» | из той же задачи в списке спринта | возраст статуса, «застряли» |
| `epics[].stories[].subtasks[].assignee` | строка \| `null` | нет → «Не назначен» | исполнитель подзадачи | инициалы, полоса «Подзадачи» у её исполнителя на операционном слайде |
| `epics[].stories[].subtasks[].priority` | строка \| `null` | нет → «·» | `priority.name` | глиф приоритета |

### Хронология истории — `epics[].stories[].events[]`
Создание, смены статуса и комментарии самой истории и её подзадач **за всё время**, по возрастанию `at` (первое событие — начало календаря, последнее — конец). Ключ события — сама история или одна из её подзадач: по нему событие ложится в дорожку «История» или «Подзадачи».

| Поле | Тип | | Смысл |
|---|---|---|---|
| `epics[].stories[].events[].at` | момент до минуты `YYYY-MM-DDTHH:MM` | обяз. | когда |
| `epics[].stories[].events[].kind` | `created` \| `status` \| `comment` | обяз. | вид события |
| `epics[].stories[].events[].key` | строка | обяз. | история или её подзадача |
| `epics[].stories[].events[].by` | строка \| `null` | | автор |
| `epics[].stories[].events[].from` | строка \| `null` | у `status` | статус до |
| `epics[].stories[].events[].to` | строка \| `null` | у `status` | статус после — цвет полосы статуса истории на календаре |
| `epics[].stories[].events[].done` | булево | у `status` | новый статус — «закрыто»: на календаре это закрытие |
| `epics[].stories[].events[].body` | строка ≤ 400 | у `comment` | текст комментария |

## Весь эпик — `epics[].scope[]`
Все задачи эпика (без подзадач на верхнем уровне): сделанные раньше, текущие, бэклог. Порядок — ранг доски. Задача текущего спринта в объёме имеет тот же `key`, что история в `stories[]`: страница подставляет ей подзадачи спринта.

| Поле | Тип | | Смысл и источник | Где видно |
|---|---|---|---|---|
| `epics[].scope[].key` | строка | обяз. | ключ | разделы «Что осталось» / «Что выполнено» |
| `epics[].scope[].title` | строка | обяз. | `summary` | там же, «Взять в работу» |
| `epics[].scope[].type` | строка | | `issuetype.name` | не показывается (для сверки) |
| `epics[].scope[].status` | строка | обяз. | `status.name` | группа «что осталось» по процессу |
| `epics[].scope[].category` | строка | обяз. | категория | бакет |
| `epics[].scope[].assignee` | строка \| `null` | | исполнитель | инициалы |
| `epics[].scope[].priority` | строка \| `null` | | приоритет | глиф |
| `epics[].scope[].sprint` | строка \| `null` | | имя спринта отчёта, где задача была; `null` — вне спринтов отчёта | метка «в спринте» / имя спринта / «вне спринта» |
| `epics[].scope[].inSprint` | булево | | задача в активном спринте | метка, «Взять в работу» берёт только вне спринта |
| `epics[].scope[].created` | дата \| `null` | | создание | сгорание эпика: «добавлено» по неделям |
| `epics[].scope[].doneAt` | дата \| `null` | | `resolutiondate` закрытой; у незакрытой `null` | сгорание эпика: «выполнено» по неделям, темп и прогноз |
| `epics[].scope[].sp` | число \| `null` | | Story Points; `null` — без оценки (сборщик 1.6.0+) | сгорание эпика в основе «SP» |
| `epics[].scope[].subtasks` | массив | обяз. | подзадачи задачи | основа «закрытие подзадач» |
| `epics[].scope[].subtasks[].key` | строка | обяз. | ключ | — |
| `epics[].scope[].subtasks[].summary` | строка | обяз. | название | — |
| `epics[].scope[].subtasks[].status` | строка | обяз. | статус | бакет |
| `epics[].scope[].subtasks[].category` | строка | обяз. | категория | бакет |
| `epics[].scope[].subtasks[].priority` | строка \| `null` | | приоритет | — |
| `epics[].scope[].subtasks[].created` | дата \| `null` | | создание (сборщик 1.6.0+) | сгорание по подзадачам |
| `epics[].scope[].subtasks[].doneAt` | дата \| `null` | | решение | сгорание по подзадачам |
| `epics[].scope[].subtasks[].assignee` | строка \| `null` | | исполнитель (сборщик 1.9.0+; в заглушке подзадачи его нет — пакетный поиск по родителям) | инициалы в «Весь эпик»; без поля — «—» у подзадач вне спринта |

## Метрики за спринты отчёта — `metrics`
`metrics.sprints[]` — по спринту, от старого к новому, последний — активный. Считаются по **всем** задачам спринта: истории, задачи, баги, подзадачи. Определения Lead и Cycle — `actual-sprint/resources/metrics.md`.

| Поле | Тип | | Смысл |
|---|---|---|---|
| `metrics.sprints[].name` | строка | обяз. | имя спринта |
| `metrics.sprints[].total` | целое | обяз. | задач в спринте |
| `metrics.sprints[].closed` | целое | обяз. | закрыто (категория «закрыто» и дата закрытия есть) |
| `metrics.sprints[].open` | целое | обяз. | `total − closed` |
| `metrics.sprints[].throughputPct` | целое 0–100 | обяз. | `round(100 · closed / total)` |
| `metrics.sprints[].lead` | stats \| `null` | обяз. | Lead Time закрытых: от создания до закрытия |
| `metrics.sprints[].cycle` | stats \| `null` | обяз. | Cycle Time: от первого «в работе» до закрытия |
| `metrics.sprints[].leadStory` | stats \| `null` | обяз. | Lead Time историй |
| `metrics.sprints[].leadTask` | stats \| `null` | обяз. | Lead Time задач верхнего уровня, кроме историй |
| `metrics.sprints[].points` | массив чисел | обяз. | Lead Time каждой закрытой, по возрастанию (`count` = длина) |
| `metrics.overall.lead` / `.cycle` / `.leadStory` / `.leadTask` | stats \| `null` | обяз. | то же по всем спринтам отчёта |
| `metrics.overall.total` / `.closed` | целое | обяз. | суммы по спринтам |

stats — `{ "mean": число, "median": число, "count": целое }`, дни, округление до 0,1. Где видно: страницы рисуют только `metrics.overall.lead` — Lead Time в шапке отчёта PO (среднее / медиана / кол-во). `metrics.sprints[]` — тренд в фактах для ИИ (`insights.py facts`: взято, закрыто, `throughputPct`, медианы) и база инвариантов 8–9; `leadStory` / `leadTask` по всем спринтам страницы не показывают.

## Производительность — `velocity`

| Поле | Тип | | Смысл |
|---|---|---|---|
| `velocity.unit` | строка | обяз. | единица: `задач` |
| `velocity.avgDone` | число | обяз. | среднее `done` по спринтам — пунктир на графике |
| `velocity.sprints[].name` | строка | обяз. | спринт |
| `velocity.sprints[].planned` | целое | обяз. | задач в спринте |
| `velocity.sprints[].done` | целое | обяз. | из них в бакете `done` |
| `velocity.sprints[].split` | объект бакет → целое | обяз. | разбивка `planned` по шести бакетам текущих статусов; сумма = `planned`, `split.done` = `done` |

Порядок спринтов — от старого к новому, последний — активный (`name` = `sprintName`). Где видно: «Производительность» в метриках отчёта PO; на операционном слайде, если нет `output`; `split` последнего спринта — «Статусы» в PDF и «где лежит работа» в фактах для ИИ. `unit` страницы не показывают.

## Сгорание активного спринта — `burndown`

| Поле | Тип | | Смысл |
|---|---|---|---|
| `burndown.sprintName` | строка | обяз. | спринт (страницы берут имя из `sprintName`) |
| `burndown.start` / `burndown.end` | дата | обяз. | первый и последний день спринта |
| `burndown.days[].date` | дата | обяз. | день; дни подряд от `start` до `end` |
| `burndown.days[].scope` | целое | обяз. | задач в спринте на этот день — из истории поля `Sprint`: внесённые и вынесенные видны ступеньками |
| `burndown.days[].closed` | целое | обяз. | закрыто к концу дня |
| `burndown.days[].remaining` | целое | обяз. | `scope − closed` |
| `burndown.days[].storyScope` | целое | необяз. | из `scope` — задач без подзадач (истории, задачи, баги: у типа нет признака `subtask`); сборщик 1.10.0+ |
| `burndown.days[].storyClosed` | целое | необяз. | из них закрыто к концу дня; только парой со `storyScope`, `storyClosed ≤ storyScope ≤ scope` |
| `burndown.days[].weekend` | булево | обяз. | выходной — затеняется, не входит в рабочие дни |
| `burndown.days[].future` | булево | обяз. | день позже `now` — линия факта обрывается |
| `burndown.items[]` | массив | | из чего сложилось сгорание (сборщик 1.10.0+): задача спринта и её даты |
| `burndown.items[].key` / `.title` | строка | `key` обяз. | задача |
| `burndown.items[].subtask` | булево | обяз. | подзадача — входит только в сгорание «с подзадачами» |
| `burndown.items[].entered` | дата | обяз. | вошла в спринт (не раньше его начала) |
| `burndown.items[].left` / `.doneAt` | дата \| `null` | | вышла из спринта / закрыта |

Где видно: burndown в метриках отчёта PO, два сгорания на операционном слайде презентации («истории и задачи» — по `storyScope/storyClosed`, «с подзадачами» — по `scope/closed`), темп «день N из M», KPI и burndown в PDF.

## Диаграммы управления — `control`
Две независимые выборки одинаковой формы: `control.stories` (всё, кроме подзадач) и `control.subtasks` — у подзадач свой масштаб Cycle Time.

| Поле | Тип | | Смысл |
|---|---|---|---|
| `control.days` | целое | обяз. | окно выборки, дней: `params.control_days` или (по умолчанию, сборщик 1.9.0+) от начала первого спринта отчёта |
| `control.stories.days` | целое | обяз. | то же у выборки — «за N дн.» в подсказке диаграммы отчёта PO |
| `control.stories.points[].key` / `.title` | строка | обяз. | задача |
| `control.stories.points[].status` / `.category` | строка | обяз. | её текущий статус (финальный бывает разным: «Отменён») |
| `control.stories.points[].doneAt` | дата | обяз. | дата закрытия — ось X |
| `control.stories.points[].cycle` | число ≥ 0 | обяз. | Cycle Time, дни — ось Y |
| `control.stories.points[].outlier` | булево | при непустых `points` | `cycle > limit`; без флага отчёт PO не покажет выбросов, факты ИИ не соберутся |
| `control.stories.risks[].key` / `.title` / `.status` / `.category` | строка | обяз. | незакрытая задача, взятая в работу |
| `control.stories.risks[].assignee` | строка \| `null` | | исполнитель |
| `control.stories.risks[].elapsed` | число | обяз. | дней в работе на `now`; в списке только `elapsed > median` |
| `control.stories.mean` / `.median` / `.sd` | число | при непустых `points` | статистика окна (σ — генеральной совокупности) |
| `control.stories.limit` | число | при непустых `points` | порог выброса `mean + sd` — красная линия |
| `control.stories.outliers` | целое | | сколько выбросов (страницы пересчитывают сами) |
| `control.stories.today` | дата | | дата `now` (не показывается) |

`control.subtasks.*` — те же поля. Точки — по возрастанию `doneAt`: отчёт PO рисует их и скользящее среднее в порядке массива. При непустых `points` статистика (`mean`, `median`, `sd`, `limit`) и флаги `outlier` обязательны (инвариант 10). Где видно: диаграммы управления в метриках отчёта PO (как есть); слайд «Сроки» и его разбор по клику — презентация пересчитывает статистику в окне «3 спринта» сама (`controlWindow`), поэтому точки должны покрывать все спринты отчёта: по умолчанию так и есть, явный `params.control_days` — не меньше их длины; зона риска в PDF; факты для ИИ.

## Выработка участников — `output`
Сборщик 1.3.0+. По спринтам отчёта от старого к новому, **без подзадач**: оценка живёт на задаче. Статус и исполнитель — на конец каждого спринта (у активного — на сейчас), восстановлены из истории изменений.

| Поле | Тип | | Смысл |
|---|---|---|---|
| `output.unit` | `SP` \| `задач` | обяз. | `SP` — поле Story Points найдено; согласовано с `field` (инвариант 13) |
| `output.field` | строка \| `null` | обяз. | id поля SP; страницы решают «SP или задачи» по нему |
| `output.sprints[].name` | строка | обяз. | спринт |
| `output.sprints[].current` | булево | обяз. | активный; только у последнего, его `name` = `sprintName` |
| `output.sprints[].start` / `.end` | дата \| `null` | | даты спринта — полосы спринтов на «Сроках», окно «3 спринта» |
| `output.sprints[].timeInStatus` | объект | | сборщик 1.8.0+: средние дни задачи спринта в бакете, в границах спринта |
| `output.sprints[].timeInStatus.blocked` / `.progress` / `.review` / `.testing` | число ≥ 0 | | «Заблокировано», «Ревью», «Отладка» на «Сроках»; `progress` собирается, на слайде не показывается |
| `output.sprints[].members[].name` | строка | обяз. | исполнитель на конец спринта — тот же `displayName`, что в `assignee`; без исполнителя — ровно `Не назначен` |
| `output.sprints[].members[].split` | объект бакет → `[задач, SP]` | обяз. | где лежала работа на конец спринта; `done` — выработка; число задач по бакету = числу `items` с этим бакетом (инвариант 13) |
| `output.sprints[].members[].items[]` | массив | | задачи участника в спринте (сборщик 1.4.0+) |
| `output.sprints[].members[].items[].key` / `.title` / `.status` | строка | обяз. | задача, статус на конец спринта |
| `output.sprints[].members[].items[].bucket` | бакет | обяз. | бакет того статуса |
| `output.sprints[].members[].items[].sp` | число ≥ 0 | обяз. | SP; без оценки — 0 |
| `output.sprints[].members[].items[].type` | строка | | тип задачи JIRA (сборщик 1.10.0+) |
| `output.sprints[].members[].items[].lead` | число \| `null` | | Lead Time закрытой задачи, дней (сборщик 1.10.0+) |
| `output.sprints[].members[].items[].history[]` | массив | | смены статуса в границах спринта: `at`, `from`, `to`, `by` |
| `output.sprints[].members[].items[].history[].at` | момент до минуты | обяз. | |
| `output.sprints[].members[].items[].history[].from` / `.to` / `.by` | строка \| `null` | | |
| `output.sprints[].members[].items[].comments[]` | массив | | до пяти комментариев в границах спринта |
| `output.sprints[].members[].items[].comments[].at` | момент до минуты | обяз. | |
| `output.sprints[].members[].items[].comments[].by` | строка \| `null` | | |
| `output.sprints[].members[].items[].comments[].body` | строка ≤ 400 | обяз. | |

| `output.sprints[].members[].subtasks[].key` / `.title` / `.status` | строка | `key`, `status` обяз. | подзадача и статус на конец спринта |

Окно — с начала активного спринта (`logs.since`), `params.activity_days` задаёт его в днях явно.

| Поле | Тип | | Смысл |
|---|---|---|---|
| `logs.days` | целое ≥ 1 | обяз. | длина окна, дней |

| `logs.authors` | массив `[имя, число]` | обяз. | счётчики по авторам, по убыванию |

| `logs.events[].key` / `.title` | строка | обяз. | задача |

## Что кладут не сборщики
Эти поля в данных сборщика не появляются: их накладывает runner или навык поверх снимка, в хеш данных (`dataHash`) они не входят.

| Поле | Кто | Что |
|---|---|---|
| `notes` | runner из `notes` конфига | заметки прошлой версии страницы, переезжают в корзину |
| `insights` | runner из `reports/sprint-insights.json` (навык `sprint-insights`) | наблюдения и интерпретация ИИ, только при совпавшем `dataHash`; форма — `contract/insights.schema.json` |
| `business` | `business.py` из `reports/sprint-business.json` (навык `sprint-business`) | цели, KR, формулировки строк, риски, планы — только в презентации, только при совпавшем `dataHash`; форма — `sprint-business/contract/business.schema.json` |
