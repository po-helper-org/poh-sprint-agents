# Структура отчёта ФАКТ — форматы, колонки, грамматика

Эталон — `examples/ideal_sprint_report.md`. Визуал, к которому приводится
результат, — `docs/reference/sprint-report-deck-reference.md`. Здесь правила.

## Каркас документа

```markdown
# ФАКТ | {sprint}

**Период:** {даты} · **Ответственный:** {po_name} · **Статус:** закрыт · **Версия:** {n}
**План:** ПЛАН-{sprint}.md

## КОМАНДА: {название} — {перечень стримов одной строкой}

### СТРИМ: {название}

**Вердикт по Sprint Goal:** {достигнут | достигнут частично | не достигнут}
{обещали · показываем · чего не показываем}

| Задачи | Комментарий | Результат |

## Изменения в процессе спринта
| Затронутые задачи | Было → Стало | Результат |

## Демо
- {что показываем} — {кто, сколько минут}

## Метрики
### {заголовок карточки, до трёх слов}
![{подпись}]({путь к скриншоту})
{объяснение: что изменилось и почему}

## Итоги спринта
### Ключевые риски и блокеры
- **{имя блокера}** — {суть и срок}
### Переносим в {sprint+1}
- **{строка}** — {процент, причина}
```

Каждый блок = слайд. `## КОМАНДА:` даёт HERO-разделитель, `### СТРИМ:` — слайд
с таблицей. Одна команда → уровень `## КОМАНДА:` не нужен, стримы идут сразу.

**Порядок фиксирован**: команды и стримы, затем изменения, демо, метрики,
итоги. Итоги последним слайдом: колоду читают линейно и вслух.

Пустой блок не пишется. Обязательны: шапка, минимум один стрим, «Итоги
спринта» с «Ключевыми рисками».

## Стрим

Стрим = направление работ = OBJ-срез квартала = инициатива (решение О1). Один
уровень декомпозиции, не три. Название — как его знает бизнес, до трёх слов
(caveman, гейт 9).

Внеплановые работы и влёты — тоже стрим (`### СТРИМ: Внеплановые работы и
влёты`), тег уходит в префикс задачи: `[BUG] BE-1: …`. Отдельной колонки под
тег нет, колонок ровно три.

Sprint Goal у такого стрима нет по природе — гейт 4 его не требует.

## Колонка «Задачи»

`[РОЛЬ] {исполнитель}: {краткое действие}`. Роли — из `sprint_standards.md`
планировщика: `[BE]`, `[FE]`, `[SA]`, `[QA]`, `[RELEASE]`, `[DevOps]`, `[PO]`.
Теги внеплановых: `[BUG]`, `[TECH-DEBT]`, `[SPIKE]`, `[UNPLANNED]`, `[CARRYOVER]`.

Исполнитель — ролью из ростера (решение Д3): вклад виден, персональной оценки
нет.

## Колонка «Комментарий»

Маркированный список фактов, одна мысль — один пункт, затем **отдельная строка
следующего шага**:

```
- Переключено 100%, десять суток без сбоев
- **Причина:** у поставщика не отрисовались места без нумерации
След. шаг: правка конвертера, повторная выкатка в S9
```

- Разделитель пунктов — `<br>`, как в таблицах плана.
- Ярлык внутри пункта жирным, когда пункт отвечает на отдельный вопрос:
  `**Причина:**`, `**Блокатор:**`, `**Статус интеграции:**`.
- Ярлык следующего шага: `След. шаг:`, `Следующий спринт:`,
  `В следующем спринте:` — по горизонту.
- `**Причина:**` и строка следующего шага обязательны у строк < 100%
  (гейт 2). У `ACTIVITY` — нет: у фоновой работы нет незавершённости.

## Колонка «Результат»

`{значение} · {ступень}` — значение и ступень лестницы, из которой оно выведено
(`readiness_ladder.md`). На слайде видно только значение, ступень уходит в
подсказку ячейки: в эталоне её нет, но гейт 3 требует, чтобы вывод был.

| Значение | Смысл | Заливка строки |
|---|---|---|
| `100%` | закрыто | зелёная |
| `50–99%` | в работе, больше половины | жёлтая |
| `0–49%` | в работе, меньше половины | красная |
| `🛑 0%` | держит внешняя зависимость | красная |
| `🚫 0%` | сняли сами: переключили исполнителя, сменили приоритет | красная |
| `ACTIVITY` | фоновая работа без шкалы | без заливки, в счётчики не идёт |

Разница `🛑` и `🚫` не косметическая: первое — вопрос к смежникам, второе —
решение, которое команда объясняет сама.

Строки сортирует экспортёр — по убыванию результата, с подписью на слайде.
Порядок из плана не наследуется.

## Вердикт по Sprint Goal

Состояние одной строкой, доказательство следующей: **обещали** (Sprint Goal из
ПЛАН дословно) · **показываем** · **чего не показываем**. Состояние уходит в
подзаголовок слайда, доказательство — в подсказку.

«Поработали над» — не вердикт. Вердикт называет состояние и чем оно доказано.

## Симметрия план↔факт

Каждая строка ПЛАН даёт строку ФАКТ. Строка ПЛАН без строки ФАКТ — нарушение
гейта 1, даже если работа не начиналась: тогда `🚫 0%`, причина «не бралась»,
следующий шаг — перенос или снятие.

## Служебные блоки

**Метрики** — скриншот от PO плюс объяснение его словами: что изменилось и
почему. Агент не читает графики и не называет цифр, которых нет в тексте PO.
Файла ещё нет → экспортёр рисует место под него с ожидаемым путём.

**Итоги** — счётчики считает экспортёр по строкам всех стримов (решение Д1).
Руками их не проставлять: разойдутся с таблицами.

**Демо** — что показываем руками, кто показывает. Ссылки — только по вайтлисту
домен-профиля (гейт 5).
