# Гейты отчёта — валидация ФАКТ (9 бинарных гейтов)

Прогоняются в `/sprint-result` (стадия 1) и повторно в `/sr-revise` перед
записью. Каждый гейт бинарный: ✅ / 🔴 / 🟡.

## Светофор

| Статус | Условие | Действие |
|---|---|---|
| 🟢 Зелёный | Все 8 гейтов ✅ | запись после «ок PO» |
| 🟡 Жёлтый | Нарушены только гейты 6–9 | запись с явными `[УТОЧНИТЬ]`, PO принимает риск |
| 🔴 Красный | Нарушен хотя бы один гейт 1–5 | вернуться на ресинк, запись блокируется |

---

## Критичные гейты (1–5) — блокирующие

### Гейт 1: Трассировка
**Правило:** Каждая строка ФАКТ ← строка ПЛАН или стоит во «Внеплановых» с
тегом. И обратно: каждая строка ПЛАН имеет строку в ФАКТ.
**Нарушение:** строка-сирота (нет ни ПЛАН, ни тега) или потерянная строка ПЛАН.
Не начатая работа — не повод пропустить строку: `0%`, причина «не бралась».
> Cold-start (нет ПЛАН): трассировка проверяется против контекста ресинка,
> отсутствие плана фиксируется один раз в шапке. Не нарушение гейта.

### Гейт 2: Объяснимость
**Правило:** Строка с `Результат` < 100% (включая `заблокировано`) несёт
`Причина:` и `Следующий шаг:`.
**Нарушение:** незакрытая строка без причины или без следующего шага.
`ACTIVITY` — исключение: у фоновой работы нет незавершённости.

### Гейт 3: Вывод процента
**Правило:** У каждого процента названа ступень лестницы
(`readiness_ladder.md`), из которой он выведен.
**Нарушение:** процент без ступени; ступень, не соответствующая факту
(«в Production» при откате).

### Гейт 4: Вердикт
**Правило:** У каждой инициативы есть вердикт по Sprint Goal в три хода:
обещали · показываем · чего не показываем.
**Нарушение:** вердикта нет; вердикт-активность («поработали над»); вердикт
без доказательства («достигнут» и точка).

### Гейт 5: Чистота публикации
**Правило:** 0 паролей, токенов, ключей доступа; 0 внутренних URL вне
вайтлиста `publication.link_whitelist` домен-профиля; ФИО — только из ростера.
**Нарушение:** любое совпадение.
**Гейт 5 блокирует запись при любом решении PO, в том числе на 🟡.** Отчёт
уходит наверх и живёт в переписке: учётные данные из него не вынуть обратно.
Найдено — не переписывать в отчёт и сказать PO, что именно найдено и где.

## Некритичные гейты (6–9) — 🟡 допустимы

### Гейт 6: Читаемость
**Правило:** строк на стрим ≤ 6 — столько влезает в слайд 720px.
**Нарушение:** превышение → 🟡 с названием стрима. Экспортёр разрежет стрим на
«(продолжение)» механически, но **содержательный разрез — решение PO**
(решение Д2): агент предупреждает, сам стрим не делит.

### Гейт 7: Метрика с объяснением
**Правило:** каждый вложенный скриншот блока «Процессные метрики» несёт
объяснение текстом.
**Нарушение:** голая ссылка на дашборд; цифры, которых нет в словах PO.

### Гейт 8: Перенос назван
**Правило:** незакрытые строки перечислены поимённо в блоке «Переносим в
{sprint+1}», каждая с процентом и причиной.
**Нарушение:** «часть задач переносится» без перечисления.

### Гейт 9: Регистр текста
**Правило:** текст отчёта — caveman ultra + anti-slop
(`writing_register.md`): без стоп-слов, хеджей, интенсификаторов и
мета-комментариев; заголовок стрима до трёх слов; ячейка не длиннее слайда.
**Нарушение:** ненулевой код `sprint-report-style-lint.py`.
**🟡 на стадии сборки, 🔴 на `/sr-final`.** Черновик имеет право быть
многословным, отчёт, который уходит наверх, — нет. Правится текст, не порог
линтера.

## Валидаторы — прогон перед генерацией колоды

Два машинных прогона, оба обязательны **до** сборки `.html` и повторно **до**
финализации. Колода не собирается по документу, который их не прошёл: сборка
дорога только тем, что её показывают.

```
python3 .claude/skills/sprint-result/scripts/check_report_structure.py   ФАКТ-{sprint}.md
python3 .claude/skills/sprint-result/scripts/sprint-report-style-lint.py ФАКТ-{sprint}.md
```

| Валидатор | Гейты | Код возврата |
|---|---|---|
| `check_report_structure.py` | 2, 3, 4, 6 + структура блоков и колонок | 1 при 🔴, 0 при 🟡 |
| `sprint-report-style-lint.py` | 9 | 1 при любом совпадении |

Гейты 1, 5, 7 и качество вердикта — агентные: валидатор не знает содержимого
ПЛАН, вайтлиста домен-профиля и слов PO про метрику.

**Порядок на финализации:** структурный → стилевой → сборка колоды. Ненулевой
код любого из двух останавливает `/sr-final`, и правится документ, а не порог.
