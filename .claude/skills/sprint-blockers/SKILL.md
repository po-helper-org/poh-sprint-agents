# Навык: отчёт по блокерам команды

Отвечает на три вопроса PO: **кого команда ждала**, **где в процессе стояли задачи**, **какие случаи были самыми долгими** — за квартал и текущий месяц: квартал закончился — «июль–сентябрь» и «1–14 октября»; квартал идёт — «1 октября – 20 ноября» и «в т.ч. 1–20 ноября».

ИИ не источник данных. Задачи снимает и дни считает скрипт; ты раскладываешь готовые ожидания по сторонам и пишешь вывод. Каждое число на странице скрипт пересчитывает сам по датам; ключ задачи в твоём тексте должен быть в фактах — это проверяется.

## Стадии

Из корня проекта, где лежит `sprint-report.config.toml`. `--team <slug>` — слаг из конфига; квартал по умолчанию: в первый месяц квартала — прошлый (с хвостом), позже — текущий; другой — `--quarter 2026Q3`, другая дата отчёта — `--to YYYY-MM-DD`; `--now <момент>` — подпись времени сборки на странице (для воспроизводимости).

### 1. Снимок и факты

```bash
python3 .claude/skills/sprint-blockers/blockers.py fetch --team <slug>
python3 .claude/skills/sprint-blockers/blockers.py facts --team <slug>
```

`fetch` пишет снимок задач, `facts` печатает факты и кладёт их в `reports/blockers/<slug>-<квартал>.facts.json`. Ошибка про `params.blockers` или доступ к JIRA — команда не настроена: раздел «Настройка команды» ниже. Снимок свежий (тот же день) — `fetch` можно не повторять.

В фактах:
- `waits` — **ожидания**: задача, стадия (`hold` — приостановлена; `review` / `test` / `deploy` — стояла в очереди не меньше `rules.queueMinDays` рабочих дней), даты, рабочие дни по окнам (только внутри периода), `bulkEnd` — ожидание кончилось в день массового закрытия (разбор бэклога), `evidence` — комментарии рядом с интервалом, ближайший к началу — первым (свои и родителя, `on`), и связи «is blocked by / depends on / to be done after».
- `stages` — сколько дней в каждой стадии стояла хотя бы одна задача: это узкие места процесса, их скрипт выводит сам.
- `signals` — комментарии «ждём / нет доступа» без статуса ожидания: в таблицы не идут, на странице — строкой в ограничениях.

### 2. Разложить ожидания — `reports/blockers/<slug>-<квартал>.json`

Форма — `contract/blockers.schema.json`:

```json
{
  "version": 1,
  "factsHash": "<из фактов, без изменений>",
  "lead": ["Абзац: где и почему команда теряла время, главное узкое место."],
  "sections": {"sides": "…", "stages": "…", "cases": "…"},
  "sides": [{"id": "dba", "name": "Команда БД", "what": "Справочников, баз и прав доступа"},
            {"id": "review", "name": "Ревью своей команды", "what": "Проверки готового кода", "internal": true}],
  "cases": [{"waits": ["w3", "w7"], "side": "dba", "what": "Не заполнен справочник на тестовом стенде",
             "evidence": "strong", "basis": "«Ожидает задач OTHER-12» — комментарий 07.09"}],
  "notBlockers": [{"waits": ["w5"], "why": "пауза по приоритету, внешней зависимости нет"}]
}
```

Готово, когда **каждое** ожидание из `waits` стоит ровно в одном месте: в случае (`cases`) или в `notBlockers` с причиной.

- **Случай** — одно ожидание одной стороны. Если несколько задач (часто история и её подзадачи) ждали одно и то же — один случай, все их `waits` в нём; дни скрипт посчитает объединением.
- **Сторона** — кого ждали, по названию команды или роли, без ФИО: «Команда БД», «DevOps», «Партнёр», «Команда сайта (PHP)», «Архитекторы», «Ревью своей команды», «Приёмка своей команды», «Решение своего PO». `internal: true` — своя команда: узкое место внутри, а не внешняя зависимость. Сторону определяй по основанию: проект ключа в связи (другая команда), слова комментария («нет доступа» → администраторы, «ждём ревью» → ревью), автор комментария, название подзадачи («получить инструкцию от партнёра»). Кого ждали — не видно (ждали человека без роли, приостановили без комментария): сторона «Сторона не названа» с `unknown: true`, `evidence: weak` — она не попадает ни в «свою команду», ни в «другие команды». `what` стороны — чего от неё ждали, обобщённо по её случаям.
- **Основание** (`basis`) — короткая цитата комментария, связь или название задачи, по которым видно, кого ждали. `evidence: strong` — сторона названа прямо: в комментарии, в связи задачи или её родителя (`from` в `links`), в названии задачи; `weak` — выведена по косвенным признакам. Ожидание в очереди без единого комментария — `weak` и сторона по стадии («Ревью своей команды», «Тестирование своей команды»).
- `workaround: true` — случай закрыли обходом, а не дождались (так сказано в комментарии).
- **Ждали кого-то из своих** — тоже случай, со стороной `internal: true`: решения своего PO, исправления своего бага, своего аналитика, соседней подзадачи той же истории. Время потеряно, и это узкое место внутри команды.
- **Никого не ждали** → `notBlockers` с причиной:
  - пауза по приоритету, отпуск исполнителя, задача отменена;
  - припарковано: стоит «в ожидании» с начала квартала или раньше, и ни в комментариях, ни в связях нет того, кого ждут (приостановка без основания, начатая внутри квартала, — случай со стороной «Сторона не названа»);
  - забытая пауза: то, чего ждали, закрыто до начала квартала, а статус не сняли;
  - `bulkEnd` у очереди без комментариев: задачу закрыли разбором бэклога, а не дождались.
- `lead` и `sections` — в последнюю очередь: разложи случаи, запусти `blockers.py check --team <slug>` — он напечатает таблицы страницы (дни сторон и случаев), — и пиши вывод по этим числам.
- `lead` — 1–3 абзаца до 450 знаков: кто забрал больше всего дней, где стоит больше всего сейчас, что держат открытые случаи. Числа — из таблиц `check` и фактов; «дни ожидания» стороны — сумма длительностей её случаев, «дней из N» — дни, когда её ждала хотя бы одна задача. `sections` — одна фраза-вывод под заголовком раздела, до 220 знаков.

### 3. Проверить и собрать страницу

```bash
python3 .claude/skills/sprint-blockers/blockers.py apply --team <slug>
```

`✗` — поправь файл и запусти снова: неразобранное ожидание, чужой ключ задачи, сторона без описания, `factsHash` не совпал (снимок пересобран — начни со стадии 1). `⚠ числа N нет` — замени на число из фактов или таблиц, либо убери.

### 4. Ответ в чат

Одна строка: команда, квартал, сколько случаев и открытых, путь к странице из вывода `apply`. Содержимое страницы в чат не пересказывай.

## Настройка команды (один раз)

В `sprint-report.config.toml` у команды — таблица `[teams.params.blockers]`:

```toml
[teams.params.blockers]
jql = "project = KEY"              # какие задачи — задачи команды; нет — спринты доски команды за период
mcp = ["mcp-atlassian"]            # MCP-сервер Atlassian по stdio; нет — REST с токеном из jira.token_env
skip = ["UAT"]                    # статусы, которые не считать; по умолчанию — установка и UAT (закрывают пачками)
# hold / review / test / deploy = [...]  — свои имена статусов стадии (в истории JIRA бывают английские)
# queue_min_days = 5   holidays = ["2026-11-04"]   utc_offset = "+03:00"
```

Имена статусов по умолчанию и правила счёта дней — в начале `waits.py`. Статус команды не попал ни в одну стадию — задача в нём не считается ожидающей: добавь его в нужный список.

PO-агент Hermes: `bash .claude/skills/sprint-blockers/hermes/install.sh <профиль> <slug> <имя команды> <рабочий каталог>` — ставит в профиль навык-обёртку (страница уходит в чат вложением `MEDIA:`).
