# Навык: статус спринта в PDF

## Роль
Ты передаёшь готовый файл. PDF целиком собирает `status.py`: ты не пересчитываешь цифры, не пересказываешь лист текстом, не добавляешь от себя выводы, оценки и эмодзи. Форма каждый раз одна и та же — ради этого навык и существует.

## Принцип: ИИ не источник данных
Цифры берутся из снимка `reports/sprint-report.data.json`, который пишет runner `actual-sprint` вместе с HTML-страницей. Ты не ходишь в трекер ни через MCP, ни запросами, не дополняешь отчёт по памяти и по прошлым разговорам. Нет снимка или конфига — отчёта нет, есть следующий шаг для человека.

## Стадии

### 1. Запустить скрипт
Из корня проекта, где лежит `sprint-report.config.toml`:

```bash
python3 .claude/skills/sprint-status/status.py --refresh
```

- `--refresh` — сначала собрать свежие данные runner'ом (нужны VPN и токен). Если сбор не удался, PDF всё равно соберётся из последнего снимка, а первой строкой вывода будет `⚠ Свежий сбор не удался: …`.
- Без `--refresh` — за секунды, из последнего снимка, без обращения к трекеру. Так отвечай, если человек только что собирал `/actual-sprint`.
- `--team <slug>` — одна команда. Слаг берётся из конфига; не угадывай.

### 2. Отдать stdout как есть
stdout — это готовое сообщение: подпись в одну строку (плюс строка `⚠`, если есть) и `MEDIA:<путь к PDF>`. По метке `MEDIA:` Hermes отправляет файл вложением. Передай stdout без изменений: не оборачивай в блок кода, не переписывай путь, не добавляй пересказ содержимого. Лог runner'а и печати идёт в stderr — его в чат не переносишь.

Если вывод начинается с `⚠` или `Статус спринта не собран:` — добавь одну строку со следующим шагом по таблице ниже.

### 3. STOP
Вопросы по листу («почему отстаём», «что с INIT-132») — отдельный разговор. Детали лежат на HTML-странице `/actual-sprint`; предложи её, а не выдумывай.

## Что на листе (порядок фиксирован)

| Блок | Откуда |
|---|---|
| Шапка: команда · спринт, рабочий день N из M, срок | `burndown`: дни без выходных. «Срок истёк» — дата прошла, а спринт в JIRA активен |
| Готово X / Y | `burndown` на сегодня: задачи спринта с подзадачами |
| Темп | остаток минус идеальная прямая (та же, что на графике страницы) |
| За сутки | разница `burndown` сегодня и вчера: закрыто, изменение объёма |
| Блокеры · Без движения · Зона риска | иерархия эпиков: бакет «Заблокировано»; в работе без смены статуса > 3 дней; `control.*.risks` только по задачам этого спринта |
| Burndown | остаток по дням и идеальный темп, выходные фоном |
| Статусы | шесть бакетов по всем задачам спринта (`velocity.split`) |
| Внимание | блокеры → без движения → зона риска, без повторов; до 6 строк, остальное числом |
| Эпики | готово/всего по иерархии эпика, полоса статусов, число блокеров |
| Подвал | когда собраны данные; старше 12 ч → пометка ⚠ |

Несколько команд — первым идёт сводный лист: таблица команд и по четыре самых острых задачи каждой.

## Когда отчёт не собрался

| Что в выводе | Что делать человеку |
|---|---|
| `Статус спринта не собран: конфиг … не найден` | `/sprint-setup` |
| `Статус спринта не собран: снимка данных нет` | собрать отчёт: `/actual-sprint` или `status.py --refresh` |
| `Статус спринта не собран: PDF не собран: нет Chrome/Chromium` | поставить Chrome или указать путь в `SPRINT_STATUS_CHROME` |
| `⚠ Свежий сбор не удался: JIRA недоступна…` | проверить VPN и `JIRA_PERSONAL_TOKEN` |
| `⚠ Свежий сбор не удался: … не проверен` / `изменён после проверки` | `/collector-validate <slug>` |
| `⚠ Данные старше N ч` | запустить с `--refresh` |

Подробный разбор отказов runner'а — `docs/actual-sprint-debug.md`.

## По расписанию (Hermes Agent)
Надёжнее всего — cron без модели: Hermes берёт stdout скрипта, по метке `MEDIA:` прикладывает PDF и отправляет в чат.

```bash
cp .claude/skills/sprint-status/hermes/sprint-status.sh "$HERMES_HOME/scripts/"
hermes cron create "45 9 * * 1-5" --no-agent --script sprint-status.sh \
  --name sprint-status --deliver telegram
```

Каталог проекта для скрипта — переменная `SPRINT_REPORT_PROJECT`. Пошагово и вариант с агентом — `docs/sprint-status-guide.md`.

## Границы
Только чтение: снимок и (с `--refresh`) runner `actual-sprint`, который сам читает JIRA. Пишет только в `reports/`: `sprint-status-<дата>.pdf` и `.html` рядом. Никаких записей в трекер. Навык не строит план дня и не читает чаты — это `/morning`.
