# Навык: статус спринта в чат

## Роль
Ты передаёшь готовый отчёт. Текст отчёта целиком собирает `status.py`: ты не пересчитываешь цифры, не переставляешь блоки, не добавляешь от себя выводы, оценки и эмодзи. Каждый раз форма одна и та же — ради этого навык и существует.

## Принцип: ИИ не источник данных
Цифры берутся из снимка `reports/sprint-report.data.json`, который пишет runner `actual-sprint` вместе с HTML-страницей. Ты не ходишь в трекер ни через MCP, ни запросами, не дополняешь отчёт по памяти и по прошлым разговорам. Нет снимка или конфига — отчёта нет, есть следующий шаг для человека.

## Стадии

### 1. Запустить скрипт
Из корня проекта, где лежит `sprint-report.config.toml`:

```bash
python3 .claude/skills/sprint-status/status.py --refresh
```

- `--refresh` — сначала собрать свежие данные runner'ом (нужны VPN и токен). Если сбор не удался, скрипт всё равно напечатает последний снимок, а первой строкой — `⚠ Свежий сбор не удался: …`.
- Без `--refresh` — мгновенно, из последнего снимка, без обращения к трекеру. Так отвечай, если человек только что собирал `/actual-sprint`.
- `--team <slug>` — одна команда. Слаг берётся из конфига; не угадывай.

### 2. Отдать stdout как есть
Весь stdout — это и есть ответ: одним сообщением, без обёртки в блок кода, без вступления и без приписок. Лог runner'а идёт в stderr — его в чат не переносишь.

Если первая строка начинается с `⚠` или `Статус спринта не собран:` — после отчёта одной строкой назови следующий шаг по таблице ниже.

### 3. STOP
Вопросы по отчёту («почему отстаём», «что с INIT-132») — отдельный разговор. Детали лежат на HTML-странице `/actual-sprint`; предложи её, а не выдумывай.

## Что в отчёте (порядок фиксирован)

| Строка | Откуда |
|---|---|
| Команда · спринт — рабочий день N из M, дата окончания | `burndown`: дни без выходных |
| Готово X из Y · отставание/опережение от идеального темпа | `burndown` на сегодня против той же идеальной прямой, что на графике страницы |
| За сутки: закрыто, изменение объёма | разница `burndown` сегодня и вчера |
| Статусы: 6 бакетов | последний спринт `velocity.split` — все задачи спринта с подзадачами |
| Внимание: блокеры и задачи без движения > 3 дней | иерархия эпиков, возраст статуса как на странице; не больше 5 строк, остальное числом |
| Зона риска | `control.*.risks`: в работе дольше медианы Cycle Time |
| Эпики (готово/всего) | иерархия эпиков: истории + подзадачи |
| Данные JIRA на … | `_meta.collectedAt`; старше 12 ч → пометка ⚠ |

## Когда отчёт не собрался

| Что в выводе | Что делать человеку |
|---|---|
| `Статус спринта не собран: конфиг … не найден` | `/sprint-setup` |
| `Статус спринта не собран: снимка данных нет` | собрать отчёт: `/actual-sprint` или `status.py --refresh` |
| `⚠ Свежий сбор не удался: JIRA недоступна…` | проверить VPN и `JIRA_PERSONAL_TOKEN` |
| `⚠ Свежий сбор не удался: … не проверен` | `/collector-validate <slug>` |
| `⚠ Данные JIRA на … — старше N ч` | запустить с `--refresh` |

Подробный разбор отказов runner'а — `docs/actual-sprint-debug.md`.

## По расписанию (Hermes Agent)
Надёжнее всего — cron без модели: Hermes отправляет stdout скрипта в чат дословно.

```bash
cp .claude/skills/sprint-status/hermes/sprint-status.sh "$HERMES_HOME/scripts/"
hermes cron create "45 9 * * 1-5" --no-agent --script sprint-status.sh \
  --name sprint-status --deliver telegram
```

Каталог проекта для скрипта — переменная `SPRINT_REPORT_PROJECT`. Пошагово и вариант с агентом — `docs/sprint-status-guide.md`.

## Границы
Только чтение: снимок и (с `--refresh`) runner `actual-sprint`, который сам читает JIRA. Никаких записей в трекер. Навык не строит план дня и не читает чаты — это `/morning`; он может взять этот текст как блок «Спринт».
