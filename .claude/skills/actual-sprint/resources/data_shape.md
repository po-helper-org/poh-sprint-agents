# Форма данных для шаблона

`resources/report_template.html` рендерит таблицу из одного JS-массива `STORIES`. Заполняй его целиком (не трогай остальной JS/CSS шаблона) — каждый элемент:

```js
{
  rowId: "GDSLV-1919",          // уникален на СТРОКУ отчёта, не на issue (см. ниже про split)
  epicKey: "GDSLV-1737",         // null, если эпика нет
  epicTitle: "AI Harness (Bartello)", // "—" не пиши сюда — шаблон сам подставит при epicKey=null
  key: "GDSLV-1919",             // issue key истории — ссылка и заголовок сайдбара строятся от него
  title: "Harness DevAgent",     // summary истории (можно сократить до «краткого названия», если попросили)
  subtasks: [
    { key: "GDSLV-1881", summary: "[FAQ] Direct: новый таб FAQ на страницах", status: "Ревью", category: "В работе" }
    // status — то что показываем текстом; category — statusCategory.name для цвета бейджа
  ]
}
```

## Разбитые строки (одна История = несколько строк отчёта)
Если PO просит показать одну Историю несколькими строками (например MVP отдельно, свод FAQ-подзадач отдельно) — `key` у обеих строк одинаковый (ссылка и заголовок сайдбара по-прежнему ведут на реальный issue), а `rowId` разный (`"GDSLV-1870-mvp"`, `"GDSLV-1870-faq"`) — иначе их заметки «Прогресс» будут затирать друг друга в localStorage.

## title vs summary
По умолчанию `title` = summary истории как есть из JIRA. Если пользователь просит «краткое название» — сократи сам, не выдумывая новый смысл, оставь узнаваемым по исходному summary.

## Категории статусов → бейдж
| statusCategory.name (JIRA) | css-класс в шаблоне |
|---|---|
| Выполнено | done |
| В работе  | progress |
| всё остальное (К выполнению и т.п.) | backlog |
