# Маппинг статусов JIRA → 6 бакетов

Полный список статусов на корпоративном инстансе (`GET /rest/api/2/status`) — ~330 уникальных пар «имя + категория», свой workflow в каждом проекте. Статичная таблица «имя статуса → бакет» нежизнеспособна. Вместо неё — детерминированная эвристика (`classifyBucket` в `report_template.html`), применяемая в момент рендера, а не заранее посчитанное поле в данных.

## 6 целевых бакетов
`Открыто` · `Заблокировано` · `В работе` · `Тестирование` · `Ревью` · `Готово`

## Правило (порядок проверок критичен)
1. `statusCategory === 'Выполнено'` → **Готово**. Категория JIRA — единственный широкий признак готовности.
2. Точное совпадение имени со списком `DONE_EXACT` (`закрыт`, `готово`, `выполнено`, `отменена`, `решён`, …) → **Готово**. Только полное совпадение строки, не подстрока.
3. `блок|ожида|пауза|hold|wait|отложен|приостановл` → **Заблокировано**.
4. `тест|qa` → **Тестирование**.
5. `ревью|review|проверк|приемк|приёмк|согласован|утвержд` → **Ревью**.
6. Дефолт: `statusCategory === 'К выполнению'` → **Открыто**; всё остальное → **В работе**.

## Почему «Готово» не ищется подстрокой
Регрессия по всем 330 статусам поймала ложные срабатывания подстрочного поиска:

| Статус | Категория | Подстрока ловила | Реально |
|---|---|---|---|
| Ожидает решения КЦ | В работе | `решен` → Готово | Заблокировано |
| Аналитика завершена | В работе | `заверш` → Готово | В работе |
| Готово к закрытию | В работе | `закрыт` → Готово | В работе |
| Валидация решения | В работе | `решен` → Готово | В работе |
| Временное решение | В работе | `решен` → Готово | В работе |

Поэтому done-по-имени — только точное совпадение целой строки. Проверка блокировок идёт раньше остальных: «Ожидает тестирование» — это очередь, не тесты.

## Агрегация
Считается по ВСЕЙ иерархии эпика: каждая История эпика + каждая её Подзадача = отдельная единица подсчёта. Историю с подзадачами НЕ сворачивать в один статус. Итог в строке отчёта — 6 чисел в порядке бакетов выше + «из N» (N = истории + подзадачи).

## Когда не трогать эвристику
Если PO говорит «у нас статус X на самом деле означает Y» — это разовая договорённость по конкретному отчёту, фиксируй в диалоге, а не переписывай общий классификатор. Нестандартные статусы вне словаря падают в дефолт по категории — осознанный fallback, не ошибка.
