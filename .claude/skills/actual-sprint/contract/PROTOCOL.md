# Протокол сборщика данных (версия 1)

Сборщик — отдельная программа на любом языке. Runner знает о ней ровно три вещи: как запустить, что подать на stdin и как прочитать stdout. Больше никакой связи нет: runner не импортирует код сборщика, сборщик не знает про HTML.

Граница нужна затем, чтобы правила команды (какие типы задач считать историями, как называются статусы, через какое поле связан эпик) жили в коде сборщика, а не в модели и не в плагине. **ИИ пишет и проверяет сборщик, но никогда сам не собирает данные отчёта.**

## Запуск

```
<cmd...>            # из cwd, если он задан в конфиге
stdin  ← один JSON-объект запроса
stdout → один JSON-объект команды по contract/team.schema.json
stderr → логи и прогресс в свободной форме
```

Runner убивает процесс по `timeout` (по умолчанию 300 с) и считает это ошибкой.

## Запрос (stdin)

```json
{"protocol": 1,
 "team": {"slug": "team-b", "name": "Команда B", "board": 202},
 "params": {"boards_extra": [203]},
 "jira": {"url": "https://jira.example.com", "caBundle": "/abs/path/corp-ca.pem"},
 "now": "2026-09-28T09:00:00+07:00"}
```

| Поле | Смысл |
|---|---|
| `protocol` | версия протокола. Сборщик, который её не поддерживает, выходит с кодом `2`. |
| `team.slug` | идентификатор команды; он же `slug` в выходе и `REPORT_ID` заметок. |
| `team.name` | отображаемое название; попадает в выход как `team`. |
| `team.board` | id agile-доски; попадает в выход как `boardId`. |
| `params` | произвольный объект из конфига. Runner передаёт его как есть, не интерпретируя. |
| `jira.url` | база инстанса без хвостового слеша. |
| `jira.caBundle` | абсолютный путь к CA-бандлу или `null`. Проверку сертификата отключать нельзя. |
| `now` | текущее время. **Единственный источник «сейчас».** |

Кроме своего окружения runner добавляет сборщику `ACTUAL_SPRINT_CONTRACT` — путь к каталогу контракта. Оттуда сборщик берёт `status_rules.json` (правила бакетов) и, если он на Python, `buckets.py` с их реализацией.

Токена во входном JSON нет **никогда**. Он приходит только через переменную окружения — `JIRA_PERSONAL_TOKEN` или ту, что задана в `token_env` конфига. Runner передаёт сборщику своё окружение, так что переменная видна как есть.

### Почему время приходит извне

Сборщик, который смотрит на системные часы, невоспроизводим: burndown, окна активности и «зона риска» зависят от момента запуска. С `now` во входе прогон на записанных ответах JIRA даёт тот же результат через месяц (НФТ-1).

## Ответ (stdout)

Ровно один JSON-объект команды по [`team.schema.json`](team.schema.json). Ничего кроме него: ни прогресса, ни предупреждений, ни пустой строки перед.

Обязательное поле `_meta` — паспорт сбора:

```json
{"collector": "team-b", "version": "1.2.0", "protocol": 1,
 "collectedAt": "2026-09-28T09:00:00+07:00", "requests": 14, "durationMs": 6800,
 "warnings": ["3 истории без эпика → псевдо-эпик «Без эпика»"]}
```

`collectedAt` — это `now` из запроса, а не время окончания работы. `warnings` — то, что человек должен увидеть: статус вне правил бакетов, задачи без эпика, обрезанная выборка. Runner показывает их в сводке и кладёт в подвал страницы.

Поле `notes` сборщик не заполняет: заметки прошлого запуска подставляет runner.

## Коды выхода

| Код | Значение | Что делает runner |
|---|---|---|
| `0` | успех | принимает результат |
| `2` | ошибка конфигурации или `params` | «проверьте конфиг» |
| `3` | JIRA недоступна или не авторизует | «проверьте VPN/токен», без повторов и обходных путей |
| `1` | любая другая ошибка | показывает stderr |

Код `3` отдельно от `1` затем, чтобы `/actual-sprint` мог сказать человеку про VPN и токен вместо того, чтобы предлагать починить код.

## Обязанности сборщика

1. **Только чтение.** Ни одного запроса, меняющего состояние JIRA, ни в одном режиме.
2. **Проверка TLS включена.** Корпоративный CA подключается через `jira.caBundle`. Отключение проверки (`CERT_NONE`, `InsecureSkipVerify` и аналоги) запрещено.
3. **Токен не утекает.** Ни в stdout, ни в stderr, ни в record-дампы.
4. **Детерминизм.** Время — только из `now`. Ключи объектов отсортированы, порядок массивов стабилен: одинаковый вход даёт побайтово одинаковый stdout.
5. **Пакетные запросы.** Никакого запроса на каждую задачу. Их число — в `_meta.requests`.

## Режимы записи и воспроизведения

Необязательные, но на них строятся тесты и сверка после правки скрипта:

```
--record <dir>    сохранить сырые ответы JIRA (без заголовков авторизации)
--replay <dir>    работать из них, без сети
```

Ключ файла — детерминированный хеш от метода, пути и параметров запроса. `--replay` не должен уметь выходить в сеть: отсутствующий ответ — ошибка, а не поход в JIRA.

Базовый сборщик понимает те же режимы как `params.record` и `params.replay`: так прогон на фикстурах включается из конфига, без правки строки запуска. Путь считается от `cwd` сборщика.

## Версионирование

`protocol: 1`. Несовместимые изменения формы запроса или выхода увеличивают номер; runner отказывается работать со сборщиком другой версии и называет её.
