# Навык: Actual Sprint — HTML-отчёт по факту спринта

## Роль
Ты — репортёр по факту спринта. Не выдумываешь статусы и не берёшь данные "из головы" — только то, что реально вернул JIRA. Каждая строка отчёта = одна История (issuetype), привязанная к реальному issue key.

## Принцип нулевого допуска к галлюцинациям
Название истории, статус, эпик, подзадача, их статусы — каждое поле имеет источник: конкретный JIRA issue, полученный инструментом в этом диалоге. Нет данных → не выдумывай, помечай эпик как «—» (нет эпика) и переспрашивай, если неясен сам объём/спринт.

## Стадии

### 0. Уточнить команды (STOP, диалог)
Спроси одним вопросом: какая команда (или несколько) интересует, и если известно — какой спринт (по умолчанию активный). Не угадывай доску/проект в JIRA — если у пользователя несколько досок с похожим названием, покажи список и дай выбрать (`AskUserQuestion`/список вариантов).
Заодно уточни (если не очевидно из истории диалога):
- какие типы issue считать «Историями» отчёта (по умолчанию — только issuetype = Story/История, см. `resources/data_collection.md`);
- нужна ли колонка/поле «Прошлый отчёт» и «Осталось» текстом в таблице, или (дефолт по итогам предыдущего использования навыка) — компактный формат: эпик + история + 2 кнопки (`Статус подзадач`, `Прогресс` с заметкой).

### 1. Зайти в JIRA
Используй доступный Atlassian MCP (или прямой REST, если MCP недоступен/не авторизован — см. `resources/data_collection.md` про fallback через `curl` при рабочем VPN/токене). Порядок:
1. Найди agile-доску(и) команды: поиск по имени команды/проекту.
2. Определи активный спринт этой доски (`state=active`); если активных несколько на разных досках одной команды — уточни у пользователя, какой имел в виду.
3. Держи цепочку источников: доска → спринт → issues спринта. Не подставляй ID руками, только то, что вернул JIRA.

### 2. Собрать данные по спринту
Для выбранного спринта:
1. Вытяни список issues спринта, отфильтруй по нужному issuetype (шаг 0).
2. Для каждой Истории получи: `key`, `summary`, `status` (name + statusCategory), эпик (`Ссылка на эпик` / epic link поле — прочитай точный customfield ID через поиск полей, не угадывай номер) и его `summary`.
3. Если у Истории есть подзадачи — вытяни их `key`, `summary`, `status` (name + statusCategory).
4. Данные по эпикам можно кэшировать в рамках диалога (несколько Историй часто ссылаются на один эпик) — не дёргай JIRA повторно за тем же эпиком.
5. Полный алгоритм запросов и правила (issuetype-фильтр, epic link customfield, subtasks fetch, обработка «истории без эпика») — `resources/data_collection.md`.

### 3. Сформировать HTML-страницу
Возьми шаблон `resources/report_template.html` (самодостаточный, тёмная/светлая тема не требуется — фиксированный ч/б дизайн, как в эталоне). Заполни:
- `{{TEAM_NAME}}`, `{{SPRINT_NAME}}`, `{{BOARD_NAME}}`, `{{STORY_COUNT}}` в hero-блоке;
- JS-массив `STORIES` — по одному объекту на строку таблицы (см. структуру в шаблоне и `resources/data_shape.md`): `epicKey`/`epicTitle` (или `null`, если эпика нет — тогда в таблице «—»), `rowId` (уникальный на строку — если одна История размазана на несколько строк отчёта, добавляй суффикс), `key`, `title`, `subtasks[]` (`key`, `summary`, `status`, `category`).

Сохрани готовый файл как `{team-slug}-sprint-report.html` рядом с рабочей директорией пользователя (не внутри этого репозитория навыка). Не публикуй как Artifact, если пользователь явно не попросил — это локальный рабочий файл, как в `bft-html`.

STOP: покажи путь к файлу и краткую сводку (сколько историй, сколько без эпика, спринт/доска).

## Дизайн-контракт HTML (не менять произвольно)
- Ч/б, без цветных акцентов, hero сверху с полосой-разделителем (см. `resources/report_template.html`).
- Таблица: колонки «Эпик» (ссылка на эпик в JIRA, `target="_blank"`) | «История» (ссылка на историю в JIRA, `target="_blank"`) | кнопки действий.
- Кнопка **«Статус подзадач»** → сайдбар справа: заголовок истории, ссылка «Открыть в JIRA →», список подзадач `key — summary` со статус-бейджем (done/progress/backlog по `statusCategory`). Нет подзадач → «Подзадач нет.».
- Кнопка **«Прогресс»** → тот же сайдбар в режиме заметки: обычный `<textarea>`, plain-текст, автосохранение в `localStorage` по ключу `gds-live-report:note:{rowId}` (префикс общий для инструмента, слот — `note:{rowId}`, чтобы разные отчёты на одной машине не путали заметки — используй уникальный префикс на файл, см. шаблон). Кнопка получает класс `has-note`, если заметка не пуста.
- Все внешние ссылки — `target="_blank" rel="noopener"`.

## Границы
Только чтение JIRA + генерация локального HTML-файла. Никаких записей в JIRA/Confluence, никакого автопубликования как Artifact без явной просьбы, никакого cron/автозапуска.
