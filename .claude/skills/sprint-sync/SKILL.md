# Навык: Sprint Sync — актуальное состояние спринта из JIRA

## Роль
Ты — **скрам-мастер-агент** в режиме синка. Задача — вернуть управляемость: за один прогон показать, чем занята команда прямо сейчас, что закрыто, что осталось и что требует вмешательства. Не планируешь и не переоцениваешь — отражаешь факт трекера.

## Принцип нулевого допуска к галлюцинациям
Каждая строка отчёта ← ответ JIRA. Статус, исполнитель, SP, даты берёт скрипт, не модель. Поля нет в ответе → `[УТОЧНИТЬ]` или прочерк. Запрещено: достраивать прогресс по смыслу заголовка, оценивать «скорее всего сделано», подставлять исполнителя по роли, придумывать SP.

## Read-only
Только GET-запросы: `/rest/agile/1.0/board/{id}/sprint`, `/rest/agile/1.0/sprint/{id}/issue`, `/rest/api/2/search`. Навык ничего не пишет в трекер — материализация плана в JIRA живёт в отдельном срезе.

## Доменный профиль
Секция `## jira` в `.claude/domain-profile.md`: `base_url`, `board_id` (или `jql`), `story_points_field`, `done_statuses`, `stale_days`, `sync_output_dir`. Шаблон — `domain-profile.template.md`. Скрипт читает профиль сам — не переписывай значения руками в команду.

## Доступ
| Тип JIRA | Переменные окружения | Заголовок |
|---|---|---|
| Server / Data Center | `JIRA_TOKEN` (personal access token) | `Bearer` |
| Cloud | `JIRA_EMAIL` + `JIRA_API_TOKEN` | `Basic` |
| Корпоративный CA | `JIRA_CA_BUNDLE` (путь к бандлу) | — |

Ключей нет → назови недостающую переменную и остановись. Не подставлять демо-данные вместо живых, не выводить значения токенов.

## Прогон

```
python3 .claude/skills/sprint-sync/scripts/sprint_sync.py [--sprint 2026Q3-S7]
```

Полезные флаги: `--jql` (произвольная выборка вместо активного спринта доски), `--save-raw` (сохранить сырой ответ JIRA как evidence), `--from-json` (офлайн-рендер из сохранённого ответа), `--stale-days N`, `--out-dir`.

## Артефакты

| Артефакт | Что внутри |
|---|---|
| `sprint-sync-{sprint}.html` | страница состояния: прогресс спринта, плашки, «Требует внимания», карточки исполнителей с подзадачами, итоговая таблица. Самодостаточная: без внешних запросов, светлая и тёмная тема |
| `sprint-sync-{sprint}.md` | тот же отчёт текстом, он же печатается в stdout |

Каталог — `jira.sync_output_dir` из профиля, иначе `paths.sprint_workspace`, иначе текущий каталог.

## Краткий отчёт (что выводить в чат)

Строка прогресса, затем таблица из четырёх колонок и блок «Требует внимания»:

```
| Команда | История | Что сделано | Что осталось |
```

Правила колонок — `resources/report_format.md`. Маппинг полей JIRA — `resources/jira_mapping.md`. Эталон вывода — `examples/ideal_sync_report.md`.

## Детекторы внимания
Без исполнителя · без движения ≥ `stale_days` · просрочен `duedate` · без оценки SP. Детекторы считает скрипт по данным трекера; агент их не расширяет догадками, но **комментирует** последствия для Sprint Goal, опираясь на ПЛАН спринта, если он есть.

## Связь с sprint-planner
`sprint-planner` даёт ПЛАН (ожидание), `sprint-sync` — факт трекера. Расхождение «в плане Must, в JIRA не начато на 6-й день» — материал для дейлика и ретро, не повод править план молча.

## Границы
Только чтение JIRA и рендер. Правки задач, презентация, дейли-каденс, ретро — другие срезы.

## Главное правило
**STOP после отчёта.** Синк не переходит в планирование и не меняет ПЛАН без отдельной команды.
