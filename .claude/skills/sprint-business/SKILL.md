# Навык: бизнес-отчёт «ФАКТ | спринт»

## Два отчёта — одни данные
- **Отчёт PO** (`/actual-sprint`, `reports/sprint-report.html`) — для синхронизации с техлидами: эпики, статусы задач, сводный отчёт, интерпретация ИИ. На нём кнопка «Бизнес-отчёт» даёт промт на этот навык.
- **Бизнес-отчёт** (этот навык, `reports/sprint-business.html`) — для управляющего комитета, PO смежных департаментов и бизнес-заказчиков: продвижение за спринт от целей. На нём кнопка «Для техлидов» даёт промт на отчёт PO.

Данные у них общие и собираются одинаково: сборщики команд → runner `actual-sprint` → снимок `reports/sprint-report.data.json`. Ты не источник данных: не ходишь в трекер, не пересчитываешь метрики, не берёшь цифры из памяти. Страница, шаблон и генерация — свои: `business.py` и `resources/business_template.html` (движок страницы общий с отчётом PO — `actual-sprint/resources/shared`).

## Откуда цифры на слайдах
Каждый слайд рисует код страницы из полей JSON команды — детерминированно: «сегодня» колоды — момент сбора (`_meta.collectedAt`), поэтому презентация, открытая через неделю, показывает тот же снимок. От модели на слайдах только тексты бизнес-блока, и они прикладываются, только если `dataHash` совпал.

| Слайд | Поля данных (подробно — `sprint-data/reference/render.md`) |
|---|---|
| титул, слайд команды | `epics[].stories[]`, `burndown.days[]`, SP — `output` |
| слайды целей (строка = эпик) | `epics[].stories[]` с подзадачами и `statusChanged`; цели, KR, сводки — бизнес-блок |
| клик по строке | истории спринта эпика; «Весь эпик» — `epics[].scope[]` (`created`, `doneAt`, `sp`, подзадачи), `epics[].epicDue` |
| клик по истории | `epics[].stories[].events[]` |
| операционный | `output.sprints[]`, `burndown` (без подзадач — `storyScope/storyClosed`, сборщик 1.10.0+), `assignee` и `statusChanged` историй и подзадач |
| «Сроки» | `control.*.points[]` и `risks[]`, `output.sprints[].start` / `end` / `timeInStatus` |
| «Планы» | строки историй, `epics[].scope[]` вне спринта (с `priority`), `plans` бизнес-блока |

Слайд пустой или частичный — значит, сборщик не отдал поле. Проверка: `python3 .claude/skills/actual-sprint/runner/run.py check reports/sprint-report.data.json` — экраны, которым не хватает данных, и каких полей. Лечится сборщиком (навык `sprint-data`), не текстом бизнес-блока и не правкой снимка.

## Стадии

### 1. Данные
Из корня проекта, где лежит `sprint-report.config.toml`. Есть снимок `reports/sprint-report.data.json` и человек не просил свежие данные — работай по нему. Снимка нет или нужны свежие — собери тем же runner'ом, что и отчёт PO (сборщики, не ты):

```bash
python3 .claude/skills/actual-sprint/runner/run.py run --config sprint-report.config.toml
```

Он заодно обновит отчёт PO — это те же цифры. Ошибки runner'а разбирай по `actual-sprint/SKILL.md` («Когда runner отказал»); данные сам не собирай.

### 2. Факты
```bash
python3 .claude/skills/sprint-business/business.py facts
```
`--team <slug>` — одна команда. По каждой команде: `dataHash`, `epics` (прогресс эпика и вклад спринта, закрытые истории), `sprintNow`, `charts`, `trend` (с выработкой команды в SP — `trend.output`).

### 3. Записать `reports/sprint-business.json`
Форма — `contract/business.schema.json`. Что пишешь — бизнес-блок по каждой команде, для управляющего комитета, PO смежных департаментов и бизнес-заказчиков. Колода верхнеуровневая: слайд = цель (OBJ), строка = направление — KR (эпик) со сводкой историй спринта; столбцы «Направление | Итог спринта | Результат». Подробности по историям — в отчёте PO для техлидов. «Результат» и сводку страница считает из данных сама («Закрыто: …», блокеры заблокированных историй, следующий шаг первой незакрытой); ты даёшь цели и формулировки лучше автоматических:

```json
{
  "version": 1,
  "generatedAt": "2026-09-15T17:20:00+03:00",
  "author": "PO-агент",
  "teams": {"<slug>": {
  "dataHash": "<из facts, без изменений>",
  "objectives": {"OBJ 3": "Платформа держит пиковый сезон"},
  "streams": {"INIT-125": {"obj": "OBJ 3", "kr": "KR 3.1 — платформа выдерживает пиковый сезон",
                           "done": "Метрики загрузчика на ревью; приём событий поднят, но не включён.",
                           "blocker": "нет доступа к очереди событий смежной команды",
                           "next": "эскалация на синке команд в четверг",
                           "promise": "что обещали на спринт", "shown": "что показываем", "verdict": "достигнут частично"},
              "no-epic": {"done": "Вне эпиков: мелкие доработки и поддержка, закрыто 2 из 12."}},
  "rows": {"INIT-132": {"done": "Сервис приёма событий поднят на стенде, приём ещё не включён.",
                        "next": "эскалация на синке команд в четверг",
                        "blocker": "нет доступа к очереди событий смежной команды"}},
  "plans": {"take": [], "finish": [], "maybe": [], "escalate": []},
  "risks": [{"title": "суть", "text": "какой коммитмент OKR под угрозой и почему"}],
  "goalsSource": ".okr/2026Q3/OKR-2026Q3.md"
  }}
}
```

- `objectives` и `streams.*.obj/kr` — **только из OKR/roadmap PO** (`.okr/<квартал>/OKR-*.md`, `roadmap.md`, `KR-EPIC-MAP.md` в рабочем пространстве) или со слов PO; откуда — в `goalsSource`. Не придумывай цели по названиям эпиков. Эпик без цели не привязывай — он уйдёт на слайд «Без привязки к OKR» (целей нет совсем — слайды «Направления спринта»). Заголовок слайда — «OBJ 3: название», строка — KR (нет KR — название эпика без меток «[PaaS]»).
- `streams.*.done/blocker/next` — **сводка строки-направления** для бизнеса: `done` — одно предложение, итог спринта по эпику (результат, а не перечень задач: «Платёжный контур стабилизирован: инциденты закрыты, нагрузочный тест ждёт стенд»); `blocker` — в чём заблокированы и кто нужен; `next` — следующий шаг, действие и срок. Ключ `no-epic` — строка «Вне эпиков» (истории без эпика), у неё только эти три поля. Главная работа агента — здесь: строк мало, каждая должна читаться руководителем без отчёта PO.
- `rows` — текст отдельной истории (`done`, `next`, `blocker`): виден в сайдбаре эпика по клику, а `blocker` — ещё и на слайде команды в панели «Заблокированы» и в автосводке эпика. Пиши для заблокированных историй (блокер своими словами) и для тех, где автотекст не передаёт сути.
- `verdict`, `promise`, `shown` — Sprint Goal по KR для фактов и разговора с PO; на слайдах не выводятся.
- `risks` — квартальные риски коммитментов OKR (слайд «РИСКИ», если есть). `changes` и `demo` устарели: слайдов «Изменения» и «Демо» в колоде нет, поля принимаются, но не выводятся — не пиши их.
- `plans` — слайд «Планы на следующий спринт», четыре колонки: `take` (взять в работу — по `epics[].nextUp` и целям), `finish` (доделать — незакрытое в спринте), `maybe` (возможно войдёт — низкий приоритет, если появится окно), `escalate` (эскалировать — блокеры, где нужна помощь руководства или смежников); до 30 строк `{title ≤ 80, text ≤ 160, keys}` в колонке. На слайде задачи сгруппированы по эпику первого ключа, строка — `title`, ключ и `text` — в подсказке (у «Эскалировать» `text` виден — это просьба). Нет колонки — страница соберёт её из данных.
- Тон — для руководителя: коротко, факт с датой, без жаргона трекера. PO может поправить любой текст прямо на слайде — пиши так, чтобы править было нечего.

Правила:
- Цифры и ключи задач — только из фактов и данных команды; `dataHash` — как в фактах.
- Цели OKR, риски и договорённости — из документов PO; их числа с фактами спринта не сверяются, но источник обязателен (`goalsSource`).
- Длины под слайд: сводка направления — `done` до 180, `next` до 100, `blocker` до 140; история — `done` до 140, `next` до 100, `blocker` до 120; `kr` до 120, `objective` до 100, риск — заголовок до 80 и текст до 280 знаков.

### 4. Проверить и собрать страницу
```bash
python3 .claude/skills/sprint-business/business.py apply
```
`apply` = `check` + `render`: схема, эпики и истории — только из спринта команды, ключи задач — из данных, длины, числа строк против фактов (`⚠`), `dataHash`; затем `reports/sprint-business.html` из снимка, без JIRA. `✗` — поправь файл и повтори. `dataHash не совпадает` — снимок пересобран после `facts`: начни со стадии 2. Без файла блока страница тоже собирается (`business.py render`) — текст строк тогда из данных.

### 5. Ответ в чат — и STOP
Одна строка: для каких команд записан блок и путь к `reports/sprint-business.html`. Пересказывать слайды не нужно. Не публикуй как Artifact без просьбы.

## Дизайн-контракт страницы
- Колода **«ФАКТ | спринт»** по эталону отчётной колоды спринта PO: белые слайды 1280×720, Arial, серые рамки, строки таблиц светофором. Страница открывается сразу колодой; отчёта PO под ней нет, кнопки закрытия нет.
  - Порядок: титул → по команде: слайд команды → слайды целей → операционный отчёт → «Сроки» → «Планы на следующий спринт» → после всех команд «РИСКИ» (если есть). Слайдов «Изменения», «Демо», «Итоги» нет: итог спринта — на слайде команды, подробности — в отчёте PO.
  - **Титул**: метка «Отчёт о продвижении за спринт», плашка статуса (идёт · рабочий день N из M / закрыт), «ФАКТ | период», строка команд и спринтов, полоса прошедших дней; по команде карточка — доля закрытых историй крупно, полоса, SP сделано, 🛑 в блоке, ⏳ не закрыто. Внизу — автор и время данных JIRA.
  - **Слайд команды — итог с одного взгляда**: «Команда · спринт · период», имя, черта, четыре числа (историй закрыто, SP сделано, 🛑 заблокировано — красным, ⏳ не успели по объёму — янтарным), цели спринта плашками (если есть) и две панели: **«🛑 Заблокированы»** — истории в статусе блокировки (ждём других, нужна помощь): суть, блокер (`rows.*.blocker` или статус), с какого дня и сколько дней; **«⏳ Не успели по объёму»** — не закрыто и не заблокировано (не успели сами), по направлениям: «N из M не закрыто · в работе · не начато». До последнего рабочего дня спринта вторая панель называется «Пока не закрыто». До 6 строк в панели, остальное — «и ещё N».
  - **От целей, верхнеуровнево.** Слайд = цель: заголовок «OBJ 3: название» (целей нет — «Направления спринта»; эпики без цели при заданных целях — «Без привязки к OKR»). Таблица «Направление | Итог спринта | Результат», строка = эпик (KR), истории без эпика — строка «Вне эпиков» последней; строки по убыванию результата. До 6 строк на слайд, поровну (8 → 4 + 4). Подписи про ИИ-агента на слайдах нет.
  - **Результат строки** — среднее результата историй спринта (история: закрыта — 100%; иначе большее из доли закрытых подзадач и стадии — в работе 30, тест 80, ревью 90, не начата 0 — не выше 90), под ним «закрыто X из Y» и полоса историй: закрыто / в работе / в блоке / не начато. Строка: 100% — зелёная, 50–99 — жёлтая, ниже — красная; есть заблокированные — красная риска слева. Как посчитано — подсказка у процента.
  - **Итог спринта** — метки «🛑 заблокировано N» и «⏳ не закрыто N», затем одно предложение итога, «Блокер: …» и «След. шаг: …». Из данных: «Закрыто: <истории>» (или «В работе: …»), блокер — заблокированные истории с их блокером или статусом, след. шаг — первой незакрытой истории. Сводка агента (`streams.*.done/blocker/next`) заменяет автоматическую.
  - **Операционный отчёт** — один слайд без заголовка (только метка «Команда · операционный отчёт»), сверху три графика: «Производительность за 3 спринта» (план в SP на конец спринта по трём группам и выполнено, пунктир — среднее), «Сгорание: истории и задачи» (без подзадач, `storyScope/storyClosed`) и «Сгорание: с подзадачами» (все задачи) — идеальная линия убывает только по рабочим дням (в выходные полка), пунктир — объём спринта (видно добавленное), красная — осталось, вертикаль — день сбора, справа крупно «N из M». Без полей сборщика 1.10.0 первый график говорит, что данные нужно пересобрать. Снизу — истории, подзадачи и SP текущего спринта по исполнителю: строка на участника, полосы по статусам (Готово / В работе / Ревью / Отладка / Заблокировано / Не начато), «сделано/всего», SP «сделано/взято» и «Застряли» — сколько задач не в бэклоге и не готово и стоят дольше 3 дней, и самое долгое (ключи — в подсказке). Подзадач с исполнителем в спринте нет — колонка подзадач скрыта с пояснением. Над ними — «Шкала: Числа / Доли» и «Сортировка: По застрявшим / По готовности / По списку»; клик по имени — сайдбар задач участника.
  - **«Сроки»** — следующий слайд, метка «Команда · сроки». Без заголовков блоков. Сверху cycle time закрытых задач за 3 спринта, дни: спринты — полосами с короткими именами (С72…), точки историй (синие) и подзадач (оранжевые), у каждого потока сглаженное скользящее среднее по 5 последним задачам (истории — сплошная, подзадачи — пунктир) с коридором ±σ того же окна, как в JIRA, и его значение подписью в конце линии; поток без закрытых задач не рисуется, в легенде — «за 3 спринта закрытых нет». Снизу среднее время в статусе по спринтам, дни — «Заблокировано», «Ревью», «Отладка»: текущее значение крупно, столбики по спринтам, текущий насыщенный; оценок «хуже / лучше» нет. Данные — `output.sprints[].timeInStatus` (сборщик 1.8.0+); без них блок говорит, что данных нет. Клик по cycle time — сайдбар разбора: вкладки «Истории / Подзадачи», показатели (закрыто, медиана, среднее, σ, порог выброса, выбросы, в зоне риска), классическая диаграмма управления со списками выбросов и зоны риска, таблица по спринтам.
  - **«Планы на следующий спринт»** — после слайда «Сроки», рабочий слайд для техлидов: четыре колонки «Взять в работу» / «Доделать» / «Возможно войдёт» / «Эскалировать»; внутри колонки — по направлениям (шапка эпика со счётчиком), строка — суть задачи без ключа, ключ и пояснение — в подсказке; у «Эскалировать» пояснение видно (до двух строк). До 15 строк в колонке вместе с шапками, остальное — «ещё N — в подсказке», счётчик колонки — всё. Из `plans` агента, иначе из данных: «Взять» — до трёх следующих открытых задач эпика вне спринта не низкого приоритета (+N в шапке — сколько ещё в объёме), «Доделать» — незакрытое в спринте, кроме заблокированного, «Возможно войдёт» — открытые задачи эпика с низким приоритетом (Low / Lowest / Minor / Trivial / Низкий), «Эскалировать» — заблокированное с блокером.
  - **Сайдбары поверх колоды.** Клик по строке-направлению — две вкладки: «Истории спринта» (каждая — статус, результат, исполнитель, «что сделано», блокер, след. шаг; клик — активность истории) и «Весь эпик» — тот же, что в отчёте PO (`renderScope` общего движка): сгорание эпика по неделям с прогнозными столбцами и панелью «≈ N недель до закрытия · прогноз · план», затем «Что осталось» и «Что выполнено». Активность истории — сверху календарь активности за всё время (статус истории полосой по дням, события подзадач — закрытие зелёным, комментарии, отметка начала спринта; детали — по наведению), ниже одна лента по хронологии — создание, смены статуса, комментарии истории и подзадач — с фильтром «Все / История / Подзадачи» (по умолчанию все). Данные — `story.events` сборщика 1.7.0. Esc закрывает сайдбар.
  - **Правка текста** — «Редактировать текст»: всё текстовое на слайдах (заголовки, KR, итог, «след. шаг», блокеры, цели, планы, риски) правится по месту, с пунктиром; правки сохраняются в браузере (`actual-sprint:deck-text:…`) и переживают пересборку слайдов, «Вернуть текст» сбрасывает. **Комментарий — правым кликом** (на телефоне — долгим нажатием) по строке-направлению или слайду; уходит в корзину команды (общую с отчётом PO, если файлы открыты из одного места), строка с комментарием помечена риской.
  - **Сцена на весь экран** (окно шире 900 px): виден один слайд, масштаб под свободную площадь — и вверх, и вниз; у левого края — чёрный вертикальный ярлык «Слайды»: открывает выезжающий сайдбар со списком слайдов «номер · тип · заголовок» (текущий выделен), клик — переход и сайдбар закрывается, Esc или клик мимо — закрыть; внизу «‹ N / M ›»; стрелки, PageUp/PageDown, пробел, Home/End листают; слайд выше 720 (много строк, правка текста) **прокручивается внутри** — колесом, а ↓ / пробел / PageDown сначала докручивают его до конца и только потом листают, внизу сцены — «↓ ещё ниже»; F или «На весь экран» — полноэкранный режим браузера. На узком экране (телефон) — лента слайдов во всю ширину и оглавление списком. «PDF» — печать всех слайдов по слайду на страницу 1280×720 без механики правок.
- **«Для техлидов»** — кнопка в шапке колоды: окно с готовым промтом «собери технический отчёт» — `/actual-sprint`, период, команды и спринты, снимок данных, и вопросы с бизнес-отчёта: комментарии к слайдам и строкам из корзин всех команд, чтобы разобрать их с техлидами. «Скопировать промт» — в буфер.

## Что где лежит
```
business.py                      facts | check | apply | render
contract/business.schema.json    форма reports/sprint-business.json
resources/business_template.html страница: колода, сцена, сайдбары, «Для техлидов»
examples/demo-business.json      пример блока на демо-данных
```
Общий движок страниц (данные команд, статусы, корзина, сайдбары, графики) — `actual-sprint/resources/shared`; сборка частей — `actual-sprint/runner/build.py`.

## Границы
Только чтение снимка и запись локальных `reports/sprint-business.json` и `reports/sprint-business.html`. Никаких записей в JIRA/Confluence, публикации и автозапуска.
