# Навык: бизнес-отчёт «ФАКТ | спринт»

## Два отчёта — одни данные
- **Отчёт PO** (`/actual-sprint`, `reports/sprint-report.html`) — для синхронизации с техлидами: эпики, статусы задач, сводный отчёт, интерпретация ИИ. На нём кнопка «Бизнес-отчёт» даёт промт на этот навык.
- **Бизнес-отчёт** (этот навык, `reports/sprint-business.html`) — для управляющего комитета, PO смежных департаментов и бизнес-заказчиков: продвижение за спринт от целей. На нём кнопка «Для техлидов» даёт промт на отчёт PO.

Данные у них общие и собираются одинаково: сборщики команд → runner `actual-sprint` → снимок `reports/sprint-report.data.json`. Ты не источник данных: не ходишь в трекер, не пересчитываешь метрики, не берёшь цифры из памяти. Страница, шаблон и генерация — свои: `business.py` и `resources/business_template.html` (движок страницы общий с отчётом PO — `actual-sprint/resources/shared`).

## Стадии

### 1. Данные
Из корня проекта, где лежит `sprint-report.config.toml`. Есть снимок `reports/sprint-report.data.json` и человек не просил свежие данные — работай по нему. Снимка нет или нужны свежие — собери тем же runner'ом, что и отчёт PO (сборщики, не ты):

```bash
python3 .claude/skills/actual-sprint/runner/run.py run --config sprint-report.config.toml
```

Он заодно обновит отчёт PO — это те же цифры. Ошибки runner'а разбирай по `actual-sprint/SKILL.md` («Когда runner отказал»); данные сам не собирай.

### 2. Факты
```bash
python3 .claude/skills/sprint-business/business.py facts
```
`--team <slug>` — одна команда. По каждой команде: `dataHash`, `epics` (прогресс эпика и вклад спринта, закрытые истории), `sprintNow`, `charts`, `trend` (с выработкой команды в SP — `trend.output`).

### 3. Записать `reports/sprint-business.json`
Форма — `contract/business.schema.json`. Что пишешь — бизнес-блок по каждой команде, для управляющего комитета, PO смежных департаментов и бизнес-заказчиков. Колода строится от целей: слайд = цель (OBJ), группа в таблице = KR (эпик), строка = история спринта; столбцы «Задачи | Комментарий | Результат». «Результат» и текст строк страница считает из данных сама (закрытые подзадачи — что сделано, первая открытая — следующий шаг); ты даёшь цели и формулировки лучше автоматических:

```json
{
  "version": 1,
  "generatedAt": "2026-09-15T17:20:00+03:00",
  "author": "PO-агент",
  "teams": {"<slug>": {
  "dataHash": "<из facts, без изменений>",
  "objectives": {"OBJ 3": "Платформа держит пиковый сезон"},
  "streams": {"INIT-125": {"obj": "OBJ 3", "kr": "KR 3.1 — платформа выдерживает пиковый сезон",
                           "promise": "что обещали на спринт", "shown": "что показываем", "verdict": "достигнут частично"}},
  "rows": {"INIT-132": {"done": "Сервис приёма событий поднят на стенде, приём ещё не включён.",
                        "next": "эскалация на синке команд в четверг",
                        "blocker": "нет доступа к очереди событий смежной команды"}},
  "changes": [{"affected": "задача", "before": "было", "after": "стало", "outcome": "что вышло"}],
  "demo": [{"what": "что показываем руками", "minutes": 3}],
  "risks": [{"title": "суть", "text": "какой коммитмент OKR под угрозой и почему"}],
  "goalsSource": ".okr/2026Q3/OKR-2026Q3.md"
  }}
}
```

- `objectives` и `streams.*.obj/kr` — **только из OKR/roadmap PO** (`.okr/<квартал>/OKR-*.md`, `roadmap.md`, `KR-EPIC-MAP.md` в рабочем пространстве) или со слов PO; откуда — в `goalsSource`. Эпик без цели не привязывай — он уйдёт на слайд «Без привязки к OKR». Заголовок слайда — «OBJ 3: название», шапка группы — KR; клик по ней открывает объём эпика «Выполнено / В работе / Осталось».
- `rows` — текст строки для бизнеса: `done` — **одно предложение**, что сделано (результат, а не статус: «Дашборд метрик собран и на ревью», не «Статус Ревью»); `next` — следующий шаг, действие и срок; `blocker` — только если есть. Пиши для строк, где автоматический текст из подзадач не передаёт сути.
- `verdict`, `promise`, `shown` — Sprint Goal по KR для фактов и разговора с PO; на слайдах не выводятся.
- `changes`, `demo`, `risks` — договорённости, поменявшиеся по ходу спринта; что показываем; квартальные риски коммитментов OKR.
- `plans` — слайд «Планы на следующий спринт»: `take` (взять в работу — по `epics[].nextUp` и целям), `finish` (доделать — незакрытое в спринте), `escalate` (эскалировать — блокеры, где нужна помощь руководства или смежников); до четырёх карточек `{title ≤ 80, text ≤ 160, keys}` в колонке. Нет колонки — страница соберёт её из данных.
- Тон — для руководителя: коротко, факт с датой, без жаргона трекера. PO может поправить любой текст прямо на слайде — пиши так, чтобы править было нечего.

Правила:
- Цифры и ключи задач — только из фактов и данных команды; `dataHash` — как в фактах.
- Цели OKR, риски и договорённости — из документов PO; их числа с фактами спринта не сверяются, но источник обязателен (`goalsSource`).
- Длины под слайд: `done` до 140, `next` до 100, `kr` до 120, `objective` до 100, риск — заголовок до 80 и текст до 280 знаков.

### 4. Проверить и собрать страницу
```bash
python3 .claude/skills/sprint-business/business.py apply
```
`apply` = `check` + `render`: схема, эпики и истории — только из спринта команды, ключи задач — из данных, длины, числа строк против фактов (`⚠`), `dataHash`; затем `reports/sprint-business.html` из снимка, без JIRA. `✗` — поправь файл и повтори. `dataHash не совпадает` — снимок пересобран после `facts`: начни со стадии 2. Без файла блока страница тоже собирается (`business.py render`) — текст строк тогда из данных.

### 5. Ответ в чат — и STOP
Одна строка: для каких команд записан блок и путь к `reports/sprint-business.html`. Пересказывать слайды не нужно. Не публикуй как Artifact без просьбы.

## Дизайн-контракт страницы
- Колода **«ФАКТ | спринт»** по эталону отчётной колоды спринта PO: белые слайды 1280×720, Arial, серые рамки, строки таблиц светофором. Страница открывается сразу колодой; отчёта PO под ней нет, кнопки закрытия нет.
  - Порядок: титул → по команде: слайд команды → слайды целей → операционный отчёт → «Планы на следующий спринт» → после всех команд: «Изменения в процессе спринта» → «Демо» → «Итоги спринта» → «РИСКИ». Изменения, демо и риски — только если есть что показать.
  - **Титул**: метка «Отчёт о продвижении за спринт», плашка статуса (идёт · рабочий день N из M / закрыт), «ФАКТ | период», строка команд и спринтов, полоса прошедших дней; по команде карточка — доля закрытых историй крупно, полоса, SP сделано, число целей, в блоке. Внизу — автор и время данных JIRA.
  - **Слайд команды** — всё по центру: «Команда · спринт · период», имя крупно, черта, три числа (историй закрыто, SP сделано, в блоке — красным, если есть), под ними «Цели спринта» карточками: OBJ, название, число KR и закрытых историй.
  - **От целей.** Слайд = цель: заголовок «OBJ 3: название». В таблице «Задачи | Комментарий | Результат» группа = KR (эпик): в шапке только KR («KR 3.1 — …»; нет цели — название эпика) — без «эпик «…»», Sprint Goal и счётчиков; строки — истории спринта по убыванию результата. Эпики без цели — слайд «Без привязки к OKR». До восьми строк на слайд вместе с шапками KR. Подписи про ИИ-агента на слайдах нет.
  - **Результат** — из данных: закрыта — 100%; иначе большее из доли закрытых подзадач и стадии (в работе 30, тест 80, ревью 90, не начата 0), не выше 90. Заблокирована — 🛑, не начата — 🚫. Строка: 100% — зелёная, 50–99 — жёлтая, ниже — красная. Как посчитано — подсказка у процента.
  - **Комментарий** — одно предложение «что сделано» и «След. шаг: …» (и «Блокер: …», если есть). Из данных: закрытые подзадачи («Сделано: схема БД, прогон (2 из 5 подзадач).») или стадия с датой («На ревью с 14.09.»), следующий шаг — первая незакрытая подзадача. Формулировки агента (`rows` в `reports/sprint-business.json`) заменяют автоматические.
  - **Операционный отчёт** — один слайд без заголовка (только метка «Команда · операционный отчёт»), три графика: сверху слева «Производительность команды за 3 спринта» (план в SP на конец спринта по трём группам и выполнено, пунктир — среднее выполненное), сверху справа «Сгорание спринта» (burndown текущего спринта: идеальная линия, остаток, выходные), снизу во всю ширину «Диаграмма управления за 3 спринта» — истории (заливка) и подзадачи (кольца), своя медиана у каждого потока, границы спринтов. Выработки по участникам здесь нет — она в отчёте PO («Команда: N»).
  - **«Планы на следующий спринт»** — после операционного отчёта команды: три колонки «Взять в работу» / «Доделать» / «Эскалировать», до четырёх кратких карточек (суть, одно предложение, ключи). Из `plans` агента, иначе из данных: открытый объём KR вне спринта, незакрытое в спринте по убыванию результата со следующим шагом, заблокированное с блокером.
  - **Итоги**: счётчики 100% / 50–99% / до 50%; «Ключевые блокеры» — по давности; «Не закрыто на сегодня — кандидаты на перенос» со следующим шагом (после конца спринта — «Переносим в следующий спринт»).
  - **Сайдбары поверх колоды.** Клик по шапке KR — тот же «Весь эпик», что в отчёте PO (`renderScope` общего движка): сгорание эпика по неделям с прогнозными столбцами и панелью «≈ N недель до закрытия · прогноз · план», затем «Что осталось» и «Что выполнено». Клик по строке истории — сверху календарь активности за всё время (статус истории полосой по дням, события подзадач — закрытие зелёным, комментарии, отметка начала спринта; детали — по наведению), ниже одна лента по хронологии — создание, смены статуса, комментарии истории и подзадач — с фильтром «Все / История / Подзадачи» (по умолчанию все). Данные — `story.events` сборщика 1.7.0. Esc закрывает сайдбар.
  - **Правка текста** — «Редактировать текст»: всё текстовое на слайдах (заголовки, KR, «что сделано», «след. шаг», блокеры, изменения, демо, риски) правится по месту, с пунктиром; правки сохраняются в браузере (`actual-sprint:deck-text:…`) и переживают пересборку слайдов, «Вернуть текст» сбрасывает. **Комментарий — правым кликом** (на телефоне — долгим нажатием) по строке, KR или слайду; уходит в корзину команды (общую с отчётом PO, если файлы открыты из одного места), строка с комментарием помечена риской.
  - **Сцена на весь экран** (окно шире 900 px): виден один слайд, масштаб под свободную площадь — и вверх, и вниз; у левого края — чёрный вертикальный ярлык «Слайды»: открывает выезжающий сайдбар со списком слайдов «номер · тип · заголовок» (текущий выделен), клик — переход и сайдбар закрывается, Esc или клик мимо — закрыть; внизу «‹ N / M ›»; стрелки, PageUp/PageDown, пробел, Home/End листают, F или «На весь экран» — полноэкранный режим браузера. На узком экране (телефон) — лента слайдов во всю ширину и оглавление списком. «PDF» — печать всех слайдов по слайду на страницу 1280×720 без механики правок.
- **«Для техлидов»** — кнопка в шапке колоды: окно с готовым промтом «собери технический отчёт» — `/actual-sprint`, период, команды и спринты, снимок данных, и вопросы с бизнес-отчёта: комментарии к слайдам и строкам из корзин всех команд, чтобы разобрать их с техлидами. «Скопировать промт» — в буфер.

## Что где лежит
```
business.py                      facts | check | apply | render
contract/business.schema.json    форма reports/sprint-business.json
resources/business_template.html страница: колода, сцена, сайдбары, «Для техлидов»
examples/demo-business.json      пример блока на демо-данных
```
Общий движок страниц (данные команд, статусы, корзина, сайдбары, графики) — `actual-sprint/resources/shared`; сборка частей — `actual-sprint/runner/build.py`.

## Границы
Только чтение снимка и запись локальных `reports/sprint-business.json` и `reports/sprint-business.html`. Никаких записей в JIRA/Confluence, публикации и автозапуска.
