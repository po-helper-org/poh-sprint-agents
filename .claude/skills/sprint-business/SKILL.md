# Навык: бизнес-отчёт «ФАКТ | спринт»

## Два отчёта — одни данные
- **Отчёт PO** (`/actual-sprint`, `reports/sprint-report.html`) — для синхронизации с техлидами: эпики, статусы задач, сводный отчёт, интерпретация ИИ. На нём кнопка «Бизнес-отчёт» даёт промт на этот навык.
- **Бизнес-отчёт** (этот навык, `reports/sprint-business.html`) — для управляющего комитета, PO смежных департаментов и бизнес-заказчиков: продвижение за спринт от целей. На нём кнопка «Для техлидов» даёт промт на отчёт PO.

Данные у них общие и собираются одинаково: сборщики команд → runner `actual-sprint` → снимок `reports/sprint-report.data.json`. Ты не источник данных: не ходишь в трекер, не пересчитываешь метрики, не берёшь цифры из памяти. Страница, шаблон и генерация — свои: `business.py` и `resources/business_template.html` (движок страницы общий с отчётом PO — `actual-sprint/resources/shared`).

## Откуда цифры на слайдах
Каждый слайд рисует код страницы из полей JSON команды — детерминированно: «сегодня» колоды — момент сбора (`_meta.collectedAt`), поэтому презентация, открытая через неделю, показывает тот же снимок. От модели на слайдах только тексты бизнес-блока, и они прикладываются, только если `dataHash` совпал.

| Слайд | Поля данных (подробно — `sprint-data/reference/render.md`) |
|---|---|
| титул, слайд команды | `epics[].stories[]`, `burndown.days[]`, SP — `output` |
| слайды целей (строка = эпик) | `epics[].stories[]` с подзадачами и `statusChanged`; цели, KR, сводки — бизнес-блок |
| клик по строке | истории спринта эпика; «Весь эпик» — `epics[].scope[]` (`created`, `doneAt`, `sp`, подзадачи), `epics[].epicDue` |
| клик по истории | `epics[].stories[].events[]` |
| операционный | `output.sprints[]` (с `start` / `end`), `burndown` (без подзадач — `storyScope/storyClosed`, сборщик 1.10.0+), `control.*.points[]` и `risks[]` |
| «Участники» | `output.sprints[]` (прошлый спринт — переходящие), `output.offboard`, `assignee` и `statusChanged` историй и подзадач |
| роадмап «Инициативы по спринтам» | `burndown.start/end` (даты следующих спринтов), открытые `epics[].scope[]` (фаза по задачам), `epics[].epicDue`, `roadmap` бизнес-блока |
| «Риски и проблемы» | `risks` бизнес-блока; иначе прежняя колонка `plans.escalate`; иначе заблокированные истории, просроченные эпики, прогноз позже срока |

Слайд пустой или частичный — значит, сборщик не отдал поле. Проверка: `python3 .claude/skills/actual-sprint/runner/run.py check reports/sprint-report.data.json` — экраны, которым не хватает данных, и каких полей. Лечится сборщиком (навык `sprint-data`), не текстом бизнес-блока и не правкой снимка.

## Стадии

### 1. Данные
Из корня проекта, где лежит `sprint-report.config.toml`. Есть снимок `reports/sprint-report.data.json` и человек не просил свежие данные — работай по нему. Снимка нет или нужны свежие — собери тем же runner'ом, что и отчёт PO (сборщики, не ты):

```bash
python3 .claude/skills/actual-sprint/runner/run.py run --config sprint-report.config.toml
```

Он заодно обновит отчёт PO — это те же цифры. Ошибки runner'а разбирай по `actual-sprint/SKILL.md` («Когда runner отказал»); данные сам не собирай.

### 2. Факты
```bash
python3 .claude/skills/sprint-business/business.py facts
```
`--team <slug>` — одна команда. По каждой команде: `dataHash`, `epics` (прогресс эпика и вклад спринта, закрытые истории), `sprintNow`, `charts`, `trend` (с выработкой команды в SP — `trend.output`).

### 2а. Цели квартала и состав команды — из кэша
Направление на слайде = цель OBJ квартального плана. Цели, привязка эпиков к ним и состав команды (прямое подчинение; остальные на доске — [EXT]) лежат в кэше `reports/sprint-goals.json` рядом со снимком — каждый раз не переспрашивать:

```json
{"version": 1, "teams": {"<slug>": {"quarter": "2026Q4", "askedAt": "2026-10-06", "askedFrom": "Hermes po-<команда>",
  "objectives": {"OBJ 1": "Название цели"}, "epics": {"INIT-125": "OBJ 1"}, "noObjective": ["INIT-140"],
  "members": ["Фамилия Имя Отчество"], "source": "квартальный план / Confluence …"}}}
```

Кэша нет, квартал сменился или в спринте эпики, которых нет в кэше, — спроси **PO-агента команды в Hermes** (профиль `po-<команда>`: `hermes -p po-gds -z "…"` под владельцем, ответ — JSON-блоком) или PO; запиши ответ в кэш и укажи источник. Из кэша — в бизнес-блок: `objectives`, `streams.*.obj` (`kr` — если KR названы), `members`, `goalsSource`.

**Заметки PO про корпоративные ресурсы** («закрыть задачу», «связать с эпиком», «поправить страницу» в JIRA/Confluence) не выполняй сам: поручи PO-агенту команды в Hermes, проверь результат чтением и пересобери данные, если менялись статусы. В отчёт — что сделал агент. Задачи, которые PO просит убрать из отчёта, — в `hide`.

### 3. Записать `reports/sprint-business.json`
Форма — `contract/business.schema.json`. Что пишешь — бизнес-блок по каждой команде, для управляющего комитета, PO смежных департаментов и бизнес-заказчиков. Колода верхнеуровневая: слайд = цель (OBJ), строка = направление — KR (эпик) со сводкой историй спринта; столбцы «Направление | Итог спринта | Результат спринта | Прогресс инициативы». Подробности по историям — в отчёте PO для техлидов. «Результат» и сводку страница считает из данных сама («Закрыто: …», блокеры заблокированных историй, следующий шаг первой незакрытой); ты даёшь цели и формулировки лучше автоматических:

```json
{
  "version": 1,
  "generatedAt": "2026-09-15T17:20:00+03:00",
  "author": "PO-агент",
  "teams": {"<slug>": {
  "dataHash": "<из facts, без изменений>",
  "objectives": {"OBJ 3": "Платформа держит пиковый сезон"},
  "streams": {"INIT-125": {"obj": "OBJ 3", "kr": "KR 3.1 — платформа выдерживает пиковый сезон",
                           "done": "Метрики загрузчика на ревью; приём событий поднят, но не включён.",
                           "blocker": "нет доступа к очереди событий смежной команды",
                           "next": "эскалация на синке команд в четверг",
                           "promise": "что обещали на спринт", "shown": "что показываем", "verdict": "достигнут частично"},
              "no-epic": {"done": "Вне эпиков: мелкие доработки и поддержка, закрыто 2 из 12."}},
  "rows": {"INIT-132": {"done": "Сервис приёма событий поднят на стенде, приём ещё не включён.",
                        "next": "эскалация на синке команд в четверг",
                        "blocker": "нет доступа к очереди событий смежной команды"}},
  "roadmap": {"rows": [{"epic": "INIT-125", "cells": ["аналитика", "аналитика", "бек", "бек", "бек", "приёмка"]}, {"title": "своя инициатива", "obj": "OBJ 3", "cells": ["", "", "qa", "qa", "qa", "приёмка"]}]},
  "risks": [{"kind": "external", "title": "от команды X ждём Kafka и оферту", "text": "если не выкатится — заказы и возвраты уходят за квартал"}],
  "goalsSource": ".okr/2026Q3/OKR-2026Q3.md"
  }}
}
```

- `objectives` и `streams.*.obj/kr` — **только из OKR/roadmap PO** (`.okr/<квартал>/OKR-*.md`, `roadmap.md`, `KR-EPIC-MAP.md` в рабочем пространстве) или со слов PO; откуда — в `goalsSource`. Не придумывай цели по названиям эпиков. Эпик без цели не привязывай — он уйдёт на слайд «Без привязки к OKR» (целей нет совсем — слайды «Направления спринта»). Заголовок слайда — «OBJ 3: название», строка — KR (нет KR — название эпика без меток «[PaaS]»).
- `streams.*.readiness` — готовность направления по оценке PO, % (только со слов PO): в «Результате» вместо расчёта по задачам, с пометкой «оценка PO», расчёт — в подсказке. 100% — «сделано, что планировалось» (в т. ч. отменённая инициатива): полоса зелёная, автоматического блокера и бейджа «блокаторы» нет — статусы задач вроде «В ожидании» не выдаются за блокер; явный `streams.*.blocker` остаётся.
- `streams.*.done/blocker/next` — **сводка строки-направления** для бизнеса: `done` — одно предложение, итог спринта по эпику (результат, а не перечень задач: «Платёжный контур стабилизирован: инциденты закрыты, нагрузочный тест ждёт стенд»); `blocker` — в чём заблокированы и кто нужен; `next` — следующий шаг, действие и срок. Ключ `no-epic` — строка «Вне эпиков» (истории без эпика), у неё только эти три поля. Главная работа агента — здесь: строк мало, каждая должна читаться руководителем без отчёта PO.
- `rows` — текст отдельной истории (`done`, `next`, `blocker`): виден в сайдбаре эпика по клику, а `blocker` — ещё и на слайде команды в панели «Заблокированы» и в автосводке эпика. Пиши для заблокированных историй (блокер своими словами) и для тех, где автотекст не передаёт сути.
- `verdict`, `promise`, `shown` — Sprint Goal по KR для фактов и разговора с PO; на слайдах не выводятся.
- `members` — состав команды из кэша (для [EXT] на «Участниках»; `members`, `hide` и `escalation` берутся и из устаревшего блока, состава нет в блоке — из `sprint-goals.json` рядом, так [EXT] размечен и на свежих данных до переписывания текстов); `escalation` — кто по умолчанию эскалирует блокеры (иначе «PO команды»), `rows.*.escalate` — для конкретного блокера; `hide` — ключи задач, которые PO убрал из отчёта; `jiraNative` (на уровне файла) — адрес задачи в виджете JIRA с `{key}`: ключи на слайдах дают выбор «JIRA — в браузере» / «JIRA-native — виджет».
- `risks` — слайд «Риски и проблемы» у каждой команды, до 5 строк: `kind` — метка (`external` — ждём другие команды, `resource` — люди и загрузка, `general` — общее, `deadline` — срок; нет — «Общее»), `title` ≤ 80 — проблема одной строкой, `text` ≤ 280 — что будет, если не решить, и какая помощь нужна (от кого, к какой дате). Это коммуникация с внешними командами и руководителями: только то, где нужна реакция или что меняет сроки. Нет `risks` — страница возьмёт `plans.escalate`, а без него — данные (блокеры → «Внешнее» с тем, кто эскалирует; просроченные эпики и прогноз позже срока → «Срок»). `changes` и `demo` устарели: слайдов «Изменения» и «Демо» в колоде нет, поля принимаются, но не выводятся — не пиши их.
- `roadmap` — слайд «Инициативы по спринтам» у каждой команды: квартальный план на 3 следующих спринта, по 2 недели — 6 ячеек. До 14 строк: `epic` — эпик команды из снимка (название, номер цели и срок страница возьмёт сама) или своя строка `title` ≤ 80 + `obj`; `cells` — фаза в каждой неделе: `аналитика`, `дизайн`, `бек`, `фронт`, `разработка`, `qa`, `приёмка`, `релиз`, `контент` или пусто. Фазы — по OKR/roadmap и словам PO (`goalsSource`), не выдумывай. Нет блока — каркас из данных: открытые эпики, полоса с текущей недели до срока (Target end) или прогноза, фаза — по задачам ([SA]/[BE]/[FE]/[QA], тест, ревью), в последней неделе — приёмка.
- `plans` устарел: слайда «Планы на следующий спринт» нет (заменён роадмапом, 2026-10); поле принимается, а `plans.escalate` показывается в «Рисках и проблемах», если `risks` не заданы. Новых `plans` не пиши.
- Тон — для руководителя: коротко, факт с датой, без жаргона трекера. PO может поправить любой текст прямо на слайде — пиши так, чтобы править было нечего.

Правила:
- Цифры и ключи задач — только из фактов и данных команды; `dataHash` — как в фактах.
- Цели OKR, риски и договорённости — из документов PO; их числа с фактами спринта не сверяются, но источник обязателен (`goalsSource`).
- Длины под слайд: сводка направления — `done` до 180, `next` до 100, `blocker` до 140; история — `done` до 140, `next` до 100, `blocker` до 120; `kr` до 120, `objective` до 100, риск — заголовок до 80 и текст до 280 знаков.

### 4. Проверить и собрать страницу
```bash
python3 .claude/skills/sprint-business/business.py apply
```
`apply` = `check` + `render`: схема, эпики и истории — только из спринта команды, ключи задач — из данных, длины, числа строк против фактов (`⚠`), `dataHash`; затем `reports/sprint-business.html` из снимка, без JIRA. `✗` — поправь файл и повтори. `dataHash не совпадает` — снимок пересобран после `facts`: начни со стадии 2. Без файла блока страница тоже собирается (`business.py render`) — текст строк тогда из данных.

Одна строка: для каких команд записан блок и путь к `reports/sprint-business.html`. Пересказывать слайды не нужно. Не публикуй как Artifact без просьбы.

## Дизайн-контракт страницы
- Колода **«ФАКТ | спринт»** по эталону отчётной колоды спринта PO: белые слайды 1280×720, Arial, серые рамки, строки таблиц светофором. Страница открывается сразу колодой; отчёта PO под ней нет, кнопки закрытия нет.
  - Порядок: титул → по команде: слайд команды → слайды целей → операционный отчёт → «Участники» → «Инициативы по спринтам» → «Риски и проблемы». Слайдов «Изменения», «Демо», «Итоги», «Планы на следующий спринт» и общего «РИСКИ» нет: итог спринта — на слайде команды, подробности — в отчёте PO.
  - **Титул**: только карточки команд по центру — доля закрытых задач крупно, полоса, SP сделано, 🛑 в блоке, ⏳ не закрыто. Без заголовка, периода, статуса спринта и подписи; «ФАКТ | период» — в оглавлении слайдов и в шапке страницы.
  - **Слайд команды** — по центру: «Команда · спринт · период», имя, черта, два числа (задач закрыто, SP сделано) и цели квартала в спринте карточками: OBJ, название, сколько направлений и закрыто X из Y. Блокеров и «не успели» здесь нет — они в строках направлений.
  - **От целей, верхнеуровнево.** Слайд = цель: заголовок «OBJ 3: название» (целей нет — «Направления спринта»; эпики без цели при заданных целях — «Без привязки к OKR»). Таблица «Направление | Итог спринта | Результат спринта | Прогресс инициативы», строка = эпик (KR), истории без эпика — строка «Вне эпиков» последней; строки по убыванию результата. До 6 строк на слайд, поровну (8 → 4 + 4). Подписи про ИИ-агента на слайдах нет.
  - **Результат спринта** — среднее результата задач спринта (задача: закрыта — 100%; иначе большее из доли закрытых подзадач и стадии — в работе 30, тест 80, ревью 90, не начата 0 — не выше 90) и полоса задач (закрыто / в работе / в блоке / не начато; «закрыто X из Y» и числа — в подсказке полосы, подсказки «как посчитано» у процента нет) и, если есть заблокированные, метка **«🛑 блокаторы: N»**: наведение — список, клик — сайдбар блокаторов (суть, с какого дня, блокер, исполнитель, кто эскалирует, последние комментарии, переход к активности). Строка: 100% — зелёная, 50–99 — жёлтая, ниже — красная; есть заблокированные — красная риска слева. Ключ эпика в строке — по наведению меню «JIRA — в браузере» / «JIRA-native — виджет» (`jiraNative`); так же — все ключи в сайдбарах.
  - **Прогресс инициативы** — весь эпик (`epics[].scope[]`), а не только спринт. В ячейке только процент закрытых задач эпика, рядом «(+n%)» — вклад спринта (задачи эпика, закрытые с начала спринта по `doneAt`, от всего объёма; закрытые без даты не считаются), и полоса стадий «не начато → в работе (заблокированные — красным рядом) → QA (тест + ревью) → готово». В подсказке полосы — «сделано X из Y», «срок дд.мм» из `epicDue` (целевая дата эпика: «Target end» Advanced Roadmaps, нет — «Срок исполнения»; нет обоих — «срок не задан»), «прогноз дд.мм» (та же «Расчётная дата», что в «Весь эпик»), числа по стадиям и SP. Прогноз позже срока или срок прошёл, а эпик не закрыт — процент красный, причина («позже срока» / «просрочен») — в подсказке. Клик — сайдбар сразу на вкладке «Весь эпик»; клик по остальной строке — «Задачи спринта». Строка «Вне эпиков» и эпик без объёма в данных — прочерк.
  - **Итог спринта** — ровный текст одного кегля: одно предложение итога (ключ эпика — в шапке сайдбара по клику), «Дальше: …» и «Блокер: …» — обычный текст в строку, тот же цвет и кегль (Arial 14px = 8 pt слайда 16:9, как в отчётной колоде) (в «Направлении» — только KR или эпик). Следующий шаг есть **всегда**: незакрытая задача → её шаг; все задачи спринта закрыты → следующее открытое по эпику вне спринта; объёма не осталось → «эпик завершён». Из данных: «Закрыто: <задачи>» (или «В работе: …»), блокер — заблокированные задачи с их блокером или статусом. Сводка агента (`streams.*.done/blocker/next`) заменяет автоматическую.
  - **Операционный отчёт** — один слайд без заголовка (только метка «Команда · операционный отчёт»): сверху без подписей и легенд «Производительность за 3 спринта» и **одно** «Сгорание спринта» (без подзадач, если сборщик 1.10.0 их разделил, иначе все задачи; клик — расшифровка по дням и задачам). Снизу во всю ширину — **cycle time** закрытых задач за 3 спринта, дни: спринты — полосами с короткими именами (С72…), точки историй (синие) и подзадач (оранжевые), у каждого потока сглаженное скользящее среднее по 5 последним задачам (истории — сплошная, подзадачи — пунктир) с коридором ±σ того же окна, как в JIRA, и его значение подписью в конце линии; поток без закрытых задач не рисуется, в легенде — «за 3 спринта закрытых нет». Клик — сайдбар разбора: вкладки «Все / Истории / Подзадачи», показатели (закрыто, медиана, среднее, σ, порог выброса, выбросы, в зоне риска), классическая диаграмма управления со списками выбросов и зоны риска, таблица по спринтам. Слайда «Сроки» и времени в статусах нет (решение владельца 2026-10-12).
  - **«Участники»** — следующий слайд, метка «Команда · участники»: имя — узкая постоянная колонка, дальше три столбца — **«Задачи из прошлого спринта»** (история спринта, которая была и в предыдущем спринте `output.sprints`; первый спринт доски — столбец пуст), **«Текущий спринт»** (взятые в этот спринт) и **«Вне спринта»** (задачи, которые человек двигал за период, кроме задач спринта, `output.offboard`; клик — сайдбар с активностью). Ширина столбца — по его самому длинному ряду (единица — подзадача — во всех столбцах одной ширины), не уже 16%; блоки делят ширину пропорцией и не вылезают за столбец. Группы: команда, **[EXT]** (на доске, но не в `members`), «Не назначен» в конце. Блок на историю: сверху полоса истории (цвет — статус), под ней её подзадачи, каждая своим цветом; ширина — по числу подзадач; подзадачи участника в чужой истории — с бледной полосой истории; наведение — сколько висит: дней в текущем статусе (с `statusChanged`; у закрытой — дата закрытия), lead time (с создания) и cycle time (с первого перехода из начального статуса, если это не сразу закрытие) по `events` — до закрытия или до сбора; у подзадач — дней в статусе; клик — активность истории. Клик по имени — сайдбар участника: сверху SP план / факт, задачи и подзадачи план / факт и lead time, вне спринта всего / закрыто; ниже — задачи по спринтам.
  - **«Инициативы по спринтам до 05 дек»** — после «Участников»: колонки — 3 спринта после текущего чёрными плашками («2026Q4-S3 · 22 окт – 04 ноя»: квартал — по дате окончания спринта, номер — двухнедельный спринт от начала квартала; спринт — ровно 2 недели с дня после окончания текущего), каждый по 2 недели; строка — инициатива: номер цели (01 = OBJ 1), название, срок эпика (красным, если просрочен или прогноз позже); ячейка — фаза цветом (аналитика и дизайн — персиковый, бек/фронт/разработка — голубой, qa — светло-голубой, приёмка и релиз — зелёный). Из `roadmap` агента, иначе каркас из данных; подписи под заголовком нет. Клик по инициативе — сайдбар «Весь эпик»; любую ячейку и название PO правит сам («Редактировать текст»). До 14 строк, остальное — «ещё N — в отчёте PO».
  - **«Риски и проблемы»** — следом, краткий слайд для внешних команд и руководителей: строка = метка (Внешнее / Ресурс / Общее / Срок) · проблема · что будет или где нужна помощь; до 5 строк. Источник — `risks` агента, иначе `plans.escalate`, иначе данные (подпись под заголовком). Нет ни того ни другого — «Блокеров и сдвигов сроков по данным нет».
  - **Сайдбары поверх колоды.** Клик по строке-направлению — широкий сайдбар, две вкладки: «Задачи спринта» и «Весь эпик». «Задачи спринта» — **два столбца**: слева задачи сгруппированы по статусам (заблокировано → в работе → ревью → тест → открыто → готово; название, ключ, исполнитель, результат), справа — выбранная задача целиком, первая незакрытая — сразу (итог, «дальше», блокер, календарь активности за всё время (статус полосой по дням, события подзадач, комментарии, начало спринта; без рамки и легенды — смысл точек в подсказке) и лента по хронологии: строка на событие, дата колонкой слева у первого события дня, подзадача — серым префиксом, «Было → Стало» текстом (цветом — только новый статус). Вид спокойный: без капса с разрядкой, рамок у карточек и статусов, цветных полос; выбранная задача — фоном, вкладки — подчёркиванием. «Весь эпик» — тот же, что в отчёте PO (`renderScope`): сгорание эпика по неделям с прогнозом, «Что осталось» и «Что выполнено»; в колоде перед «Что осталось» — «Что сделали за эту итерацию (+n%)»: закрытые с начала спринта задачи эпика (дата закрытия) и расчёт «+n% = закрыто в спринте X ÷ Y в эпике» (`iterationClosed` — та же функция, что «(+n%)» в строке). У выбранной задачи и в карточке блокатора — поле комментария: заметка ложится в корзину «Комментарии» с привязкой к задаче и уходит ИИ-агенту (сменить статус, привязать к эпику, снять блок). Любой переход внутри сайдбара (блокаторы → активность, участник → задача…) запоминается: в шапке **«← Назад»** возвращает на прошлый экран. Esc закрывает сайдбар.
  - **Правка текста** — «Редактировать текст»: всё текстовое на слайдах (заголовки, KR, итог, «след. шаг», блокеры, цели, планы, риски) правится по месту, с пунктиром; правки сохраняются в браузере (`actual-sprint:deck-text:…`) и переживают пересборку слайдов, «Вернуть текст» сбрасывает. **Комментарий — правым кликом** (на телефоне — долгим нажатием) по строке-направлению или слайду; уходит в корзину команды (общую с отчётом PO, если файлы открыты с того же адреса), строка с комментарием помечена риской. **Комментарии не пропадают**, пока PO не удалит их сам: корзина показывает все команды (счётчик — сумма), ключ хранения без имени спринта (смена спринта или версии файла не обнуляет; корзины старого формата вливаются), битая запись откладывается, а не затирается, копия — в IndexedDB (очищенный localStorage восстанавливается), браузер просят не вытеснять хранилище. Промт из корзины — по блоку на команду. Стереть всё можно только кнопкой **«Очистить комментарии»** в корзине (с подтверждением): удаляются комментарии всех команд, их копии и копия в IndexedDB.
  - **Сцена на весь экран** (окно шире 900 px): виден один слайд на всю ширину и высоту сцены, без рамки и тени; холст не меньше 1280×720 единиц, масштаб под окно — и вверх, и вниз, лишняя ширина или высота экрана (ультраширокий, 32:9) уходит в раскладку: колонки — в процентах; у левого края — чёрный вертикальный ярлык «Слайды»: открывает выезжающий сайдбар со списком слайдов «номер · тип · заголовок» (текущий выделен), клик — переход и сайдбар закрывается, Esc или клик мимо — закрыть; внизу «‹ N / M ›»; стрелки, PageUp/PageDown, пробел, Home/End листают; слайд выше 720 (много строк, правка текста) **прокручивается внутри** — колесом, а ↓ / пробел / PageDown сначала докручивают его до конца и только потом листают, внизу сцены — «↓ ещё ниже»; F или «На весь экран» — полноэкранный режим браузера. На узком экране (телефон) — лента слайдов во всю ширину и оглавление списком. «PDF» — печать всех слайдов по слайду на страницу 1280×720 без механики правок.
- **«Для техлидов»** — кнопка в шапке колоды: окно с готовым промтом «собери технический отчёт» — `/actual-sprint`, период, команды и спринты, снимок данных, и вопросы с бизнес-отчёта: комментарии к слайдам и строкам из корзин всех команд, чтобы разобрать их с техлидами. «Скопировать промт» — в буфер.

## Что где лежит
```
business.py                      facts | check | apply | render
contract/business.schema.json    форма reports/sprint-business.json
resources/business_template.html страница: колода, сцена, сайдбары, «Для техлидов»
examples/demo-business.json      пример блока на демо-данных
```
Общий движок страниц (данные команд, статусы, корзина, сайдбары, графики) — `actual-sprint/resources/shared`; сборка частей — `actual-sprint/runner/build.py`.

## Границы
Только чтение снимка и запись локальных `reports/sprint-business.json` и `reports/sprint-business.html`. Никаких записей в JIRA/Confluence, публикации и автозапуска.
