# poh-sprint-agents

Автономный скрам-мастер-агент. Навык `sprint-planner` (slice 1): спринт → согласованный vault-ПЛАН + операционный контракт + гейт консенсуса. Навык `actual-sprint`: факт текущего спринта → самодостаточная HTML-страница отчёта по команде.

## Установка
`bash install.sh [target-проект]` — копирует навыки и команды (non-destructive), кладёт `domain-profile.md` из шаблона.

## Команды

### Планирование (STOP после каждой)
`/sm-sync` → `/sm-goal` → `/sm-decompose` → `/sm-load` → `/sm-deliver` → `/sm-consensus`

### Факт спринта
`/actual-sprint {команда?}` — читает JIRA и собирает самодостаточную HTML-страницу отчёта. **Одна страница на все команды**: переключатель в шапке, у каждой команды своя доска, свой спринт и свои заметки.

Единица отчёта — **эпик** (PO трекает прогресс на этом уровне). В строке эпика — счётчики статусов по всей иерархии (истории + подзадачи) в виде `2/2/3/0/5/1`, цвет на бакет, расшифровка по наведению. Клик по строке открывает панель: слева заметка о прогрессе (сохраняется в браузере), справа истории с разворотом подзадач, статусом, возрастом статуса и исполнителем.

**Сводный отчёт за 3 спринта** — клик по Lead Time в шапке. Три графика: burndown текущего спринта (объём пересчитан по changelog, изменения scope видны ступеньками), производительность «запланировано / сделано» с разбивкой планового столбца по статусам, диаграммы управления отдельно по историям и подзадачам — с выбросами и жёлтой зоной риска (задачи, которые ещё не закрыты, но идут дольше медианы).

**Лента активности** — кнопка «Logs»: смены статусов, комментарии и создание задач за неделю, фильтры по типу события и по автору.

Данные собирает `scripts/collect.py --board <id> --team "<Название>" --slug <slug>` — один JSON на команду, массив подставляется в шаблон. Только чтение JIRA, ничего не публикует. См. `.claude/skills/actual-sprint/SKILL.md`.
