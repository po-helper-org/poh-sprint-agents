# dsh-plugin-sprint

Раздел **«Управление спринтами»** для DeepSeek Harness: встроенный коннектор к
корпоративной JIRA. Карточка доступов в настройках, кнопка проверки подключения
и три нативных инструмента модели — чат ходит в трекер напрямую.

## Зачем, если есть JIRA MCP

MCP-мост ставит между моделью и трекером третий процесс со своей схемой
инструментов и своим переводом ответов. В харнессе этот путь работал плохо:
инструменты моста подхватывались неустойчиво, а отказы приходили без причины —
«не получилось» вместо «токен не принят» или «страница входа SSO вместо API».

Коннектор раздела убирает посредника:

| | JIRA через MCP | Коннектор раздела |
|---|---|---|
| Путь к трекеру | модель → мост → JIRA | модель → JIRA |
| Схемы инструментов | зависят от моста | `ctx.tools.register`, уезжают в промт сами |
| Доступы | файл конфигурации моста | карточка «Настройки → Плагины» |
| Отказ | «не получилось» | «JIRA не приняла токен (401)», «страница входа SSO» |
| Проверка до чата | нет | кнопка «Протестировать» |

## Что появляется

- **Карточка «Управление спринтами»** в «Настройки → Плагины → Конфигурация
  плагинов»: полоса коннекторов (иконка JIRA), поля доступа, «Протестировать».
- **Инструменты модели** — `jira_current_stories`, `jira_search`, `jira_issue`.
- **Секция системного промта** «когда ходить в JIRA» с вашим промтом подключения.

## Установка в харнесс

Нужны Node.js 22.19+ и собранный пакет: **несобранный плагин роняет харнесс
целиком**, а не свой раздел — cordis считает такую запись фатальной.

```sh
cd plugins/dsh-plugin-sprint
npm install && npm run build      # tsc в lib/ + браузерный бандл lib/client.js
npm test                          # 61 тест, без сети и без живой JIRA
```

Дальше — в профиль харнесса (`$DSH_HOME/profiles/web/`):

1. `package.json` профиля — зависимость и бандл:

   ```json
   {
     "dependencies": {
       "dsh-plugin-sprint": "link:/абсолютный/путь/к/poh-sprint-agents/plugins/dsh-plugin-sprint"
     },
     "dsh": { "profile": { "bundles": ["dsh-plugin-sprint"] } }
   }
   ```

2. Строка монтирования приезжает из `cordis.patch.yml` самого пакета — в слое
   профиля её задавать не нужно. Значения по умолчанию правятся точечно по
   идентификатору строки:

   ```yaml
   - id: sprint-management
     config:
       timeoutMs: 30000     # корпоративный контур за VPN отвечает медленнее
   ```

3. Перезапустить харнесс: плагин на живую не подхватывается.

> **Грабля.** Слой профиля **заменяет** конфигурацию пакета целиком, а не
> дополняет: задав здесь один ключ, повторите остальные, которые вам нужны.

Для контура [poh-harness](https://github.com/po-helper-org/poh-harness) это те
же две правки в `profile/package.json.tpl` и списке плагинов `install.sh`.

## Настройка коннектора

**Настройки → Плагины → Конфигурация плагинов → «Управление спринтами»**, иконка
JIRA:

| Поле | Что задать |
|---|---|
| Ссылка на JIRA | `https://jira.example.com` — адрес корпоративного контура, можно с контекстным путём (`https://intranet.example.com/jira`) |
| Токен доступа | персональный токен JIRA (Server/DC — PAT, Cloud — API token) |
| Промт подключения | что модель должна знать про контур: чей проект, как называются статусы, что считать историей |
| Проект | ключ проекта команды (`SPRINT`) — из него строится запрос историй |
| JQL историй | свой запрос вместо построенного из проекта |
| Учётная запись | только для Jira Cloud: e-mail учётной записи (Basic). Пусто — Bearer, как на Server/DC |
| Поле оценки | `customfield_XXXXX` со story points. Пусто — коннектор находит поле сам по каталогу полей |

**«Протестировать»** проверяет то, что введено в полях, — сохранять до проверки
не обязательно. Узел ходит в `/rest/api/2/myself` и контрольным запросом историй,
и отвечает одной строкой: кто вы для этой JIRA и сколько историй нашлось.

## Инструменты модели

| Инструмент | Когда | Параметры |
|---|---|---|
| `jira_current_stories` | «покажи актуальные истории команды», «что в спринте», «чем занят такой-то» | `limit`, `assignee`, `status`, `issue_type`, `sprint` (`active`/`any`) |
| `jira_search` | всё, что не покрывает первый: другой проект, закрытый спринт, баги, метки | `jql` (обязателен), `limit` |
| `jira_issue` | детали одной задачи с описанием | `key` |

Выдача уходит модели таблицей (ключ, тип, статус, исполнитель, SP, спринт,
заголовок) и тем же значением в каноническом JSON. Незаполненное поле — прочерк,
а не выдуманное значение: принцип нулевого допуска к галлюцинациям
([VISION](../../VISION.md)) действует и в коннекторе.

## Границы

Коннектор **только читает**. Записи в JIRA нет ни одной: ни заведения задач, ни
смены статусов, ни комментариев — материализация ПЛАНа в трекер идёт отдельным
срезом дорожной карты и отдельным решением. Кнопка проверки и инструменты
используют одни и те же настройки и один и тот же код похода в JIRA, поэтому
«зелёная» проверка означает работающий чат, а не другую ветку кода.

## Токен и безопасность

Токен хранится в документе настроек харнесса на машине владельца — так же, как
токен соседнего раздела «Управление коммуникацией». Кому нужен токен вне
документа: оставьте поле пустым и задайте `JIRA_TOKEN` в окружении процесса
харнесса — коннектор возьмёт его оттуда.

В `cordis.patch.yml` и любых файлах репозитория секретам не место: там только
бюджеты ожидания и потолки выдачи.

## Устройство

| Файл | Роль |
|---|---|
| `src/plugin.ts` | узловая половина: настройки, инструменты, секция промта, канал |
| `src/settings.ts` · `src/settings-schema.ts` | пространство настроек раздела и его схема |
| `src/connector.ts` | одна дверь в JIRA для карточки и для модели |
| `src/jira/client.ts` | REST-клиент: авторизация, отказы, отступление на облачный поиск |
| `src/jira/jql.ts` · `src/jira/normalize.ts` | сборка запроса и разбор ответа |
| `src/tools.ts` · `src/prompt.ts` | инструменты модели и секция «когда ходить в JIRA» |
| `src/channel.ts` | канал `/sprint`: «Протестировать» и статус |
| `src/client/` | браузерная половина: карточка, полоса коннекторов, контроллер черновика |

Тесты (`npm test`) в сеть не ходят: сетевой порт подменяется подделкой, а формы
ответов Server/DC и Cloud зафиксированы снимками.
